# Rule Authoring Tutorial

This walkthrough creates a small Python command-injection rule set. The same structure applies to every language: sources introduce taint, sinks require tainted arguments, sanitizers attach evidence, and constraints keep matches precise. Libraries whose factories or callback signatures determine receiver types can add non-finding `typing/` rules with `returns_type` or `callback_param_types`; see [Custom Rules](custom-rules.mdx).

<Steps>

1. Write a source rule.
2. Write a sink rule.
3. Write a sanitizer rule.
4. Add a constraint.
5. Test the pack and run a fixture scan.

</Steps>

## 1. Write Source

### Source rule YAML

```yaml
- id: python.flask.request_args_get
  enabled: true
  language: python
  trust: remote
  tag: http-input
  category: http-input
  payload_types: [query]
  frameworks: [flask]
  match:
    kind: call
    callee:
      attribute: [request, args, get]
  match_examples:
    - name: flask query get
      code: |
        from flask import request
        def handler():
          return request.args.get("cmd")
      expect_match_text: [request.args.get]
  description: "Flask request.args.get(name) returns attacker-controlled query input."
```

### Source example

```python
from flask import request

def handler():
    cmd = request.args.get("cmd", "")
    return cmd
```

## 2. Write Sink

### Sink rule YAML

```yaml
- id: python.cmdi.os_system
  enabled: true
  language: python
  tag: command-injection
  severity: critical
  cwe: [CWE-78]
  match:
    kind: call
    callee:
      attribute: [os, system]
  constraints:
    - arg_tainted:
        index: 0
  match_examples:
    - name: tainted command
      code: |
        import os
        def run(cmd):
          os.system(cmd)
    - name: literal command negative
      code: |
        import os
        def run():
          os.system("echo safe")
      expect_no_match: true
  description: "os.system(command) executes through the shell; tainted arg 0 is command injection."
```

### Sink example

```python
import os

def run(cmd):
    return os.system(cmd)
```

## 3. Distinguish Sanitizers from Transforms

Rules in `sanitizers/` can also describe non-crediting transforms. The bundled
metadata treats `shell-escape` as one: matching a quote operation does not
prove a trusted executable or its interpreter context.

### Transform rule YAML

```yaml
- id: python.sanitizer.shlex_quote
  enabled: true
  language: python
  tag: shell-escape
  match:
    kind: call
    callee:
      attribute: [shlex, quote]
  match_examples:
    - name: shlex quote
      code: |
        import shlex
        def clean(value):
          return shlex.quote(value)
      expect_match_text: [shlex.quote]
  description: "shlex.quote quotes one POSIX-shell token; context-free matching preserves taint and gives no execution-safety credit."
```

### Transform example

```python
import shlex

def clean(value):
    return shlex.quote(value)
```

An unsafe source-to-sink path through this operation remains `unsanitized` and
records `taint_transforms_seen`. Credited protection requires a separately
modeled proof appropriate to the sink, not merely the presence of a wrapper.

## 4. Add Constraint

### Constrained rule YAML

```yaml
- id: python.cmdi.subprocess_shell_true
  enabled: true
  language: python
  tag: command-injection
  severity: critical
  cwe: [CWE-78]
  match:
    kind: call
    callee:
      attribute: [subprocess, run]
  constraints:
    - keyword_arg_equals:
        name: shell
        value: "True"
    - arg_tainted:
        index: 0
  match_examples:
    - name: shell true command
      code: |
        import subprocess
        def run(cmd):
          subprocess.run(cmd, shell=True)
    - name: shell false negative
      code: |
        import subprocess
        def run(cmd):
          subprocess.run(cmd, shell=False)
      expect_no_match: true
  description: "subprocess.run(command, shell=True) interprets the command string through a shell."
```

### Constrained example

The negative example above excludes only this shell-interpretation rule.
An attacker-controlled executable can still match a separate process-selection
rule with `shell=False`; it is not a blanket safe-execution example.

```python
import subprocess

def run(cmd):
    subprocess.run(cmd, shell=True)
```

## 5. Test

### Validate the pack

```bash
./target/release/bonsai-ninja security ./examples/python/language_gauntlet pack \
  --rules-dir ./security-patterns \
  --validate
```

### Run a fixture scan

```bash
./target/release/bonsai-ninja security ./examples/python/language_gauntlet taint-analysis \
  --profile all \
  --rules-dir ./security-patterns \
  --source python.flask.request_args_get \
  --sink python.cmdi.os_system
```

<Tip>
Every enabled discriminating constraint should have a positive example and a negative example. This keeps rulepack drift visible during validation.
</Tip>
