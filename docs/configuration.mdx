# Configuration

CLI flags take precedence over environment variables. Environment variables
take precedence over built-in defaults. Rulepack lookup checks `--rules-dir`,
then `BONSAI_RULES_DIR`; otherwise the binary materializes its embedded,
content-addressed pack under the operating-system cache. Security therefore
works from any current directory without implicitly trusting a rulepack inside
the workspace being scanned. Editable and custom base packs require an
explicit override.

Generated analysis state lives in `$CACHE_DIR`, a canonical-workspace-keyed
directory below the operating system cache root. Run `cache stats <workspace>`
to print the exact path or set `BONSAI_WORKSPACE_DIR` to an explicit override.
Only optional rule overlays remain inside `<workspace>/.bonsai/rules/`; normal
analysis does not write into the inspected repository.

## Config File Keys

bonsai-ninja does not require a project config file for normal scans. Workspace-local rule overlays use the file layout under `<workspace>/.bonsai/rules/`.

| Name | Type | Default | Description |
|---|---|---|---|
| `.bonsai/rules/` | directory | Absent | Optional workspace-local rule overlay. |
| `$CACHE_DIR/manifest.json` | generated file | `index --semantic`, SDK semantic/full-prewarm facades, or `cache rebuild` | JSON inventory of cache coverage, producer fingerprints, sidecar paths, missing reasons, and the versioned exact source ledger. Unchanged path/size/mtime entries reuse their recorded SHA-256 digest; a metadata change forces content rehashing. Do not use as the analysis payload path; commands validate and read the binary sidecars. |
| `$CACHE_DIR/compiler-objects.v*.factstore` | generated file | first phase of `index --semantic`, SDK semantic prewarm, or `cache rebuild` | Atomic generation of per-file adapter-lowered compiler objects and diagnostics, validated by relative path, adapter, frontend ABI, SHA-256 source digest, and payload digest. Import indexes, declaration linkage facts (including direct-call receiver-field initializers), and compact syntax targets (calls, exact return targets, assignment aliases, factory assignments, inline callbacks, typed callables, and receiver/type evidence) remain independently decodable without retaining declaration/flow bodies. Publication holds a cross-process lock and removes only unlocked older recognized compiler-object schemas plus abandoned matching staging files; unknown/manual files are preserved. |
| `$CACHE_DIR/dataflow.v3.factstore` | generated file | SDK full prewarm, explicit dataflow prewarm, or exact query commands | Persisted dataflow sidecar. Do not edit manually. |
| `$CACHE_DIR/value_flow.v*.factstore` | generated file | explicit compatibility prewarm/save APIs | Persisted `ValueFlowGraph` compatibility projection. Canonical security/export semantics live in the IDG; do not edit manually. |
| `$CACHE_DIR/flow_ids.v*.factstore` | generated file | SDK full prewarm or exact render/query commands | Persisted flow-id sidecar. Do not edit manually. |
| `$CACHE_DIR/callgraph.v*.factstore` | generated file | Query commands or `cache rebuild` | Persisted resolved-callgraph sidecar. Do not edit manually. |
| `$CACHE_DIR/idg.v*.factstore` | generated file | Query commands, `cache rebuild`, or `index --semantic` | Persisted IDG sidecar. Do not edit manually. |
| `$CACHE_DIR/retrieval.v*.factstore` | generated file | `index --semantic`, `cache rebuild`, or small complete-workspace search on demand | Persisted fact-backed candidate index. Inspect may consume a warmed sidecar for pre-open large-workspace scoping, but does not build it as query-time evidence. Do not edit manually; it is candidate lookup only, not evidence. |
| `$CACHE_DIR/taint_graph.v*.<mode>.<config>.factstore` | generated file | Security analysis commands | Versioned, mode/config-specific taint/source graph sidecar. Do not edit manually. |
| `$CACHE_DIR/export.default.v*.json` | generated file | Explicit `cache rebuild --export` only | Reusable default native export. Normal one-shot `export` streams directly to stdout/`--output-path` and never creates then copies this potentially multi-gigabyte cache. The default export always uses the exact `compressed_callgraph`; capped path-prefix caches are not supported. |
| `$CACHE_DIR/page-cache.v*/` | generated directory | Generated lazily | Versioned rendered-page cache for paginated CLI output. |
| OS cache `bonsai-ninja/rulepacks/<SHA-256>/security-patterns/` | generated directory | First default security command | Immutable materialization of the pack compiled into the binary. It is shared across workspaces and never written into the inspected repository. |
| `security-patterns/` | directory | Optional | Editable rulepack source. Use `--rules-dir` when testing a specific tree. |

Sidecars are validated by source-content hashes, dependency hashes, and
pipeline-config fingerprints. Derived semantic pipeline identities also bind
the compiler-object frontend ABI: changing AST lowering invalidates an older
callgraph or IDG even if no source file changed. Root-only cache validation
reconstructs that same ABI-bound identity. Cache diagnostics also decode sidecar headers
and payload indexes for the binary caches they report, so corrupt same-size
files are marked stale instead of treated as reusable. Stale or mismatched
sidecars are ignored and rebuilt by the command that needs them. `cache stats` reports the same
freshness decision as JSON and text output so file presence is not mistaken
for reusable analysis facts. A normal `index` run builds the syntax/construct
index without semantic sidecar prewarm; `index --semantic` explicitly builds
structural semantic sidecars up front, and `index --prewarm-dataflow`
explicitly rebuilds only the compatibility dataflow projection. That
projection supports older SDK/query surfaces; it is not a second taint engine.
`index --watch` keeps a live workspace open, polls for saved changes, and
reparses changed files in place.

The manifest source ledger is a validation accelerator, not a weaker cache
key. A warm reopen can stat unchanged sources instead of reading and hashing
every byte. Any path, size, timestamp, adapter, frontend ABI, or payload
identity change falls back to exact hashing/decoding before reuse. Missing,
old-schema, or corrupt manifests are rebuilt; independently valid binary
sidecars remain eligible through their own exact headers.

Semantic workers publish compiler objects first. Unchanged compressed objects
are copied into the next generation; only source/path/adapter/ABI misses are
lowered again. Callgraph, retrieval, linkage, and IDG then consume that one
generation. Broad rule planning applies raw source anchors, exact
import/package headers, and exact syntax-target headers in that order, then
decodes bodies only for surviving files. Import headers are loaded directly
from the compiler-object generation even when no workspace-package prewarm is
needed; static imports must never disappear merely because that optional
prewarm is empty. Independent header decoding runs concurrently behind the
same source-size-weighted memory permits as exact bodies. A surviving body
derives only secondary views that its retained rules can inspect—such as
decorators, assignment text, must-alias closure, runtime narrowing, or
lifecycle state—and that projection is part of the derived-fact cache key.
Eviction or a later larger projection causes exact recomputation, never a
missing match. The linkage generation stores symbol headers, receiver
ancestry, and call linkage as independent payloads so each command loads only
its required compiler product. The IDG persistence phase replays typed stitch
records from its first transfer pass instead of running transfer lowering
twice. That pass continuously overlaps memory-admitted source segments, holds
each result's admission through consumption, and restores canonical segment
order before stitching. IDG writers hold a target-specific advisory lock for
the complete generation, recheck a peer's completed sidecar before rebuilding, and remove
only lock-proven FactStore staging files left by a terminated writer. Lock
files in `$CACHE_DIR` are ownership metadata and may remain after the process
exits; the operating system releases their locks automatically.

IDG closure storage also follows a strict lazy-allocation contract. A
resident-only fixed point starts with sparse empty sets and frontiers. Dense
workspace bitsets, bounded positive/Bloom acceleration, and temporary spill
files appear only after actual relation density reaches the representation's
promotion or spill threshold. Those thresholds schedule storage; they never
cap facts, functions, paths, or iterations.

Broad consumers keep a compact linkage index of declarations, types, modules,
imports, inheritance, and stable symbols. They stream exact per-file bodies
from compiler objects and remap those bodies to the retained symbols. The
memory-derived body cache is an optimization only: eviction or an oversize
body causes exact replay, never omission.

Filtered/literal query workspaces retain the deterministic full-workspace
`FileId` ordinal for each included source. This lets a scoped query decode the
same compiler object generation as a complete open. Scoped workspaces never
publish their partial retrieval, linkage, callgraph, or IDG products as the
full workspace cache.

Cache and render limits never change analysis semantics. The IDG factstore is
streamed and has no source-file-count ceiling. A rendered page that exceeds
the persistence size policy is returned normally and simply is not cached;
pagination or path-preview limits report more pages/truncation instead of
claiming exhaustive coverage.

Retrieval follows the candidate-only evidence and validation contract in
[Architecture](contributing/architecture.mdx#query-browse-trace).
The taint-graph sidecar is default-on for `security taint-analysis` and
`security source-analysis`. Each exact analysis configuration gets a distinct
filename, so source-analysis and taint-analysis do not overwrite each other's
warm facts. Set `BONSAI_TAINT_GRAPH_PERSIST=0` only when you intentionally
want to trade repeated-run speed for less cache I/O.

Security `--file`, `--exclude-file`, `--exclude-tests`, and production-profile
path filters are evaluated against workspace-relative paths. A selected
workspace is not treated as generated, vendored, or test code merely because an
ancestor directory outside the workspace has a matching name such as `target/`
or `tests/`. Explicit absolute path filters are still matched against absolute
paths.

## Environment Variables

The table lists supported user-facing configuration. Internal test probes,
build fingerprints, and phase-tuning variables are implementation details and
are not a stable deployment interface; prefer the CLI flags and resource
settings below.

| Name | Type | Default | Description |
|---|---|---|---|
| `BONSAI_RULES_DIR` | path | Bundled rulepack | Explicit rulepack directory override. |
| `BONSAI_PARSE_TIMEOUT_MS` | integer milliseconds | unset (uncapped) | Optional per-file tree-sitter parse timeout. `0` disables the timeout guard. |
| `BONSAI_MEMORY_BUDGET_MB` | positive integer MiB | detected host/container limit | Lower the compiler's scheduling/spill budget. Linux resolves the current process's nested cgroup v1/v2 memory controller, not only the root controller. Weighted phases subtract measured process RSS and safety headroom before admitting transient units; the exact-body hot cache derives from the same value. This is not an OS hard-RSS limit: clean memory-mapped factstore pages, allocator arenas, stacks, the binary, and output buffers can make RSS/physical footprint exceed it and are reclaimed or paged by the OS under pressure. A smaller value serializes work, evicts bodies sooner, and can cause exact recomputation/I/O; it cannot reduce analyzed files, facts, or graph closure. |
| `BONSAI_DEBUG` | comma-separated categories | unset | Emit selected diagnostic categories to stderr; `*` enables all categories. Equivalent to global `--debug`. Common categories include `idg-closure`, `idg-resolve`, `recv-state`, `find-group`, `taint-graph`, and `xcall`; security progress notes also use categories such as `security-progress` and `security-phase`. |
| `BONSAI_COMPILER_JOBS` | positive integer | available CPU count | Upper bound on compiler-object workers before file-size/memory weighting. Every file is still compiled. |
| `BONSAI_IDG_TRANSFER_BATCH_SEGMENTS` | positive integer | available CPU workers | Compatibility name for the upper bound on dedicated IDG transfer workers. Exact VFS source size and the live memory permit pool determine actual overlap; completed results retain admission until canonical `SegmentId`-ordered stitching consumes them. Every segment and transfer fact is still compiled. |
| `BONSAI_SECURITY_JOBS` | positive integer | available CPU count | Upper bound on the continuous security header/body CPU worklist. Source-size-weighted permits independently bound memory overlap, so small files can use available CPUs while a large file consumes more of the scheduling budget. It changes throughput only, never the scanned file, rule set, or derived evidence. |
| `BONSAI_SOURCE_ANALYSIS_JOBS` | positive integer | available CPU count | Upper bound on concurrent source-analysis compiler units before the shared memory scheduler. |
| `BONSAI_TAINT_ANALYSIS_JOBS` | positive integer | `RAYON_NUM_THREADS` or available CPU count | Upper bound on concurrent exact source closures. Constrained machines run the same closures serially. |
| `BONSAI_SECURITY_STACK_BYTES` | integer bytes, at least 1 MiB | 16 MiB | Stack size for security matcher workers. |
| `BONSAI_TAINT_GRAPH_CACHE_MB` | non-negative integer MiB | memory-budget-derived, normally 64 MiB without detection | Byte budget for decoded source-seeded graph retention. Oversize/evicted graphs are still computed and persisted exactly; only in-process reuse changes. |
| `BONSAI_TAINT_GRAPH_CACHE_ENTRIES` | non-negative integer | 512 | Secondary entry-count bound for decoded taint graph retention. `0` disables resident retention, not analysis or persistence. |
| `BONSAI_NO_DATAFLOW` | boolean-like | unset | Skip explicit dataflow prewarm and trace eager hydration. Query commands still compute required facts on demand. |
| `BONSAI_THEME` | string | `moss` | Terminal theme: `moss`, `earthy-dark`, `dracula`, or `retro-amber`. |
| `BONSAI_WORKSPACE_DIR` | path | OS cache directory keyed by canonical workspace root | Exact per-workspace cache-directory override. Relative values are resolved below the workspace for backward compatibility; prefer an absolute path. |
| `BONSAI_CONTEXT` | token budget | `32k` for text and JSON | Default paging/context budget. |
| `BONSAI_NO_CACHE` | boolean-like | unset | Disable in-process caches. |
| `BONSAI_TAINT_GRAPH_PERSIST` | boolean-like | enabled | Persist exact taint/source graph entries to mode/config-specific `$CACHE_DIR/taint_graph.v*.<mode>.<config>.factstore` files. Set to `0`, `false`, `no`, or `off` to opt out. |
| `BONSAI_INCLUDE_MINIFIED` | boolean-like | unset | Include `.min.*` assets in `read-file` path and symbol resolution. Minified assets are excluded from that navigation command by default. |
| `BONSAI_RAYON_STACK_BYTES` | integer bytes | internal default | Rayon worker stack size override for very deep syntax trees. |
| `NO_COLOR` | boolean-like | unset | Disable color output. |
| `NO_PROGRESS` | boolean-like | unset | Disable progress output. |

## Progress Output

Progress renders to stderr and is separated from command payloads on
stdout. Interactive runs show staged progress for workspace ingest,
parse, sidecar prewarm, query collection, analysis phases, pagination,
cache writes, and rendering. Programmatic output stays clean: JSON,
SARIF, DOT, graph exports, and `--output-path` files do not contain
progress text.

Indexing keeps a parent-owned display alive across process-isolated compiler
workers. Structural indexing reports compiler-cache maintenance, workspace
ingest, and Tree-sitter object compilation. `index --semantic` additionally
reports validation and the numbered compiler-object, declaration-linkage,
callgraph, retrieval, and IDG-query-accelerator phases. Worker processes stay
quiet so they cannot erase, duplicate, or interleave the parent display.

Use `--no-progress` or `NO_PROGRESS=1` to suppress progress bars. Bars are
also hidden automatically when stderr is not a TTY. `--no-color` and
`NO_COLOR` remove ANSI styling but do not hide progress; combine them
with `--no-progress` for quiet script/LLM runs.

## Precedence

| Setting | Highest precedence | Then | Default |
|---|---|---|---|
| Rulepack directory | `--rules-dir` | `BONSAI_RULES_DIR` | Embedded, content-addressed bundled pack |
| Parse timeout | `--parse-timeout` | `BONSAI_PARSE_TIMEOUT_MS` | uncapped |
| Compiler memory budget | `--memory-budget` | `BONSAI_MEMORY_BUDGET_MB` | detected host/container limit |
| Debug categories | `--debug` | `BONSAI_DEBUG` | disabled |
| Theme | `--theme` | `BONSAI_THEME` | `moss` |
| Context budget | `--context` | `BONSAI_CONTEXT` | 32k |
| Cache behavior | `--no-cache` | `BONSAI_NO_CACHE` | enabled |
