# Configuration

CLI flags take precedence over environment variables. Environment variables
take precedence over built-in defaults. Rulepack lookup checks `--rules-dir`,
then `BONSAI_RULES_DIR`; otherwise the binary materializes its embedded,
content-addressed pack under the operating-system cache. Security therefore
works from any current directory without implicitly trusting a rulepack inside
the workspace being scanned. Editable and custom base packs require an
explicit override.

Generated analysis state lives in `$CACHE_DIR`, a canonical-workspace-keyed
directory below the operating system cache root. Run `cache stats <workspace>`
to print the exact path or set `BONSAI_WORKSPACE_DIR` to an explicit override.
Only optional rule overlays remain inside `<workspace>/.bonsai/rules/`; normal
analysis does not write into the inspected repository.

## Config File Keys

bonsai-ninja does not require a project config file for normal scans. Workspace-local rule overlays use the file layout under `<workspace>/.bonsai/rules/`.

| Name | Type | Default | Description |
|---|---|---|---|
| `.bonsai/rules/` | directory | Absent | Optional workspace-local rule overlay. |
| `$CACHE_DIR/manifest.json` | generated file | `index` (after a compiler-object rebuild, or whenever the stored manifest has an older schema, a different workspace root, or a different minified-source profile), `index --semantic`, SDK semantic/full-prewarm facades, or `cache rebuild` | JSON inventory (schema 8) of cache coverage, producer fingerprints, sidecar paths, missing reasons, and the versioned exact source ledger. Each source entry records its filesystem stamp (length, mtime, ctime, device, inode), FNV-1a hash, and — when the on-disk bytes are the text verbatim — its SHA-256 `text_digest`. Unchanged stamps reuse the recorded digest and, on Unix, let a warm open intern the file by identity and read it only on first semantic use; a stamp change forces content rehashing. Do not use as the analysis payload path; commands validate and read the binary sidecars. |
| `$CACHE_DIR/compiler-objects.v*.factstore` | generated file | `index`, first phase of `index --semantic`, SDK semantic prewarm, or `cache rebuild` | Atomic generation (currently `v178`) of per-file adapter-lowered compiler objects and diagnostics, validated by relative path, adapter, frontend ABI, SHA-256 source digest, and payload digest. Import indexes, declaration linkage facts (including direct-call receiver-field initializers), compact syntax targets (calls, exact return targets, assignment aliases, factory assignments, inline callbacks, typed callables, and receiver/type evidence), per-declaration frames, and the source's line-start table remain independently decodable without retaining declaration/flow bodies; the line table lets a lazily interned source render line/column locations unread. | `$CACHE_DIR/flow_ids.v*.factstore` | generated file | SDK full prewarm or exact render/query commands | Persisted flow-id sidecar. Do not edit manually. |
| `$CACHE_DIR/callgraph.v*.factstore` | generated file | Query commands or `cache rebuild` | Persisted resolved-callgraph sidecar. | `$CACHE_DIR/idg.v*.factstore` | generated file | Query commands, `cache rebuild`, or `index --semantic` | Persisted IDG sidecar. Do not edit manually. |

| OS cache `bonsai-ninja/rulepacks/<SHA-256>/security-patterns/` | generated directory | First default security command | Immutable materialization of the pack compiled into the binary. It is shared across workspaces and never written into the inspected repository. |

Sidecars are validated by source-content hashes, dependency hashes, and
pipeline-config fingerprints. Derived semantic pipeline identities also bind
the compiler-object frontend ABI: changing AST lowering invalidates an older
callgraph or IDG even if no source file changed. Root-only cache validation
reconstructs that same ABI-bound identity. Cache diagnostics also decode sidecar headers
and payload indexes for the binary caches they report, so corrupt same-size
files are marked stale instead of treated as reusable. Stale or mismatched
sidecars are ignored and rebuilt by the command that needs them. `cache stats` reports the same
freshness decision as JSON and text output so file presence is not mistaken
for reusable analysis facts. A normal `index` run builds the syntax/construct
index without semantic sidecar prewarm; `index --semantic` explicitly builds
structural semantic sidecars up front, and `index --prewarm-dataflow`
explicitly rebuilds only the compatibility dataflow projection. That
projection supports older SDK/query surfaces; it is not a second taint engine.
`index --watch` keeps a live workspace open, polls for saved changes, and
reparses changed files in place.

The manifest source ledger is a validation accelerator, not a weaker cache
key. A warm reopen can stat unchanged sources instead of reading and hashing
every byte. Any path, size, timestamp, adapter, frontend ABI, or payload
identity change falls back to exact hashing/decoding before reuse. Missing,
old-schema, or corrupt manifests are rebuilt; independently valid binary
sidecars remain eligible through their own exact headers.

Semantic workers publish compiler objects first. Unchanged compressed objects
are copied into the next generation; only source/path/adapter/ABI misses are
lowered again. Callgraph, retrieval, linkage, and IDG then consume that one
generation. Broad rule planning applies raw source anchors, exact
import/package headers, and exact syntax-target headers in that order, then
decodes bodies only for surviving files. Import headers are loaded directly
from the compiler-object generation even when no workspace-package prewarm is
needed; static imports must never disappear merely because that optional
prewarm is empty. Independent header decoding runs concurrently behind the
same source-size-weighted memory permits as exact bodies. A surviving body
derives only secondary views that its retained rules can inspect—such as
decorators, assignment text, must-alias closure, runtime narrowing, or
lifecycle state—and that projection is part of the derived-fact cache key.
Eviction or a later larger projection causes exact recomputation, never a
missing match. The linkage generation stores symbol headers, receiver
ancestry, and call linkage as independent payloads so each command loads only
its required compiler product. The IDG persistence phase replays typed stitch
records from its first transfer pass instead of running transfer lowering
twice. That pass continuously overlaps memory-admitted source segments, holds
each result's admission through consumption, and restores canonical segment
order before stitching. IDG writers hold a target-specific advisory lock for
the complete generation, recheck a peer's completed sidecar before rebuilding, and remove
only lock-proven FactStore staging files left by a terminated writer. Lock
files in `$CACHE_DIR` are ownership metadata and may remain after the process
exits; the operating system releases their locks automatically.

IDG closure storage also follows a strict lazy-allocation contract. A
resident-only fixed point starts with sparse empty sets and frontiers. Dense
workspace bitsets, bounded positive/Bloom acceleration, and temporary spill
files appear only after actual relation density reaches the representation's
promotion or spill threshold. Those thresholds schedule storage; they never
cap facts, functions, paths, or iterations.

Broad consumers keep a compact linkage index of declarations, types, modules,
imports, inheritance, and stable symbols. They stream exact per-file bodies
from compiler objects and remap those bodies to the retained symbols. The
memory-derived body cache is an optimization only: eviction or an oversize
body causes exact replay, never omission.

Filtered/literal query workspaces retain the deterministic full-workspace
`FileId` ordinal for each included source. This lets a scoped query decode the
same compiler object generation as a complete open. Scoped workspaces never
publish their partial retrieval, linkage, callgraph, or IDG products as the
full workspace cache.

Cache and render limits never change analysis semantics. The IDG factstore is
streamed and has no source-file-count ceiling. A rendered page that exceeds
the persistence size policy is returned normally and simply is not cached;
pagination or path-preview limits report more pages/truncation instead of
claiming exhaustive coverage.

Retrieval follows the candidate-only evidence and validation contract in
[Architecture](contributing/architecture.mdx#query-browse-trace).
The taint-graph sidecar is default-on for `security taint-analysis`,
`security source-analysis`, and `security sink-analysis`. Each exact analysis
product gets a distinct filename, so source, sink, and taint queries do not overwrite
one another's warm facts. Set `BONSAI_TAINT_GRAPH_PERSIST=0` only when you intentionally
want to trade repeated-run speed for less cache I/O.

Security `--file`, `--exclude-file`, `--exclude-tests`, and production-profile
path filters are evaluated against workspace-relative paths. The bundled
production profile is the default for `source-analysis`, `sink-analysis`, and `taint-analysis`;
it keeps every sink severity, and `--profile all` disables its review-path and
trust defaults. Independently,
the default compiler-input profile excludes adapter-classified minified
JavaScript/TypeScript for indexing, navigation, graphs, security, and export;
global `--minified-js` includes those bundles. Use both switches for an
unfiltered security audit over every supported source representation. A selected
workspace is not treated as generated, vendored, or test code merely because an
ancestor directory outside the workspace has a matching name such as `target/`
or `tests/`. Explicit absolute path filters are still matched against absolute
paths.

## Environment Variables

CLI flags win over environment variables. The binary mirrors `--memory-budget`,
`--no-color`, `--no-progress`, `--no-cache`, `--minified-js`, and `--debug`
into the variables below so isolated semantic worker processes inherit the
same contract. Every variable listed here is read by the current code; the
test-only variables at the end are not a deployment interface. Worker-count
and stack variables change scheduling, concurrency, or representation only —
never the analyzed files, facts, closure, or findings.

### Workspace and cache

| Name | Type | Default | Description |
|---|---|---|---|
| `BONSAI_WORKSPACE_DIR` | path | OS cache directory keyed by canonical workspace root | Exact per-workspace cache-directory override. Relative values resolve below the workspace root for backward compatibility; prefer an absolute path. When set, the shared cache root is not enumerated, so `cache clear --orphans` and the daily orphan sweep are inert. |
| `BONSAI_RULES_DIR` | path | Embedded, content-addressed bundled pack | Rulepack directory override; same as `--rules-dir`. |
| `BONSAI_NO_CACHE` | `1`, `true`, `yes`, or `on` | unset | Same as global `--no-cache`: the invocation neither loads nor publishes reusable semantic sidecars or taint graphs. Command-local compiler memoization still avoids duplicate parsing within the process. |
| `BONSAI_TAINT_GRAPH_PERSIST` | `0`, `false`, `no`, or `off` to disable | enabled | Write-through persistence of exact taint/source graphs to `$CACHE_DIR/taint_graph.v*.<mode>.<config>.factstore`. Forced off while `BONSAI_NO_CACHE` is set. |
| `BONSAI_TAINT_GRAPH_CACHE_MB` | non-negative integer MiB | effective memory limit / 64, clamped to 64 KiB–256 MiB (64 MiB when no limit is detected) | Byte budget for decoded taint graphs retained in process. Oversize or evicted graphs are still computed and persisted exactly; only in-process reuse changes. |
| `BONSAI_TAINT_GRAPH_CACHE_ENTRIES` | non-negative integer | 512 | Secondary entry-count bound on resident taint graphs. `0` disables resident retention, not analysis or persistence. |
| `BONSAI_NO_DATAFLOW` | `1`, `true`, `yes`, or `on` | unset | Skip loading/prewarming the compatibility dataflow sidecar; the open reports `dataflow` as skipped. Query commands still compute required facts on demand. |
| `BONSAI_NO_VALUE_FLOW` | `1`, `true`, `yes`, or `on` | unset | Skip the compatibility `ValueFlowGraph` sidecar (`value_flow.v*.factstore`) in the same way. Security and export read the IDG directly and are unaffected. |
| `BONSAI_KEEP_DECL_INDEX_CACHE` | boolean-like (`1`/`0`, `true`/`false`, `yes`/`no`, `on`/`off`) | unset (drain) | Keep per-file declaration indexes resident after the global linker header is built instead of moving them into it. Memory trade-off only. |
| `BONSAI_INCLUDE_MINIFIED_JS` | `1`, `true`, `yes`, or `on` | unset | Same as global `--minified-js`: include adapter-classified minified JavaScript/TypeScript in compiler-backed commands and their worker processes. |

### Performance and parallelism

| Name | Type | Default | Description |
|---|---|---|---|
| `BONSAI_MEMORY_BUDGET_MB` | positive integer MiB | detected host/container limit | Lower the compiler's scheduling/spill budget; same as `--memory-budget`. Linux resolves the process's nested cgroup v1/v2 memory controller. Weighted phases subtract measured process RSS and safety headroom before admitting units; the exact-body hot cache and taint-graph cache derive from the same value. Not an OS hard-RSS limit: clean memory-mapped factstore pages, allocator arenas, stacks, and output buffers can exceed it. A smaller value serializes work and can cause exact recomputation; it cannot reduce analyzed files, facts, or closure. |
| `BONSAI_PARSE_TIMEOUT_MS` | integer milliseconds | unset (uncapped) | Optional per-file tree-sitter parse timeout; same as `--parse-timeout`. `0` also disables the guard. |
| `RAYON_NUM_THREADS` | positive integer | available CPU count | Rayon pool size. Also the default for `BONSAI_PARSE_JOBS`, `BONSAI_GLOBAL_INDEX_JOBS`, `BONSAI_CALLGRAPH_JOBS`, `BONSAI_SECURITY_JOBS`, and `BONSAI_TAINT_ANALYSIS_JOBS`. |
| `BONSAI_PARSE_JOBS` | positive integer | `RAYON_NUM_THREADS` or CPU count | Upper bound on Tree-sitter parse/declaration-index workers, clamped to the CPU count and then memory-weighted. |
| `BONSAI_COMPILER_JOBS` | positive integer | CPU count | Upper bound on compiler-object workers (clamped to 1..CPU count) before source-size/memory weighting. Every file is still compiled. |
| `BONSAI_GLOBAL_INDEX_JOBS` | positive integer | `RAYON_NUM_THREADS` or CPU count | Upper bound on global linker-header workers. |
| `BONSAI_CALLGRAPH_JOBS` | positive integer | `RAYON_NUM_THREADS` or CPU count | Upper bound on callgraph resolver workers; every file remains in one exact worklist. |
| `BONSAI_IDG_TRANSFER_BATCH_SEGMENTS` | positive integer | Rayon pool size | Compatibility name for the upper bound on dedicated IDG transfer workers (clamped to the pool and to the segment count). | `BONSAI_SECURITY_JOBS` | positive integer | `RAYON_NUM_THREADS` or CPU count | Upper bound on the continuous security header/body CPU worklist. Source-size-weighted permits independently bound memory overlap. Throughput only, never the scanned files, rule set, or evidence. |
| `BONSAI_SOURCE_ANALYSIS_JOBS` | positive integer | CPU count | Upper bound on concurrent `source-analysis` source groups and `sink-analysis` origin queries before the shared memory scheduler. |
| `BONSAI_TAINT_ANALYSIS_JOBS` | positive integer | `RAYON_NUM_THREADS` or CPU count | Upper bound on concurrent exact source closures in `taint-analysis`. Constrained machines run the same closures serially. |
| `BONSAI_RETRIEVAL_ON_DEMAND_FILE_LIMIT` | non-negative integer files | 512 | Largest complete workspace for which a query command builds the retrieval candidate sidecar on demand; larger workspaces get it only from `index --semantic` or `cache rebuild` and otherwise use canonical syntax-backed collection. Candidate lookup only, never evidence. |
| `BONSAI_FACTSTORE_QUEUE_BYTES` | positive integer bytes | 4 MiB × producer threads | Backpressure budget of the FactStore writer queue. Oversize facts are admitted one at a time and written losslessly. |

### Stack reservations

Reservations are virtual address space committed on demand. They exist
because adapter-lowered structured IR retains source nesting; a platform's
smaller spawned-thread default can abort on valid deeply nested input.

| Name | Type | Default | Description |
|---|---|---|---|
| `BONSAI_MAIN_STACK_BYTES` | integer bytes, at least 8 MiB | 512 MiB | Stack of the main analysis thread the CLI runs every command on. |
| `BONSAI_COMPILER_STACK_BYTES` | integer bytes, at least 1 MiB | 64 MiB | Shared reservation for parser, compiler-object, IDG transfer/summary, query-accelerator, and security matcher workers. |
| `BONSAI_RAYON_STACK_BYTES` | integer bytes, at least 1 MiB | unset | Compatibility alias consulted when `BONSAI_COMPILER_STACK_BYTES` is unset. |
| `BONSAI_PARSE_STACK_BYTES` | integer bytes, at least 1 MiB | compiler stack | Parse-worker override of the shared reservation. |
| `BONSAI_GLOBAL_INDEX_STACK_BYTES` | integer bytes, at least 1 MiB | compiler stack | Global linker-header worker override. |
| `BONSAI_SECURITY_STACK_BYTES` | integer bytes, at least 1 MiB | compiler stack | Security matcher worker override. |

## Progress Output

Progress renders to stderr and is separated from command payloads on
stdout. Interactive runs show staged progress for workspace ingest,
parse, sidecar prewarm, query collection, analysis phases, pagination,
cache writes, and rendering. Programmatic output stays clean: JSON,
SARIF, DOT, graph exports, and `--output-path` files do not contain
progress text.

Indexing keeps one active display across process-isolated compiler workers.
Structural indexing reports compiler-cache maintenance, the exact source-file
read worklist after the metadata walk, and Tree-sitter object compilation.
`index --semantic` additionally reports
validation and the numbered compiler-object, declaration-linkage, callgraph,
retrieval, and IDG-query-accelerator phases. The active worker owns that phase
line. Compiler-object, declaration-linkage, callgraph, retrieval, and IDG
transfer work show exact completed/total counts, percentage, throughput, ETA,
and elapsed time. A monotone worklist whose final scope is discovered during
compilation shows its exact completed-unit count and elapsed time without
claiming a percentage or ETA; source-reachable callgraph work counts either
finished compiler files or finished persisted relation partitions, depending
on the exact reusable artifact available. Accelerator compilation, compression,
validation, and atomic publication show their named phase plus elapsed time
because byte/page counts are representation details, not comparable semantic
work units. The CLI never turns those steps into guessed percentages. Workers
are sequential, so their displays cannot interleave and exiting a worker still
reclaims the phase's memory.

Security matching reports its real compiler stages separately: raw source
anchor filtering, exact import/syntax-header planning, receiver-type
enrichment when required, and adapter-lowered body matching. Native JSON
export likewise counts both structural-file and compiler-file phases while
its compact callgraph, flow-graph, and taint-relation streams remain named
elapsed-time spinners. Progress callbacks observe existing worklists; they do
not pre-scan, cap, or otherwise change analysis.

Use `--no-progress` or `NO_PROGRESS=1` to suppress progress bars. Bars are
also hidden automatically when stderr is not a TTY. `--no-color` and
`NO_COLOR` remove ANSI styling but do not hide progress; combine them
with `--no-progress` for quiet script/LLM runs.

## Precedence

| Setting | Highest precedence | Then | Default |
|---|---|---|---|
| Rulepack directory | `--rules-dir` | `BONSAI_RULES_DIR` | Embedded, content-addressed bundled pack |
| Parse timeout | `--parse-timeout` | `BONSAI_PARSE_TIMEOUT_MS` | uncapped |
| Compiler memory budget | `--memory-budget` | `BONSAI_MEMORY_BUDGET_MB` | detected host/container limit |
| Debug categories | `--debug` | `BONSAI_DEBUG` | disabled |
| Theme | `--theme` | `BONSAI_THEME` | `moss` |
| Context budget | `--context` | `BONSAI_CONTEXT` | 32k |
| Cache behavior | `--no-cache` | `BONSAI_NO_CACHE` | enabled |
| Minified JS/TS inputs | `--minified-js` | `BONSAI_INCLUDE_MINIFIED_JS` | excluded |
| Progress | `--no-progress` | `NO_PROGRESS` | shown on a TTY |
| Color | `--no-color` | `NO_COLOR` | styled on a TTY |
