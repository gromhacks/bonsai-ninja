# Configuration

CLI flags take precedence over environment variables. Environment variables take precedence over built-in defaults. Rulepack lookup checks `--rules-dir`, then `BONSAI_RULES_DIR`, then workspace-local and cwd-relative `security-patterns/` locations.

## Config File Keys

bonsai-ninja does not require a project config file for normal scans. Workspace-local rule overlays use the file layout under `<workspace>/.bonsai/rules/`.

| Name | Type | Default | Description |
|---|---|---|---|
| `.bonsai/rules/` | directory | Absent | Optional workspace-local rule overlay. |
| `.bonsai/manifest.json` | generated file | `index --semantic`, SDK semantic/full-prewarm facades, or `cache rebuild` | JSON inventory of cache coverage, producer fingerprints, sidecar paths, and missing reasons. Do not use as the hot analysis path; commands validate and read the binary sidecars. |
| `.bonsai/dataflow.v3.factstore` | generated file | SDK full prewarm, explicit dataflow prewarm, or exact query commands | Persisted dataflow sidecar. Do not edit manually. |
| `.bonsai/value_flow.v*.factstore` | generated file | explicit compatibility prewarm/save APIs | Persisted legacy `ValueFlowGraph` projection. Canonical security/export semantics live in the IDG; do not edit manually. |
| `.bonsai/flow_ids.v*.factstore` | generated file | SDK full prewarm or exact render/query commands | Persisted flow-id sidecar. Do not edit manually. |
| `.bonsai/callgraph.v*.bin` | generated file | Query commands or `cache rebuild` | Persisted resolved-callgraph sidecar. Do not edit manually. |
| `.bonsai/idg.v*.factstore` | generated file | Query commands, `cache rebuild`, or `index --semantic` | Persisted IDG sidecar. Do not edit manually. |
| `.bonsai/retrieval.v*.factstore` | generated file | `index --semantic`, `cache rebuild`, or small complete-workspace search on demand | Persisted fact-backed candidate index. Inspect may consume a warmed sidecar for pre-open large-workspace scoping, but does not build it as query-time evidence. Do not edit manually; it is candidate lookup only, not evidence. |
| `.bonsai/taint_graph.v*.<mode>.<config>.factstore` | generated file | Security analysis commands | Versioned, mode/config-specific taint/source graph sidecar. Do not edit manually. |
| `.bonsai/page-cache.v*/` | generated directory | Generated lazily | Versioned rendered-page cache for paginated CLI output. |
| `security-patterns/` | directory | Auto-discovered | Rulepack root when `--rules-dir` and `BONSAI_RULES_DIR` are not set. |

Sidecars are validated by source-content hashes, dependency hashes, and
pipeline-config fingerprints. Cache diagnostics also decode sidecar headers
and payload indexes for the binary caches they report, so corrupt same-size
files are marked stale instead of treated as reusable. Stale or mismatched
sidecars are ignored and rebuilt by the command that needs them. `cache stats` reports the same
freshness decision as JSON and text output so file presence is not mistaken
for reusable analysis facts. A normal `index` run builds the syntax/construct
index without semantic sidecar prewarm; `index --semantic` explicitly builds
structural semantic sidecars up front, and `index --prewarm-dataflow`
explicitly rebuilds only the compatibility dataflow projection. That
projection supports older SDK/query surfaces; it is not a second taint engine.
`index --watch` keeps a live workspace open, polls for saved changes, and
reparses changed files in place.

Cache and render limits never change analysis semantics. The IDG factstore is
streamed and has no source-file-count ceiling. A rendered page that exceeds
the persistence size policy is returned normally and simply is not cached;
pagination or path-preview limits report more pages/truncation instead of
claiming exhaustive coverage.

Retrieval follows the same validation rules: exact indexes decide candidates;
canonical facts and semantic graph verification decide truth. Vector
similarity is never evidence.
The taint-graph sidecar is default-on for `security taint-analysis` and
`security source-analysis`. Each exact analysis configuration gets a distinct
filename, so source-analysis and taint-analysis do not overwrite each other's
warm facts. Set `BONSAI_TAINT_GRAPH_PERSIST=0` only when you intentionally
want to trade repeated-run speed for less cache I/O.

Security `--file`, `--exclude-file`, `--exclude-tests`, and production-profile
path filters are evaluated against workspace-relative paths. A selected
workspace is not treated as generated, vendored, or test code merely because an
ancestor directory outside the workspace has a matching name such as `target/`
or `tests/`. Explicit absolute path filters are still matched against absolute
paths.

## Environment Variables

| Name | Type | Default | Description |
|---|---|---|---|
| `BONSAI_RULES_DIR` | path | Auto-discover | Rulepack directory. |
| `BONSAI_PARSE_TIMEOUT_MS` | integer milliseconds | unset (uncapped) | Optional per-file tree-sitter parse timeout. `0` disables the timeout guard. |
| `BONSAI_NO_DATAFLOW` | boolean-like | unset | Skip explicit dataflow prewarm and trace eager hydration. Query commands still compute required facts on demand. |
| `BONSAI_THEME` | string | `moss` | Terminal theme: `moss`, `earthy-dark`, `dracula`, or `retro-amber`. |
| `BONSAI_WORKSPACE_DIR` | path | Workspace root | Per-workspace state directory override. |
| `BONSAI_CONTEXT` | token budget | `32k` for text and JSON | Default paging/context budget. |
| `BONSAI_NO_CACHE` | boolean-like | unset | Disable in-process caches. |
| `BONSAI_TAINT_GRAPH_PERSIST` | boolean-like | enabled | Persist exact taint/source graph entries to mode/config-specific `.bonsai/taint_graph.v*.<mode>.<config>.factstore` files. Set to `0`, `false`, `no`, or `off` to opt out. |
| `BONSAI_RAYON_STACK_BYTES` | integer bytes | internal default | Rayon worker stack size override for very deep syntax trees. |
| `NO_COLOR` | boolean-like | unset | Disable color output. |
| `NO_PROGRESS` | boolean-like | unset | Disable progress output. |

## Progress Output

Progress renders to stderr and is separated from command payloads on
stdout. Interactive runs show staged progress for workspace ingest,
parse, sidecar prewarm, query collection, analysis phases, pagination,
cache writes, and rendering. Programmatic output stays clean: JSON,
SARIF, DOT, graph exports, and `--output-path` files do not contain
progress text.

Use `--no-progress` or `NO_PROGRESS=1` to suppress progress bars. Bars are
also hidden automatically when stderr is not a TTY. `--no-color` and
`NO_COLOR` remove ANSI styling but do not hide progress; combine them
with `--no-progress` for quiet script/LLM runs.

## Precedence

| Setting | Highest precedence | Then | Default |
|---|---|---|---|
| Rulepack directory | `--rules-dir` | `BONSAI_RULES_DIR`, workspace/cwd discovery | None |
| Parse timeout | `--parse-timeout` | `BONSAI_PARSE_TIMEOUT_MS` | uncapped |
| Theme | `--theme` | `BONSAI_THEME` | `moss` |
| Context budget | `--context` | `BONSAI_CONTEXT` | 32k |
| Cache behavior | `--no-cache` | `BONSAI_NO_CACHE` | enabled |
