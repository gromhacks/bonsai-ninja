# Rule Testing

Rule testing has three layers: schema/example validation proves rule content,
integration fixtures prove behavior against adapter compiler facts, and scale
checks prove the same uncapped IDG semantics remain practical on production
workspaces.

<Steps>

1. Add or update `match_examples` on every enabled rule.
2. Run normal validation while editing.
3. Run `--taint-replay` before merge.
4. Add a fixture when propagation or adapter lowering changes.
5. Run the deployment gates for the affected command surface.

</Steps>

## Match Examples

Positive examples contain the exact callee or target shape the rule claims.
Negative examples cover the closest safe form, usually a literal argument,
disabled option, wrong receiver type, or unrelated package.

```yaml
match_examples:
  - name: tainted arg 0
    code: |
      void example(char *input) {
        system(input);
      }
  - name: literal command negative
    code: |
      void example(void) {
        system("echo safe");
      }
    expect_no_match: true
```

## Pack Validation

```bash
cargo build --release -p bonsai_cli

./target/release/bonsai-ninja security . pack --validate \
  --rules-dir security-patterns \
  --format json --no-color --no-progress
```

The normal validator checks schema, metadata, collisions, and statically
replays examples. Taint-dependent constraints
(`arg_tainted`, `any_arg_tainted`, and `receiver_tainted`) require live
source-to-sink evidence, so run the deep gate before merge:

```bash
./target/release/bonsai-ninja security . pack --validate --taint-replay \
  --rules-dir security-patterns \
  --format json --no-color --no-progress
```

Current counts and the latest zero-error result belong in
[Release Readiness](RELEASE_READINESS.md); the command remains authoritative.

A `match-example-taint-miss` usually means the rule is broken, its package or
receiver gate rejects the example, or its example has no source. Use a real
parameter source and, when appropriate, a typed receiver. See the
[Pattern Guide](./pattern-guide.mdx).

## Integration Fixtures

Use `examples/<lang>/micro` for command-surface checks,
`examples/<lang>/mega_flow` for construct coverage, and focused fixtures for
sanitizer, lifecycle, resolver, and field-sensitive behavior.

```bash
./target/release/bonsai-ninja security examples/python/mega_flow \
  taint-analysis \
  --rules-dir security-patterns \
  --format json \
  --all \
  --no-color \
  --no-progress
```

Adapter syntax changes must be tested at the Tree-sitter/IR boundary and at
the public behavior boundary. A language-specific node kind, receiver,
constructor, module root, or grammar-declared type spelling belongs in that
adapter and its fixtures, never in a shared hardcoded source-token union.
This includes pseudo calls and caller-visible write-back syntax: test the
adapter's positive form and its closest ordinary-expression negative, then
assert the language-neutral `CallKind` / `ArgumentPassingMode` fact.
Library/package/framework identities and security values belong in rule YAML;
provider-bound adapter facts must have a negative test proving that an
undeclared provider receives no sanitizer or source/sink credit.
For same-origin helpers, test the approved imported parser and a same-named
lookalike module. The adapter should emit both syntax facts with different
provider identities; only the rule-declared provider may clear taint.

Treat sanitizer changes as path-ordering changes:
source -> sanitizer -> sink can mark or suppress a path, while
source -> sink -> sanitizer cannot.

## Large-Codebase Performance Checks

Run the release binary and request an exhaustive JSON artifact. Do not impose a
command timeout as a substitute for scalability; external CI watchdogs may
still detect a genuine hang, but the analyzer must complete the requested
semantic fixed point.

```bash
env BONSAI_DEBUG=security-phase,idg-build \
  ./target/release/bonsai-ninja security ../large-project taint-analysis \
  --profile production \
  --format json \
  --all \
  --no-color \
  --no-progress \
  --output-path /tmp/bonsai-large-project.json
```

A valid result has `analysis_complete: true`, an empty incomplete-reason
list, valid source/sink/path files, deterministic IDs, clean pagination, and no
cache persistence warning. Record cold and warm wall time, peak RSS, file
count, rule-match counts, finding count, cache state, and swaps.

The production taint result is not bounded by BFS depth, iterations, source
count, or result count. The sparse IDG closure runs to a fixed point.
`--all` removes output paging; it does not enable a more accurate engine.
Path-preview and diagnostic controls are allowed only when they report
truncation and do not feed semantic reachability. The streamed IDG sidecar has
no workspace file-count ceiling.

The current Elasticsearch references are the dated 30,055-file runs in
[Release Readiness](RELEASE_READINESS.md). The exact large-workspace suite
covers fresh-cache planning, warm reuse, navigation, inspect, inventory, and
production taint under a 3 GiB scheduling budget. The gate requires production
security to finish complete and keeps every measured warm query/analysis
command below its reviewed SLO. Older
synthetic and superseded whole-body timings remain in
[the archived goal benchmark](goal-benchmark-2026-05-15.md).

Use `BONSAI_DEBUG=security-phase` for phase timing and add `idg-build` when
the semantic graph phase is slow. For package-oriented languages, call-edge
site counts should remain proportional to real resolved call sites. A
sibling-package same-name explosion indicates resolver/module narrowing
regressed.

## Security Pattern Audit

Use this stricter pass when reviewing the checked-in rulepack end to end:

```bash
./target/release/bonsai-ninja security . pack --validate --taint-replay \
  --format json --no-color --no-progress

./target/release/bonsai-ninja security . pack --audit \
  --format json --no-color --no-progress

python3 scripts/pack_audit.py --duplicates --fail-on-family-file-mismatch
python3 scripts/pack_audit.py --json > /tmp/bonsai-pack-audit.json
```

Do not enable generic print, log, join, or parse patterns without a real
security boundary and constraints that keep common safe usage quiet. Solidity
uses the smart-contract taxonomy; do not manufacture app/web SQLi, XSS, SSRF,
path, or command-injection parity rules for it.
