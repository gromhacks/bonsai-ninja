# Getting Started

<Steps>

1. Install or build the CLI.
2. Index the workspace so structural facts are ready.
3. Keep `index --watch` running while you edit if you want save-time hot reloads.
4. Run `security taint-analysis` against a source tree.
5. Re-run with JSON or SARIF when you need machine-readable output.
6. Use `show F:...` or `security taint-analysis --flow F:...` to drill into a specific security flow.

</Steps>

## Install

### Cargo install

Use this when the crate is published or when you have a local checkout that you want Cargo to install into your toolchain.

```bash
cargo install --path crates/cli --locked
bonsai-ninja --version
```

### Prebuilt binary

Use a GitHub release artifact when you want the same binary locally and in CI.

```bash
tar -xzf bonsai-ninja-x86_64-unknown-linux-gnu.tar.gz
cd bonsai-ninja-x86_64-unknown-linux-gnu
chmod +x ./bonsai-ninja
./bonsai-ninja --version
```

### Local release build

Use the repository build when contributing or validating rulepack changes.

```bash
cargo build --release -p bonsai_cli
./target/release/bonsai-ninja --version
```

For non-release CPU architectures, validate the target toolchain and
parser-pack path before relying on a build:

```bash
scripts/check-targets.sh --extra
```

See [Platform And Architecture Support](platform-support.mdx) for the
release target matrix and parser bundle constraints.

## First Scan

```bash
./target/release/bonsai-ninja index ./examples/python/mega_flow
./target/release/bonsai-ninja security ./examples/python/mega_flow taint-analysis --rules-dir ./security-patterns
```

`index` is the syntax/construct warm-up command: it parses supported files
and builds the declaration/import indexes that later commands share without
forcing a whole-workspace semantic prewarm. Browse, inspect, trace, security,
export, and debug commands validate and hydrate sidecars when present, then
compute missing exact facts on demand when needed. Pass `--semantic` only
when a workflow explicitly wants structural semantic sidecars built up front;
pass `--prewarm-dataflow` only when it needs the full-workspace
compatibility dataflow projection built by itself. That projection serves
older SDK/query surfaces; it is not a separate taint engine. Retrieval
sidecars are candidate lookup:
exact indexes decide candidates; canonical facts and semantic graph
verification decide truth. Vector similarity is never evidence. Search,
inspect, and literal-filtered browse commands validate a fresh retrieval
sidecar from source/dependency/build fingerprints before large-repo candidate
lookup, then hydrate the selected candidate files/facts through canonical
APIs. Large or scoped queries that are not prewarmed fall back to canonical
syntax-backed facts instead of writing partial retrieval cache state.

Each adapter parses its own language with Tree-sitter and lowers syntax into
typed compiler facts. Shared resolver, callgraph, IDG, security, and export
passes consume those facts without hardcoded per-language name lists. Taint
propagation runs the sparse IDG to a fixed point without semantic depth,
iteration, or result caps; `--context`, `--page`, and inspect preview flags
only control what is rendered.

For development workflows, keep the workspace hot while your editor saves:

```bash
./target/release/bonsai-ninja index ./src --watch
```

Long-lived SDK projects use the same refresh path before queries, so
embedded tools can keep one project open and still see saved changes.
Reduced-open SDK projects, such as literal or path-filtered query opens,
keep their declared file scope stable by default.

For CI or scripts:

```bash
./target/release/bonsai-ninja security ./src taint-analysis \
  --profile production \
  --rules-dir ./security-patterns \
  --format json \
  --all \
  --no-color \
  --no-progress
```

## Read A Finding

Each finding has a stable `S:` ID, a source rule, a sink rule, a status, a primary security `F:` flow ID, and a `G:` flow-group ID. The source and sink show exact file, line, function, and rule metadata. The flow block shows the call path and the tainted argument at each hop.

<Tip>
Security text reports render flow bodies by default. Use `--context` and `--page next` to walk larger reports without losing source code.
</Tip>

```bash
./target/release/bonsai-ninja security ./src taint-analysis --flow F:0123456789abcdef
./target/release/bonsai-ninja security ./src taint-analysis --group G:0123456789abcdef
./target/release/bonsai-ninja show ./src F:0123456789abcdef
./target/release/bonsai-ninja show ./src G:0123456789abcdef
```

Use `inspect --flow F:...` / `inspect --group G:...` for structural
inspect IDs printed by `inspect`, `defs`, `refs`, and other
code-navigation commands. Security finding flow/group IDs are taint-path
IDs; reopen them with `show F:...` / `show G:...` or
`security taint-analysis --flow F:...` / `--group G:...`.

For code-navigation queries, `inspect` is rulepack-free by default: it
shows syntax hits plus bounded taint paths and source-body flow evidence
that contain the query. Add `--syntax-only` when you deliberately want
indexed facts without flow evidence, `--taint-flow` to request bounded raw
taint paths for large result sets, or `--graph-flow` to request structural
source-body evidence for large result sets that would otherwise render
syntax/index facts only. These flags change output scope, not analysis
accuracy.
