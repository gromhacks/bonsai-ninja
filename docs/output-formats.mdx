# Output Formats

Commands with a `--format` flag can write the selected payload to a file
with `--output-path <PATH>`. This replaces shell redirection for JSON,
SARIF, DOT, GraphML, Cypher, and text output; progress and diagnostics
still use stderr.

Text and row/object JSON commands are token-budgeted by default. Small
JSON results keep their native shape; larger results return page metadata
and the current rows or JSON lines. Use `--page next` or the printed
`P:...` cursor to continue. Use `--all`, `--context all`, or
`--context uncapped` only when you intentionally want an exhaustive
artifact.

These are presentation controls, not analysis budgets. The semantic IDG
closure runs to a fixed point before authoritative taint/security facts are
emitted. When a preview enumerator or page is limited, metadata says that more
output exists or that the preview was truncated.

## Grouped

Grouped view clusters flows that share a tail. Use it when a sink has many source paths but the same final call chain.

```text
GROUP 1 G:701fc172b976025d  3 flow(s)
  FLOW 1a F:c48be683d9e53628
  handle_request -> orchestrate -> persist -> execute
```

## Compact

Compact text keeps flow headers and step labels while omitting repeated source bodies. `inspect` uses `FLOW`; security source mapping uses `SOURCE FLOW`; security findings use `TAINT FLOW`. Security text expands flow bodies by default and paginates when needed; compact security blocks remain only when full source bodies cannot be resolved for a finding.

```bash
bonsai-ninja inspect ./src --query execute --compact
```

```text
TAINT FLOW 2 F:0123456789abcdef python.cmdi.os_system
handle_request -> run_pipeline -> orchestrate -> execute
  1 SOURCE app.py:29 request.args.get
  2 TAINT  app.py:48 run_pipeline arg[0] envelope -> envelope
  3 SINK   executor.py:29 os.system arg[0] cmd
```

## Graph

`export --format networkx`, `graphml`, and `cypher` project the same workspace graph into graph-tooling formats.

Native `export --all` preserves exhaustive semantics in an exact compressed
form when a derived path family could be quadratic. Add
`--full-propagations` only when a downstream consumer explicitly requires
every materialized propagation record; compression changes representation,
not graph meaning.

```bash
bonsai-ninja export ./src --format networkx --output-path graph.node_link.json
bonsai-ninja export ./src --format graphml --output-path graph.graphml
bonsai-ninja export ./src --format cypher --output-path graph.cypher
```

## Train

Training or evaluation pipelines usually consume native JSON because it preserves exact rule IDs, locations, tainted args, chains, taint path steps, and stable IDs.

Use `security taint-analysis --summary --format json` when a tool only
needs aggregate triage counts. Summary mode emits the summary object
directly, including severity, status, precision, tag, language, source
rule, and sink rule counts, without paged finding rows.

```json
[
  {
    "finding_id": "S:979a7231afe45297",
    "source": { "rule_id": "python.flask.request_args_get", "line": 29 },
    "sink": { "rule_id": "python.cmdi.os_system", "line": 29 },
    "chain_display": ["handle_request", "run_pipeline", "orchestrate", "execute"],
    "taint_path": [
      { "caller": "handle_request", "callee": "run_pipeline", "tainted_args": [{ "index": 0, "value_text": "envelope" }] },
      { "caller": "execute", "callee": "os.system", "tainted_args": [{ "index": 0, "value_text": "cmd" }] }
    ]
  }
]
```

## SARIF

SARIF 2.1.0 is available from `security taint-analysis`. Results include standard locations, code flows, rules, CWE properties, and bonsai-specific metadata under `properties.bonsai`. Security code flows are built from the same source-specific propagation used by text `TAINT FLOW` output.

SARIF also includes exact source-independent findings by default, such as weak crypto, weak random, JWT, TLS, cookie, CORS, and memory API misuse rules. These results intentionally omit `codeFlows` and use a synthetic `pattern:<sink-rule-id>` source id so consumers do not mistake a local API misuse for a proven source-to-sink taint path. Lifecycle-audit transition sites are excluded from SARIF/taint findings until the engine proves the later same-value use.

`security source-analysis` is source-flow mapping, not vulnerability
finding output. It accepts text and JSON only; `--format sarif` is
rejected with a clear error so callers do not confuse source inventory
with security findings. Use `--format json` for structured `SOURCE FLOW`
data.

```json
{
  "$schema": "https://docs.oasis-open.org/sarif/sarif/v2.1.0/cs01/schemas/sarif-schema-2.1.0.json",
  "version": "2.1.0",
  "runs": [{
    "tool": { "driver": { "name": "bonsai-ninja", "rules": [] } },
    "results": [{
      "ruleId": "python.cmdi.os_system",
      "level": "error",
      "message": { "text": "Tainted input reaches os.system" },
      "locations": [{ "physicalLocation": { "artifactLocation": { "uri": "executor.py" }, "region": { "startLine": 29 } } }]
    }]
  }]
}
```

## Deps

Dependency output lists imports that match package names mentioned by the loaded rulepack.

```bash
bonsai-ninja security ./src deps --severity critical --format json --output-path deps.json
```

```json
[
  {
    "package": "flask",
    "language": "python",
    "file": "app.py",
    "line": 14,
    "rules": ["python.flask.request_args_get"]
  }
]
```
