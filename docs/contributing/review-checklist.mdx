# PR review checklist

A change-class checklist for reviewers and contributors. Match your PR's
class and verify each box.

---

## Engine change (`crates/taint/src/idg_api.rs`, `idg_build.rs`, `reachable.rs`, `intra.rs`, `assignment.rs`)

- [ ] **Test pins the change.** A focused test in the affected crate's
      dedicated test file (`*_tests.rs`, `tests/over_taint_matrix.rs`,
      `tests/semantic_container_fields.rs`, etc.) reproduces the bug or
      demonstrates the new behaviour. Keep new regression suites outside
      large implementation files.
- [ ] **Empty seed invariant holds.** `interproc_false_path_clean_seed_
      does_not_propagate` and `concept_1_source_model_empty_seed_no_
      propagation` both pass.
- [ ] **Over-taint matrix passes.** `cargo test -p bonsai_taint --test
      over_taint_matrix` is green for all 20 languages.
- [ ] **Determinism holds.** `finding_ids_deterministic_across_runs`
      passes.
- [ ] **Quoted-literal short-circuit unchanged.** `arg_text_is_tainted` /
      `rhs_operand_is_tainted` do not propagate identifier tokens from
      inside string literals.
- [ ] **Matcher policy fingerprint bumped.** If the change alters
      propagation semantics, `MATCHER_POLICY_FINGERPRINT` is incremented.
- [ ] **`CONTEXTLESS_LOOKUP_JUSTIFICATION` markers preserved.** New
      `find_by_name` calls outside the resolver primitives carry the
      marker comment; conformance test
      `engine_resolves_via_context_not_bare_name` passes.
- [ ] **Single-candidate edges stay `Direct/Narrowed`.** No new
      widenings to `OverApproximate` when the resolver already
      narrowed the candidate set.
- [ ] **Fixed point stays uncapped.** No BFS name search, hidden call-depth
      ceiling, iteration budget, or result cap is introduced into the
      semantic IDG closure. Preview/path limits remain presentation-only.
- [ ] **One frontend/transfer interpretation remains.** Broad phases consume
      `CompiledFileObject`; persisted IDG construction spools typed stitch
      records and does not add a second Tree-sitter or transfer-lowering pass.
- [ ] **Compiler ABI bumped when required.** A change to persisted adapter IR,
      diagnostic semantics, or frontend post-processing bumps
      `COMPILER_OBJECT_CACHE_VERSION`; an IDG semantic change also bumps its
      normal pipeline fingerprint.
- [ ] **Documentation updated.** `docs/contributing/taint-engine-spec.mdx` reflects the
      new behaviour.

## Adapter change (`crates/lang_*/src/lib.rs`)

- [ ] **Conformance test passes.** `cargo test -p bonsai_lang_<name>`.
- [ ] **Workspace test passes.** `cargo test -p bonsai_workspace --test
      lang_<name>` and `--test inspect_lang_<name>`.
- [ ] **Per-language matrix passes.** `cargo test -p bonsai_cli --test
      per_lang_cli_matrix <lang>_matrix`.
- [ ] **Mega-flow fixture intact.** `scripts/validate-mega-cli.py`
      reports the expected finding count.
- [ ] **Capabilities declaration matches reality.** `fn capabilities()`
      reflects the actual coverage; `Unsupported` levels are honest.
- [ ] **Cross-language frontend contracts stay green.** Run
      `cargo test -p bonsai_conformance --test capability_matrix` and
      `--test flow_event_conformance`. Applicable capability cells may not be
      `Missing`; valid fixtures must be diagnostic-free, and malformed input
      must report parser incompleteness instead of silently claiming complete
      analysis.
- [ ] **Positive and negative taint contracts execute.** Run
      `cargo test -p bonsai_taint --test matrix`. Every applicable
      scenario/language cell executes the real engine, and every language must
      retain positive propagation, clean-overwrite, and over-taint negatives.
- [ ] **Syntax ownership stays in the adapter.** New source tokens, grammar
      node kinds, constructor/receiver forms, module roots, and broad type
      spellings are emitted as adapter facts. Shared crates do not branch on
      language id or accumulate a cross-language spelling union.
- [ ] **Adapter never reaches into core analysis.** Imports are limited
      to `bonsai_lang_api` and tree-sitter.
- [ ] **Fresh/object parity holds.** The adapter's typed output is fully
      serializable in `CompiledFileObject`; a warm decode cannot omit a fact or
      diagnostic that fresh Tree-sitter lowering emits.
- [ ] **Documentation updated.** `docs/contributing/architecture.mdx` per-language
      summary reflects new GrammarHandler config.

## Rule pack change (`security-patterns/`)

- [ ] **Validator passes.** `cargo run --bin bonsai-ninja -- security
      . pack --validate --rules-dir ./security-patterns` reports
      `valid: true` with zero error- or warning-level issues.
- [ ] **Rulepack conformance passes.** `cargo test -p bonsai_security
      --test rulepack_conformance`.
- [ ] **No FP audit passes.** `cargo test -p bonsai_security --test
      no_fp_audit`.
- [ ] **Match examples are realistic.** Imports use real adapter-visible
      forms (e.g. `from Crypto.Cipher import DES`, not `import
      pycryptodome`).
- [ ] **Discriminating constraints have positive AND negative examples.**
- [ ] **Disabled rules have `subsumed_by` pointing at an enabled
      canonical** (or transitively-enabled chain).
- [ ] **CWE / severity declared on sinks.** Validator catches missing
      values.
- [ ] **Taxonomy stays in the pack.** Package/API identities, manifest names,
      sink-family aliases, sanitizer cross-tag credits, and tag-level guard
      defaults are YAML metadata, not branches or tables in shared Rust.
- [ ] **Sanitizer-credit audit passes.** `python3
      scripts/sanitizer_credit_audit.py` reads the same metadata as runtime and
      reports no unknown or untagged sanitizer rules.

## Browse / Inspect / Trace change (`crates/browse`, `crates/inspect`, `crates/trace`)

- [ ] **Compiler phase stays minimal.** Syntax commands do not call
      `global_index()`, resolve a callgraph, open an IDG, or load a rulepack.
      They stream exact file-local compiler objects or use compact headers.
- [ ] **Predicates run before allocation.** File/name/kind/caller/callee
      filters are applied during the Tree-sitter IR walk, not after collecting
      every workspace row.
- [ ] **No nested lazy construction.** A Rayon file loop does not initialize a
      workspace-wide header, linkage, graph, or body cache. Initialize the
      immutable product before the loop or stream independent file objects.
- [ ] **Text rendering stays out of JSON cost.** JSON pagination does not read
      source-line previews or build flow annotations absent from JSON rows.
- [ ] **Browse tests pass.** `cargo test -p bonsai_workspace --test
      flow_event_audit_fixes` and the per-command tests.
- [ ] **JSON shape stable.** Field names in `*Out` structs match
      previous releases unless explicitly breaking.
- [ ] **CLI output unchanged.** `cargo test -p bonsai_cli --test
      browse_commands` passes.
- [ ] **SDK parity intact.** `cargo test -p bonsai_cli --test
      sdk_cli_parity`.
- [ ] **Pagination still works** for the affected command.
- [ ] **Inspect mode contract holds.** Default targeted queries are a light
      indexed syntax/source view. `--taint-flow` requests raw taint paths, and
      `--graph-flow` requests structural source-body evidence. These flags change
      output scope, not the exact/narrowed static-evidence contract.
- [ ] **Stable ID routing holds.** `show F:`, `show G:`, `show T:`,
      `show E:`, `show N:`, `show S:`, and resolver-scoped `show R:`
      delegate to the expected owner command.

## Security analysis change (`crates/security`)

- [ ] **Findings deterministic.** `finding_ids_deterministic_across_runs`
      passes.
- [ ] **SARIF parity intact.** `<lang>_matrix::micro_security_sarif_shape`
      tests pass.
- [ ] **Sanitizer fixtures intact.** `cargo test -p bonsai_cli --test
      sanitizer_fixtures` reports expected raw + sanitized findings.
- [ ] **Validator matches CLI.** `cargo test -p bonsai_cli --test
      validate_script` passes.
- [ ] **Hardcoded-knowledge boundary passes.** `scripts/audit-hardcoded.sh
      --check` reports zero production violations.
- [ ] **Documentation updated.** `docs/security-spec.mdx` reflects schema
      / lifecycle changes.

## CLI change (`crates/cli`)

- [ ] **Command coverage test passes.** `cargo test -p bonsai_cli --test
      command_coverage`.
- [ ] **Per-language command matrix passes.** `cargo test -p bonsai_cli
      --test per_lang_cli_matrix` must pass. This is the semantic command
      gate across all 20 supported languages: browse commands, navigation
      commands, debug dumps, export, `comments`, `security sources`,
      `security sinks`, `security sanitizers`, `security deps`,
      `security source-analysis`, `security taint-analysis`, and SARIF
      parity. Do not treat a command as covered by exit-code or JSON-shape
      alone; each row must preserve the language-specific semantic hints
      pinned in the matrix.
- [ ] **All-flag test passes.** Every command accepts the relevant
      `--all` / `--page` / `--context` flags consistently.
- [ ] **Theme / paging integration intact.** Output respects
      `BONSAI_THEME`, `--theme`, `--page`, `--context`.

## SDK change (`crates/sdk`)

- [ ] **Public re-exports preserved.** Existing consumers of
      `bonsai_sdk::*` still compile.
- [ ] **SDK / CLI parity intact.** `cargo test -p bonsai_cli --test
      sdk_cli_parity` passes.
- [ ] **Documentation updated.** `docs/contributing/sdk.mdx` lists the new API.

## Cache / performance / large-workspace change

- [ ] **Stable scoped identity holds.** Filtered workspaces preserve the
      complete workspace's deterministic `FileId` ordinal and reuse identical
      compiler objects; scoped opens never publish partial sidecars as a full
      generation.
- [ ] **Cache validation is exact and cheap.** Sidecar headers are checked
      before payload hydration. Unchanged manifest source-ledger entries avoid
      rehashing; any metadata change forces SHA-256 content validation.
- [ ] **Syntax lookup uses the symbol payload.** Complete declaration/type
      lookup decodes the independent header payload from the linkage
      factstore. It does not decode call linkage or every full compiler object
      and then clear `FlowEvent` bodies.
- [ ] **Header/body staging is preserved.** Compiler-object import indexes and
      compact syntax-target facts remain independently integrity-checked and
      decodable. Broad rule scans apply raw source anchors, exact
      import/package predicates, and exact adapter-lowered syntax targets in
      that order before decoding declaration/flow bodies. Streaming import
      consumers read the header even when optional package prewarm is empty;
      they do not invoke the adapter/parser again.
- [ ] **File-local inventory keeps exact ancestry.** Receiver-sensitive
      inventory loads the compact receiver-ancestry linkage payload and
      enriches exact local bodies. It does not load the complete symbol table
      or silently drop cross-file inheritance matches.
- [ ] **Memory changes scheduling only.** `BONSAI_MEMORY_BUDGET_MB` and worker
      settings may alter parallelism, cache retention, or spill frequency, but
      never files, facts, closure, iterations, or findings.
- [ ] **External-memory acceleration stays lazy.** Resident-only IDG fixed
      points do not reserve maximum spill pages, dense workspace bitsets,
      Bloom/positive caches, or temporary files. Promotion/spill is covered by
      unit and conformance tests and changes representation only.
- [ ] **Semantic prewarm is query-ready.** The immutable IDG generation carries
      its compact function/node directories and default semantic contextual
      fixed point. Warm open validates the accelerator before reuse and does
      not decode every source segment to rebuild it. A canonical-only sidecar
      remains a valid cold graph but must not satisfy `index --semantic`.
- [ ] **One canonical callgraph is shared.** Workspace callgraph publication
      seeds dataflow and flow-ID consumers with the same `Arc`; phase release
      drops all shared owners without discarding computed labels/facts.
- [ ] **Native export never enumerates paths.** CLI, SDK, and renderer expose
      only the exact `compressed_callgraph` relation. There is no
      `complete_chains`/capped-prefix switch, fixed chain count, BFS probe
      budget, or graph-size heuristic. Schema truncation counters remain zero
      and absent concrete rows reference the graph representation.
- [ ] **Export phase residency is sequential.** Structural/flow callgraph rows
      serialize first, then all canonical callgraph owners and resident
      presentation labels are released. Exact file-local body projections
      serialize next and release the body cache before the IDG opens. A
      one-shot cache miss writes directly to the requested sink; only
      `cache rebuild --export` may publish a reusable default export.
- [ ] **IDG queries reuse IDG linkage.** Query code calls
      `IdgQueryService::global_linkage_index()` and streams exact attribution
      bodies on demand; it never calls `AnalyzerDb::global_index()` and
      materializes every body beside an already-open graph.
- [ ] **Inspect syntax and IDG residency are sequential.** `inspect
      --taint-flow` records exact AST target spans, releases syntax bodies and
      graph caches, and only then opens the persisted IDG. Broad target sets
      use one sparse backward demand proof plus exact forward closures; they
      do not run an unrestricted whole-IDG closure once per lexical hit.
- [ ] **Architecture invariant passes.** Run
      `cargo test --release -p bonsai_conformance --test
      architecture_invariants`.
- [ ] **Hardcoded-knowledge boundary passes.** Run
      `scripts/audit-hardcoded.sh --check`. Review production code, excluding
      `#[cfg(test)]` fixtures: Tree-sitter grammar strings stay in adapters;
      API/package/security values stay in rulepack data; shared crates contain
      only typed IR, algorithms, protocols, and centralized product policy.
      Do not approve a language-id branch in shared analysis or move an API
      spelling from shared analysis into an adapter as a cosmetic fix. This is
      a zero-violation gate, not a ratcheted snapshot.
- [ ] **Elasticsearch exact SLO gate passes.** Build the release binary, then
      run `BONSAI_REQUIRE_ELASTICSEARCH_GATE=1 cargo test --release --locked -p bonsai_cli --test
      elasticsearch_large_repo -- --nocapture` with
      `../elasticsearch` or `BONSAI_ELASTICSEARCH_ROOT`. The gate waits for
      completed exact work and checks warm index, navigation, inspect,
      inventory, and production taint latency under the default 3 GiB
      scheduling budget; it never times out or truncates analysis. Keep its
      shared scenario lock: measured commands must not compete with one another
      inside Rust's parallel test harness. The lock does not serialize analyzer
      workers.
- [ ] **Rooted query scheduling charges committed memory, not mapped cache
      history.** The external-memory IDG's clean file-backed pages are
      reclaimable. Keep the named non-reclaimable reserve and per-closure
      sparse-frontier profile covered at 1/2/3 GiB; do not use live RSS to
      collapse a warmed exact query to one worker, and do not add a minimum
      worker count that ignores the configured budget.
- [ ] **Broad raw-flow paging performs only requested presentation work.** Row
      costs are worker-precomputed and reused. The renderer must not serialize
      or rescan every exact flow for each page and must not eagerly format
      future raw-taint pages. Every result remains reachable through stable
      page/cursor navigation.
- [ ] **Broad matcher scheduling has no artificial barriers.** Raw source
      ingestion uses memory-weighted parallel read windows but publishes VFS
      entries in canonical order. Raw rule-anchor planning uses the bounded
      worker pool and preserves that order; it must not rescan every file/rule
      pair on one thread. Body matching sizes one continuous worker pool
      against the largest actual source units that can overlap. Memory changes
      concurrency and window size only, never files, rules, or facts.
- [ ] **Cold security planning stays staged.** A fresh-cache production scan
      applies raw/import/syntax-target filters before receiver ancestry,
      requests ancestry only for typed method candidates it can change, and
      reuses exact parser coverage in the completion audit. Unchecked files
      receive a Tree-sitter diagnostic pass only; declarations and flow bodies
      are not lowered for `analysis_complete`. On the reference Elasticsearch
      checkout, compare against the recorded final 2026-08-06 ABI-v62
      fresh-cache baseline (30.22 s, 3 GiB scheduling budget) and investigate
      material regressions
      rather than loosening the gate. The same checkout's exhaustive
      `security sinks --severity high --context 4k` baseline is 22.63 s process
      wall time under the same budget. The 2026-08-07 final warm-generation
      repeat completed fresh-cache taint in 34.28 s, warm taint in 27.74 s, and
      broad raw-taint inspect in 29.53 s with all 12,233 entry closures retained.
      The current ABI-v64 migration gate completed its one-time generation in
      1,672.82 s, immediate reuse in 2.34 s, fresh-cache taint in 29.89 s,
      warm taint in 28.46 s, broad raw-taint inspect in 27.11 s, and scoped
      `read-file` in 1.31 s. Every navigation and inventory SLO passed under
      the 3 GiB scheduling budget.
- [ ] **Large native export gate passes when relevant.** Export the complete
      sibling Elasticsearch checkout under a recorded scheduling budget,
      validate with `jq --stream`, and record bytes, wall time, physical
      footprint/RSS, dirty resident memory when available, swaps, hash, and
      incompleteness reasons. Confirm the three chain/flow modes are
      `compressed_callgraph`, truncation counters are zero, and no hidden
      `export.default.*` artifact was created in the workspace cache.
- [ ] **Baseline changes are explained.** Record file count, cold versus warm
      state, wall time, physical footprint/RSS, swaps, and
      `analysis_complete`. Do not replace a regression with a looser SLO
      without an intentional architecture rationale.

## Documentation-only change

- [ ] **Code references match.** File paths, function names, type
      signatures referenced in docs match the current code.
- [ ] **Cross-links resolve.** Markdown links point at existing files
      and sections; `python3 scripts/audit-docs.py` passes.
- [ ] **Command surface checked against the binary.** Run
      `./target/release/bonsai-ninja --help` and the affected
      `<command> --help` output before updating CLI docs.
- [ ] **Help layout documented consistently.** Root help keeps
      `COMMAND GROUPS` before global `OPTIONS`, and CLI docs preserve
      the uppercase section casing used by the binary (`USAGE`,
      `OPTIONS`, `ARGUMENTS`, `COMMANDS`, `EXAMPLES`, `SEE ALSO`).

## Workspace-cache change (`crates/workspace/src/{dataflow,value_flow,flow_ids,taint_index,class_index,enclosing_index,decl_name_index}.rs`)

- [ ] **Invalidation hook fires on edit.** New caches expose `clear()`
      (or `invalidate_file(file)` for per-file granularity) and
      `Workspace::ingest_dir` calls it in the `if let Some(prev) = old_id`
      block.
- [ ] **`parking_lot` read-then-write hazard avoided.** Read-lock
      temporaries from `if let Some(x) = lock.read().get(...).cloned()`
      are bound to a `let` so the guard drops before any
      `lock.write()` upgrade. The cached resolved-call-graph pattern in
      `crates/workspace/src/lib.rs` is the template.
- [ ] **Sidecar persistence is content-addressed.** New on-disk
      caches carry a version + content-hash + matcher-policy
      fingerprint. Mismatched fingerprints invalidate.
- [ ] **Workspace prewarm wires through the shared call graph.** New
      caches that need a `ResolvedCallGraph` accept it via
      `seed_call_graph(arc)` (or call
      `Workspace::cached_resolved_call_graph()`); they don't rebuild
      identical content.
- [ ] **Tests cover invalidation.** A unit test rewrites a fixture
      file and asserts the cache produces fresh results (not stale
      ones).

## All changes

- [ ] Unit-test bodies stay in separate sibling files (`*_tests.rs` or
      crate-root `tests.rs`), leaving production modules with only the
      `#[cfg(test)] mod ...;` declaration.
- [ ] `cargo build --release` is warning-free.
- [ ] `cargo test --workspace` passes (full sweep before merging).
- [ ] `[profile.test] debug = 0` remains enabled. The full workspace creates
      hundreds of executables that each link the 20-language graph; opt in to
      `CARGO_PROFILE_TEST_DEBUG=2` only for a focused debugger session.
- [ ] No `panic!` / `unwrap()` introduced on user input.
- [ ] No `unsafe_code` introduced.
- [ ] Commit message explains the why, not just the what.
