# Contributing

## Dev Setup

```bash
cargo build --workspace
cargo test -q -p bonsai_cli --test security_commands
cargo test --workspace
```

Use `./target/release/bonsai-ninja` for CLI validation when the test or script expects the release binary.
Before merge, also run `cargo check --workspace --all-targets --locked`,
Clippy with `-D warnings`, rustdoc with `-D warnings`, and the
architecture invariants. The exact current gate is in
[Release Readiness](../RELEASE_READINESS.md).

## Test Layout

Keep production modules focused on production code. Unit-test bodies live in
separate sibling files and are included with a small `#[cfg(test)]` module
declaration:

```rust
#[cfg(test)]
#[path = "value_flow_tests.rs"]
mod tests;
```

For crate roots (`lib.rs`, `main.rs`, or `mod.rs`), `mod tests;` may point to
the conventional sibling `tests.rs` file. For nested modules, use an explicit
`#[path = "..._tests.rs"]` so Rust resolves the file next to the module source.
Integration and matrix tests stay under each crate's `tests/` directory.

## Add A Rule

1. Choose `sources`, `sinks`, or `sanitizers`.
2. Put the rule in `security-patterns/langs/<lang>/<kind>/<family>.yml`.
3. Add positive and negative `match_examples`.
4. Run `python3 scripts/validate-pattern-pack.py --binary ./target/release/bonsai-ninja`.
5. Add a fixture test if propagation behavior changes.

## Add A Language Adapter

<Steps>

1. Add the tree-sitter grammar and adapter crate.
2. Implement the adapter contract with Tree-sitter-derived declarations,
   refs, imports, scopes, flow events, expression flow, and visibility.
3. Declare every `LanguageCapabilities` field explicitly, including module,
   constructor, receiver, type, and field-place facts. Do not add language
   branches or source-token inventories to shared analysis.
4. Add micro, complex, sanitizer, and mega-flow fixtures.
5. Register the adapter in the bundled registry.
6. Run conformance, per-language matrix, and full workspace tests.

</Steps>
