# FlowEvent shape specification

The canonical, cross-language shape of `bonsai_lang_api::FlowEvent`. Every
adapter must emit events that conform to this spec — the engine's
intra/inter-procedural passes, the matcher, the trace exporter, and the
SDK all read events through this contract. New adapters and field
additions begin here.

The enum lives at
[`crates/lang_api/src/types.rs`](../../crates/lang_api/src/types.rs).

## Conformance gates

Every variant declared "supported" by an adapter is exercised by the
[capability matrix](./adapter-capabilities.mdx) and by the
**flow-event conformance suite**
(`crates/conformance/tests/flow_event_conformance.rs`), which runs
canonical fixtures through every bundled adapter and asserts the
shape contract documented below. The suite also requires canonical valid
fixtures to be parser/adapter-diagnostic-free for all 20 languages. Its
malformed-source companion proves that each frontend reports a syntax error,
and marks the parser scope incomplete. Adapters may conservatively withhold
facts from a damaged file or retain facts outside the exact error span, but
neither policy may claim complete analysis. Phase rollouts must move the
matrix cell from ❌ to ✅ and add or refresh the cross-language fixture before
merge.

## Variant catalog

The fifteen `FlowEvent` variants below are the complete vocabulary the
engine accepts. Anything else is an adapter bug.

### `Call`

```text
Call {
  span,                       // required
  name: String,               // adapter-normalized callee identifier
  receiver: Option<String>,   // explicit `obj.foo()` receiver text
  receiver_types: Vec<String>,// static types of `receiver`, post-kit pass
  call_kind: CallKind,        // Function | Method | Constructor | Macro | Operator | Indirect | ChannelSend | IndexWrite
  args: Vec<CallArg>,         // parsed positional/named argument facts
}
```

Adapter obligations:

- `name` is the adapter-normalized callee spelling. Adapters may retain a
  qualified grammar spelling when it carries real module or receiver syntax;
  the resolver derives its canonical short-name variants centrally without
  reparsing source text.
- `receiver` is set for `obj.foo()` / `obj->foo()` / `obj:foo()` /
  `obj::foo()` / `obj#foo()`. Implicit-receiver bare calls
  (`self.foo()` written as `foo()`) leave `receiver` as `None`; the
  kit's `apply_call_receiver_types` pass then infers
  `receiver_types` from the enclosing decl's `implicit_receiver_names`.
- `receiver_types` MUST be empty at adapter output time; the kit
  post-pass fills it. Adapters that want to short-circuit (e.g. when
  the callee class is unambiguous from the syntax) may pre-populate
  it — the kit pass is idempotent.
- `call_kind::Constructor` is structural: adapters emit it for grammar-proven
  construction such as `new Foo(...)` or an adapter-declared constructor
  method. When a language uses an ambiguous bare-call CST for `Foo()`, the
  callgraph refines it only after exact class/constructor resolution. Neither
  capitalization nor a shared constructor-name inventory is evidence.
- `call_kind::IndexWrite` is structural too: it represents an assignment
  through a parser-proven index/subscript place. The index and assigned value
  remain typed arguments; shared analysis does not pretend the source invoked
  a provider method.
- Constructor delegation is also structural. An adapter emits the exact
  constructor event from its CST (`this(...)`, `super(...)`, or the
  language's equivalent); shared callgraph resolution selects the enclosing
  class or its declared bases from symbol headers rather than recognizing
  those source tokens itself.
- `args[i].value_text` is retained for rendering only. `name` preserves an
  adapter-decoded keyword name, while `place`, `source_names`,
  `passing_mode`, and the file's `CallArgumentValueFact` table carry semantic
  value shape. `CallArgumentValueFact::value_kind` is the adapter's exact AST
  classification for the complete argument; it is the only generic evidence
  that a clean-output value is a literal. Inline callback parameter bindings
  are stored on that compiler fact from parsed parameter/pattern nodes. Shared
  analysis must never recover argument or callback semantics by tokenizing
  `value_text`, guessing from capitalization, or slicing source with `Span`.
- `args[i].passing_mode` is emitted by the active adapter. `WriteBack` means
  the callee may update the caller-owned place and enables the IDG's outbound
  parameter stitch. The shared kit and taint engine do not recognize
  language-specific address/ref/out tokens; unsupported languages emit
  `Value`, and each supported adapter carries positive and negative
  conformance fixtures.
- Literal keywords and string/character node kinds are adapter-owned grammar
  facts. They drive addressable-place suppression and string inventory
  directly; shared lowering has no cross-language literal token table.
  Identifier-shaped values such as JavaScript `undefined` remain dynamic
  unless that language adapter can prove literal semantics.

Direct constructor-owned receiver-field call assignments additionally appear
in `Decl::receiver_field_initializers`. This compact linkage fact stores the
adapter-normalized target and parsed call identity so cross-file linking can
resolve the constructed field type without retaining or reparsing the body.
It is not a second flow event and never types an unresolved or ambiguous call.

### `Branch`

```text
Branch {
  span,
  condition: Option<String>,   // diagnostic rendering only
  then_events: Vec<FlowEvent>,
  else_events: Vec<FlowEvent>, // empty when source has no else arm
}
```

Adapter obligations:

- `condition` is adapter-normalized diagnostic text. Engines must not parse
  it. The adapter's sibling `BranchConditionFact` owns semantic polarity and
  its optional typed `ConditionExpressionFact` tree owns boolean, equality,
  membership, type-test, runtime-truth, and exact scalar facts derived from
  Tree-sitter. `Truthy { operand }` preserves the exact tested property/value;
  a falsey literal fallback does not turn a dynamic projection into a constant.
- `then_events` / `else_events` must be **non-overlapping** even when
  the grammar emits a single flat block. The kit helper
  `repair_branch_events_by_else_keyword` partitions on the literal
  `else` keyword for C-like grammars; adapters in match/case-heavy
  languages call `split_match_arms_in_branch_events`.
- A branch with no else arm leaves `else_events` empty. Adapters MUST
  NOT synthesize an empty `else: pass` arm — the engine treats empty
  arms as "no constraint", not "no effect".

### `Loop`

```text
Loop {
  span,
  loop_kind: LoopKind,         // For | While | DoWhile | ForEach | Loop
  body: Vec<FlowEvent>,
}
```

Adapter obligations:

- `body` contains the loop-body events. A bare `for x in xs: F(x)`
  produces `Loop { body: [Call { name: "F", args: [{ value_text: "x",
  place: Some("x"), source_names: ["x"] }] }] }`
  with no Assign for the iteration binding — the engine resolves `x`
  through the function's parameter list / scope chain (the loop
  binding is part of the surrounding `Decl::params` for some grammars,
  or is synthesized from the grammar's parsed binding and iterable nodes).
- `LoopKind::ForEach` is for explicit collection iteration; `For` is
  C-style `for(init; test; step)`. `Loop` covers infinite/`loop` /
  `while true`.

### `Assign`

```text
Assign {
  span,
  target: String,                  // LHS bare name
  source_name: Option<String>,     // bare-name RHS rename: `y = x` → Some("x")
  source_call: Option<String>,     // direct call RHS: `y = f(x)` → Some("f")
  source_call_args: Vec<String>,   // call-arg texts when source_call set
  source_names: Vec<String>,       // bare identifiers in a compound RHS
  declares_new_binding: bool,      // CST node is a declaration (let/var/val/...)
  value_kind: Option<AssignValueKind>, // Literal | CallResult | YieldResult | Destructure | CallableReference | Compound | Unknown
}
```

Adapter obligations:

- For a **simple rename** (`y = x`): set `source_name`, leave
  `source_call` and `source_names` empty.
- For a **direct call**  (`y = f(x)` / `y = obj.f(x)`): set
  `source_call` to the adapter-normalized callee spelling and
  `source_call_args` to the
  per-positional arg texts; `source_name` and `source_names` stay
  empty. Identifier sigils retained by the concrete grammar (`$x`,
  `@x`, `%x`) are canonicalized before argument-carrier pruning, so a
  call argument cannot also appear as an independent call-result source.
- For a **compound RHS** (`y = a + b`, `y = f"{x}"`, `y = obj.field`):
  set `source_names` to every bare identifier visited; leave
  `source_name` and `source_call` empty.
- For a **literal RHS** (`y = "abc"`, `y = 42`, `y = true`,
  `y = None`): leave all three empty and set
  `value_kind = Some(AssignValueKind::Literal)`.
  An adapter with `quoted_callable_literals` may additionally retain the
  exact non-empty quoted token in `source_name` for runtime callable
  resolution. The value remains `Literal`, so IDG overwrite semantics still
  commit a clean writer and never treat the quoted token as value taint.
- `YieldResult` marks a binding supplied by a callee yield/callback boundary;
  `Destructure` marks one field or position projected from an aggregate; and
  `CallableReference` marks a syntax-proven function value rather than an
  invocation. These shapes preserve their typed transfer role without
  inferring it from `source_name` text.
- `declares_new_binding` is `true` when the CST kind unambiguously
  introduces a new local binding (`let`, `var`, `val`, `const`, `my`,
  `our`, `local`, Python first-assignment in scope, etc.). It is
  `false` for re-assignments. This drives Phase-2 scope-aware
  bindings — incorrect values cause spurious cross-scope taint.
- The owning adapter classifies complete parsed values for assignments,
  returns, and call arguments through one expression-value contract. A
  synthetic or unsupported carrier-free shape becomes `Unknown`, never
  `Literal`; clean-overwrite therefore fails closed.

Multiple sibling assignments in a single source-level statement
(`a, b = f()`) emit one `Assign` per LHS target. Destructuring with
heterogeneous RHS shapes (`a, b = c, d`) emits `Assign { target: "a",
source_name: Some("c") }` and `Assign { target: "b", source_name:
Some("d") }`.

### `AggregateAssign`

```text
AggregateAssign {
  span,
  target: String,                 // normalized aggregate binding/place
  type_name: Option<String>,      // adapter-derived declared type
  value_flow: ExpressionFlow,     // fields/items/spreads from AST nodes
}
```

Adapters emit this variant for positional or named aggregate initializers.
`value_flow.aggregate_fields` preserves statically named map/object/record
fields, `tuple_items` preserves positional order, and `spreads` preserves
aggregate spread operands. For positional struct initializers, the workspace
resolves those items against the adapter-emitted `Decl::aggregate_layouts`;
it does not infer field order from names or a language table. This is the
field-sensitive compiler fact used by IDG transfer and export.

### `Return`

```text
Return {
  span,
  value_kind: Option<AssignValueKind>, // adapter-owned complete-expression shape
  value_text: Option<String>,   // rendering only
  value_name: Option<String>,   // single bare identifier returned
  value_flow: ExpressionFlow,   // AST-derived places, carriers, calls, aggregates
}
```

Adapter obligations:

- A bare-name return (`return x`): `value_name = Some("x")`,
  `value_flow.place = Some("x")` and `value_kind = Some(Compound)`.
- A call-expression return (`return f(x)`): `value_name = None`,
  `value_flow.call_sites` contains the exact call and `value_kind` is
  `Some(CallResult)` when classified at the return node.
- A compound return (`return x + y`): `value_name = None`,
  `value_flow.source_names = ["x", "y"]`.
- A literal return (`return 7`): `value_kind = Some(Literal)` and no value
  carriers.
- A void / bare `return;`: no value kind, name, or flow carriers.
- A template-literal return (``return `${x}` ``): `value_name =
  Some("x")` when the template wraps exactly one identifier with no
  static prefix/suffix that would make the value a derivation rather
  than a pass-through.

The interprocedural pass consumes `value_flow` and `value_name`; clean-return
proofs also consume `value_kind`. `value_text` is never reparsed for semantic
carriers.

### `Throw`

```text
Throw {
  span,
  value_name: Option<String>,   // `throw err` → Some("err")
  thrown_type: Option<String>,  // `throw new IOException(...)` → Some("IOException")
}
```

Adapter obligations:

- `value_name` is the bare identifier when the throw target is a
  single name (`throw err`, `raise e`). For
  `throw new IOException(msg)` it stays `None` — the value isn't a
  name reference.
- `thrown_type` is the **adapter-extracted static type**. Java /
  Kotlin / C# / Scala / Swift adapters populate this through
  `populate_*_exception_types`. Adapters that don't surface throw
  types leave it `None`, and the engine falls back to seeding any
  catch arm in scope.

### `Try`

```text
Try {
  span,
  body: Vec<FlowEvent>,
  catch_events: Vec<FlowEvent>,
  finally_events: Vec<FlowEvent>,
  catch_param: Option<String>,  // first-param binding of the catch arm
  catch_types: Vec<String>,     // declared catch-arm types
}
```

Adapter obligations:

- `body` holds the try / begin block events.
- `catch_events` is the **flattened union** of every catch / except /
  rescue arm. Adapters that need to preserve per-arm precision should
  emit separate `Try` events per arm; the canonical shape merges arms
  to give the engine one catch region to reason about.
- `catch_param` is the catch-arm's first-parameter binding: `e` in
  `catch (e)` / `except Exception as e:` / `rescue => e`. When
  present, the engine seeds the catch region with this name
  pre-tainted whenever any `Throw` in the body throws a tainted
  `value_name`.
- `catch_types` is the union of declared exception types across every
  arm. Empty means catch-all (`catch (...)`, `except:`). When
  non-empty, the engine pairs it with `Throw::thrown_type` to skip
  arms whose declared type cannot catch this throw.

### `Break` / `Continue`

```text
Break    { span, label: Option<String> }
Continue { span, label: Option<String> }
```

These are control-flow markers consumed by the CFG builder. Adapters
include `label` when the source has a labeled break (Java/Kotlin
labeled loops, Rust loop labels, Swift labeled `continue`).

### `Yield`

```text
Yield {
  span,
  value_text: Option<String>,
  value_flow: ExpressionFlow
}
```

`yield`, `yield from`, `yield return`. `value_text` is presentation evidence;
semantic transfer comes from the adapter-lowered `value_flow`. The IDG lowers
that expression to the callable's `Yield` endpoint and stitches it to an exact
`YieldResult` binding at each resolved call site. When an adapter proves an
inline callback/yield binding but the external callee has no workspace body,
the call's compiler-proven receiver and explicit arguments reach that binding
at narrowed precision. Shared analysis never selects this behavior from an API
or language spelling.

### `Await`

```text
Await { span, value_name: Option<String> }
```

`await`, `.await`, `await?`. The intra-pass treats `await expr` as
unwrap-pass: a tainted promise yields a tainted resolved value. The
adapter populates `value_name` when the awaited expression is a bare
identifier; compound awaited expressions
(`await fetch(url)`) leave it `None`.

### `Defer`

```text
Defer { span, body: Vec<FlowEvent> }
```

Go `defer stmt`, Swift `defer { … }`. Body events conceptually
execute at scope exit; the CFG builder threads them after the normal
returns.

### `Using`

```text
Using { span, body: Vec<FlowEvent> }
```

Python `with`, C# `using`. Body events execute under the managed
resource. The engine treats `Using::body` as a normal sequenced
block for taint propagation; lifecycle facts come through
`FlowEvent::Lifecycle`.

### `Lifecycle`

```text
Lifecycle { span, name: String, transition: String }
```

Resource lifecycle transition on a named binding. `transition` is one
of the canonical states: `freed`, `closed`, `unlocked`, `cancelled`,
`moved`. Consumed by the matcher's `RequiresState` constraint and by
the CFG builder for use-after-free / double-free analysis.

## Cross-language equivalences

The conformance suite asserts these semantic equivalences. When an
adapter emits a structurally different shape for a semantically
identical construct, it is an adapter bug, not a "language quirk."

| Construct | Python | JS/TS | Java/Kotlin/C# | Rust | Go | Ruby |
|---|---|---|---|---|---|---|
| Bare rename | `y = x` | `let y = x` | `var y = x` | `let y = x` | `y := x` | `y = x` |
| Direct call | `y = f(x)` | `let y = f(x)` | `var y = f(x)` | `let y = f(x)` | `y := f(x)` | `y = f(x)` |
| Literal write | `y = "abc"` | `let y = "abc"` | `var y = "abc"` | `let y = "abc"` | `y := "abc"` | `y = "abc"` |
| Single-condition branch | `if x: F(t)` | `if (x) F(t)` | `if (x) F(t);` | `if x { F(t) }` | `if x { F(t) }` | `F(t) if x` |
| Catch-bind | `except E as e:` | `catch (e)` | `catch (E e)` | n/a | n/a | `rescue => e` |

Adapter outputs MUST agree at the FlowEvent level. The exact field
populations are listed below.

### Bare rename — `y = x`

```text
Assign {
  target: "y",
  source_name: Some("x"),
  source_call: None,
  source_call_args: [],
  source_names: [],
  declares_new_binding: true | false,  // language-dependent
  value_kind: None,
}
```

### Direct call — `y = f(x)`

```text
Assign {
  target: "y",
  source_name: None,
  source_call: Some("f"),
  source_call_args: ["x"],
  source_names: [],
  declares_new_binding: true | false,
  value_kind: Some(CallResult) | None,
}
```

### Literal write — `y = "abc"`

```text
Assign {
  target: "y",
  source_name: None,
  source_call: None,
  source_call_args: [],
  source_names: [],
  declares_new_binding: true | false,
  value_kind: Some(Literal),
}
```

### Single-condition branch — `if x: F(t)`

```text
Branch {
  condition: Some("x"),
  then_events: [Call { name: "F", args: [{ value_text: "t", place: Some("t"), source_names: ["t"] }] }],
  else_events: [],
}
```

### Catch-bind — `try { F(t) } catch e { ... }`

```text
Try {
  body: [Call { name: "F", args: [{ value_text: "t", place: Some("t"), source_names: ["t"] }] }],
  catch_events: [...],
  finally_events: [],
  catch_param: Some("e"),
  catch_types: [...],   // empty for catch-all; populated for typed
}
```

## Field-level invariants

These are universal — every adapter, every language, every variant.

1. **Spans are byte-offset, source-relative.** A span pointing into a
   re-written buffer or a macro-expansion buffer breaks trace
   rendering and call-site reporting.
2. **Names preserve adapter-normalized syntax.** Canonical short-name and
   qualified-name variants are a resolver concern; shared consumers do not
   tokenize the rendered call spelling.
3. **Empty fields use empty collections, not synthetic placeholders.**
   `Branch { else_events: [] }` is the right shape for a no-else
   branch; `Branch { else_events: [Call { name: "<noop>", ... }] }` is
   wrong.
4. **Field semantics are language-agnostic.** An adapter cannot
   redefine `source_call` to mean "the LHS of `=`" because that
   language has weird syntax — it pre-normalises the syntax during
   extraction.
5. **Events are tree-structured, not flat.** Loop bodies live inside
   the `Loop::body` field, not in a sibling list with implicit
   sequencing. The engine's CFG builder relies on the tree.

## Analysis boundaries

`FlowEvent` describes source-visible syntax. The compiler does not execute a
language toolchain, package manager, macro expander, template compiler, or
bytecode decompiler while indexing a workspace.

### Generated and expanded code

Adapters lower the concrete syntax that Tree-sitter parsed. Macro calls,
preprocessor directives, and template/DSL forms can contribute ordinary
surface facts, but code produced only after expansion is unavailable unless
the generated source is also present in the selected workspace. Resolver and
diagnostic surfaces report the resulting static gaps; shared analysis must not
invent the expanded declarations or calls.

### Cross-language FFI

Each source file is lowered by its selected adapter. The engine does not infer
an ABI bridge between independently parsed declarations such as Rust
`extern "C"`, Python `ctypes`, JNI, P/Invoke, or native Node modules merely
because names look alike. A future bridge must be an explicit typed ABI model
with binding evidence, never a cross-language string match. Rulepacks can
describe security boundaries on either side, but that does not synthesize a
source-to-sink edge across the ABI.

### Compiled-only artifacts

The workspace ingests supported source text. Bytecode and binary artifacts
such as `.class`, `.jar`, `.dll`, `.pyc`, native libraries, and WebAssembly are
not decompiled into `FlowEvent`s. Analyze available source or generated source
when those components must participate in a path.

## Adapter migration

Adding a new event variant or field is a **two-step** rollout:

1. **Define the field with a sensible default** (`Option<T>` /
   `Vec<T>` / `bool`) and bump the compiler-object frontend ABI. Defaults keep
   source compatibility during the adapter rollout; the ABI bump prevents an
   older serialized object from masquerading as current compiler output.
2. **Populate it adapter-by-adapter**, gating progress on the
   capability matrix. Each adapter change includes positive and negative
   fixtures for the fact it now emits.

Removing or renaming a persisted field requires a compiler-object schema/ABI
bump and updates to every derived pipeline fingerprint. If the change also
alters matching or transfer semantics, bump the corresponding matcher or IDG
policy identity. Public SDK or output-schema changes follow the separate
stability rules in [specification.mdx](./specification.mdx#3-stability).
