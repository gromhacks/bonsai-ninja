# Adapter contract

The contract between `bonsai_lang_api::kit` and the per-language `lang_*`
adapters. New adapters and language-specific patches should follow it;
deviations should be documented here.

## What the kit guarantees

`kit::walk_flow_events(file, tree, src, handler)` walks a parsed
tree-sitter tree and emits a `Vec<FlowEvent>` per declaration. The walk
is driven by a supplied `GrammarHandler` — a declarative configuration
struct that names node kinds for each construct.

Every non-empty `GrammarHandler` field used in production is declared by the
owning adapter. `EMPTY_HANDLER` is only an ergonomic all-empty base for struct
update syntax; it does not activate defaults. `GENERIC_HANDLER` and
`COMMON_CALL_KINDS` exist only in `lang_api` tests for synthetic multi-grammar
fixtures. Production adapters may not reference either symbol, and the
architecture conformance gate rejects such a dependency.

`kit::decl_index_with_handler(pack_name, file, ctx, handler)` is the full
adapter pipeline (decls + refs + per-function flow events) in a single
call. Most adapters delegate fully to this helper and add language-
specific patches in their own `decl_index` implementation.

The database packages the completed declaration index, import index,
`FlowEvent` trees, auxiliary syntax facts, and diagnostics into one immutable
`CompiledFileObject`. That is the only persisted frontend unit. Adapters must
not write their own cache or make semantics depend on a later consumer: a
fresh Tree-sitter lowering and a decoded compiler object must be identical.
Object reuse is validated by relative path/module context, selected adapter,
frontend ABI, and SHA-256 source content.

An adapter that owns multiple Tree-sitter grammar variants selects the exact
pack with `LanguageAdapter::grammar_name_for_path`. TypeScript uses the
`typescript` grammar for `.ts`/`.mts`/`.cts` and the `tsx` grammar for `.tsx`.
The parser cache keys both adapter and grammar variant; syntax highlighting
uses the same per-extension selection. Shared parser/CLI code does not carry a
parallel extension-to-grammar table.

## Where language syntax belongs

In the adapter, not in `kit`. A useful test: if a Tree-sitter construct or
runtime syntax rule applies to exactly one language, it lives in that
language's adapter.

This does **not** make adapters a home for security API inventories. A package
name, framework receiver, source/sink method, safe configuration value,
forbidden key, escaping table, severity, trust class, or CWE belongs in
`security-patterns/langs/<language>`. The adapter lowers syntax to a typed
fact; rule data assigns security meaning; shared analysis joins the two. If a
proof needs new information, add a narrow typed fact or semantic role rather
than matching the API name in Rust.

Examples that follow this rule:

- Python FastAPI binder annotation merging — `lang_python`.
- Python `getattr(obj, "literal")` reflection rewriting —
  `lang_python::rewrite_python_constant_reflection`.
- Python `__all__` literal parsing for future wildcard-import narrowing;
  it is not a visibility boundary for explicit imports — `lang_python`.
- Python `gen.send(value)` coroutine resume forwarding —
  `lang_python::rewrite_python_generator_send`.
- Perl `\&foo` coderef invocation lowering — `lang_perl`.
- Erlang record pattern destructuring — `lang_erlang`.
- Ruby `class Child < Parent` header fallback — `lang_ruby`.
- Ruby `module_function` scope flip — `lang_ruby`.
- Rust tuple struct base extraction — `lang_rust`.
- Rust `tokio::spawn` body isolation —
  `lang_rust::isolate_rust_spawn_bodies`.
- Java / Kotlin / C# typed-exception extraction —
  `populate_*_exception_types` in each adapter.
- Java `Class.forName(...).getMethod(...).invoke(...)` chain rewriting —
  `lang_java::rewrite_java_reflection_chain`.
- Lua `local M = {}; ...; return M` module-export narrowing — `lang_lua`.

Examples that legitimately stay in `kit` because they describe
language-agnostic shapes:

- `repair_branch_events_by_else_keyword` — applies to any C-like grammar
  that drops the else arm. Keying on the literal `else` keyword is a
  generic recovery, not a language fact.
- `extract_return_value_text/name` — handles the `return EXPR;` shape
  that appears in every supported language.
- `extract_foreach_binding_assigns` follows each grammar's parsed binding
  and iterable fields, including wrapped range/generator clauses.
- `split_match_arms_in_branch_events` — applies to any match/switch
  grammar that emits a single flat Branch with arms concatenated.
  Adapters supply per-arm body spans; the helper rewrites for arm-
  disjoint precision. Used by Scala / Swift / Rust.
- Repeated field-name parameter extraction — applies to grammars that
  attach multiple `name` fields to one parameter declaration, such as Go
  grouped parameters (`func(acc, tok string)`). The kit emits distinct
  parameter slots for each repeated name and reuses the shared type text.

## Standard adapter pipeline

```rust
fn decl_index(&self, file: FileId, ctx: &AdapterContext<'_>) -> DeclIndex {
    let mut idx = decl_index_with_handler(PACK_NAME, file, ctx, &HANDLER);
    // Per-language post-processing.
    apply_per_language_visibility(&mut idx, ...);
    apply_per_language_type_aliases(&mut idx, ...);
    apply_per_language_bases(&mut idx, ...);
    apply_per_language_synthetic_events(&mut idx, ...);
    bonsai_lang_api::apply_file_stem_semantic_identity(&mut idx, ctx);
    idx
}
```

Post-processing patches must be **idempotent** and **non-overlapping**:
two adapters running back-to-back over the same `DeclIndex` (e.g. C/C++
header reuse) must converge to the same final state.

## Hook surface

When the kit needs language-specific behaviour in its core walker, the
right move is a hook field on `GrammarHandler`, not an
`if language == "X"` branch.

Existing hooks:

- `pseudo_call_extractor(node, file, src, handler) -> Option<FlowEvent>` —
  adapters lower non-call-shaped invocations to the `Call` model. JSX/TSX,
  Go sends, C++ delete expressions, Perl scalar eval, PHP echo, Ruby
  subshells, and Scala operator calls are implemented by their owning
  adapters; `kit/pseudo_call.rs` only dispatches the active callback.
- `pseudo_call_receiver_extractor(node, src) -> Option<Node>` — preserves the
  exact receiver subtree for pseudo calls so value-flow facts join by span.
- `syntax_event_extractor(node, file, src, handler) -> Option<FlowEvent>` —
  lowers an adapter-owned grammar node whose typed control/dataflow meaning
  cannot be selected from a single construct-kind list. Kotlin uses it to
  distinguish the variants of `jump_expression`; Scala uses it to retain the
  dynamic payload carried by a constructed exception; C++ uses it for direct
  initialization declarations such as `Repository repo(args)` and constructor
  initializer entries such as `Derived(args)`. The shared walker consumes the
  emitted event without inspecting language keywords or types. Adapter syntax
  events are tested before generic declaration/initializer pruning because a
  grammar may encode an executable construct in a declaration-shaped node.
  When a grammar places executable nodes outside the function body, as C++
  does for a constructor's `field_initializer_list`, the owning adapter must
  walk that exact syntax and prepend its events to the declaration body. It
  must not reconstruct the call later from text or callee-name guesses.
- `argument_passing_mode_extractor(argument, value) -> ArgumentPassingMode` —
  classifies caller-visible write-back from the owning grammar. Shared
  lowering receives only `Value` or `WriteBack`; it has no cross-language
  inventory of address/ref/out syntax.
- `callable_reference_extractor(node, src) -> Option<String>` — lowers a
  grammar-proven callable value without invoking it.

The ordinary construct inventories (`call_kinds`, `assignment_kinds`,
`member_expression_kinds`, `subscript_expression_kinds`, branch/loop/exit
kinds, and call-reference kinds) follow the same rule. An empty list means the
language does not expose that construct through the shared walker; shared
code never substitutes a union collected from other adapters.

`special_forms` selects a small typed lowering capability when a grammar
encodes control flow or calls in a nonstandard tree shape. The adapter still
declares the capability; shared consumers must never select it from a
`LanguageId` or an API/package spelling.

Helpers that aren't hooks:

- `apply_file_stem_semantic_identity` /
  `apply_module_path_semantic_identity` — standalone because they need
  the adapter context.

`LanguageAdapter::parse_recovery_edits` is the parser-boundary hook for
grammar mismatches that the adapter can prove from the concrete syntax tree.
Recovery edits operate on a private, same-width parser buffer; the workspace
keeps the original source snapshot, and every emitted span still addresses
the original bytes. The parser accepts a recovery only when its exact
`ERROR`/missing-node damage score strictly improves.

The shared C-family recovery derives declaration macros from parsed
preprocessor directives and resolvable include edges. It also recognizes the
standard `va_arg(list, pointer_type)` CST shape, where Tree-sitter parses the
type head but leaves only the pointer declarator as an `ERROR` sibling. That
recovery masks the proven pointer token; it does not maintain a library API
inventory, expand arbitrary macros, or reinterpret malformed value
expressions.

New hooks should:

1. Take only data the adapter could know (no `Db` handle).
2. Return `Option<...>` or a small enum — not `bool` flags that
   accumulate over time.
3. Carry a docstring naming the language(s) that use it and why the kit
   can't do it generically.
4. Describe source syntax only. A hook must not classify a library call as a
   source, sink, sanitizer, or vulnerability.

## Branch arm contract

`FlowEvent::Branch { then_events, else_events, .. }` requires both arms
to be present when the source has both arms. If a grammar can only
distinguish them in one shape, the adapter normalises before walking —
or falls back to `kit::repair_branch_events_by_else_keyword` for span-
based partitioning around the outer `else` keyword.

Adapters must not emit both arms under `then_events` and trust the
repair to fix it. The repair is a last resort, not a primary strategy.
Same caveat for the missing first-else assignment synthesis.

The common declaration-index pass also emits `BranchConditionFact` for every
grammar-proven conditional, including the exact condition span and parsed
negation polarity. Adapters using `decl_index_with_handler` receive these
facts automatically. A custom declaration-index path must call
`extract_branch_condition_facts`; downstream analyses must not reconstruct
condition polarity from `FlowEvent::Branch.condition` text.

`ConditionExpressionFact::Truthy` is the typed form for a grammar-proven
runtime truth test of one exact operand, such as a boolean property projection.
An adapter must preserve the operand place/call identity. For falsey fallback
expressions, retain the dynamic operand selected by the AST; a clean literal
fallback does not erase the dynamic projection from the condition fact.

## Value-shape summary contract

Security guards that are not a single library call are still compiler facts,
not shared source-text heuristics. The owning adapter may attach the following
exact, serializable summaries to `DeclIndex`:

- `CharacterConstraintFact` for a character comprehension, regular-expression
  substitution, or equivalent runtime construct whose output alphabet is
  proven by the parsed syntax;
- `GuardedValueFilterFact` for a clean output whose only dynamic element write
  is copied from one input under a positively required predicate call. The
  fact records the exact predicate, write, input, and output spans/places but
  does not decide what the predicate means;
- `SameOriginPathConstraintFact` for a helper that rejects schemes and
  authorities, requires an absolute path, and rejects `//` paths;
- `DynamicKeyFilterFact` for a helper that drops a finite static key set before
  reconstructing an object;
- `StringCompositionFact` for concatenations, interpolations, accessor calls,
  and language-level literal fallbacks used to reconstruct a value;
- exact static aggregate/scalar fields on `CallArgumentValueFact` for
  constructor or call configuration.

Provider-dependent facts record the canonical imported factory/operation call
but do not classify it. `CharacterConstraintDomain::ProviderBound` and
`SameOriginPathConstraintFact::provider_call` receive security credit only
when rule metadata declares that provider. `SameOriginPathConstraintFact`
also carries the exact guarded `input_place`; `input_param_index` is present
only for a reusable helper summary and absent for caller-local guarded values.
Likewise, a `GuardedValueFilterFact` receives sanitizer credit only when an
enabled sanitizer rule matches its exact `predicate_call_span`. Proximity to a
predicate is never evidence: negated predicates, predicates over a different
input, non-zero initialization, and any additional unguarded dynamic output
write must prevent the adapter from emitting the fact.

These facts describe language/runtime behavior only. They do not name a CWE,
sink, package, or security API. The rulepack assigns security meaning by
declaring the forbidden characters, required configuration values, URL
component roles, or denied keys. Shared analysis relates those rule-owned
requirements to the typed facts and never branches on a language id.

Lowering must fail closed. A summary is omitted when the frontend sees a
spread, computed property, mutable/shadowed configuration binding, ambiguous
helper target, unsupported escape, partially parsed expression, or a value
that can reintroduce a forbidden character. `direct_call_span` is set only
when the complete argument expression is one direct call; a nested call inside
a larger expression must not receive that proof. Every positive adapter test
for one of these summaries needs a nearby negative test that breaks exactly
one proof condition.

## Capability declarations are the narrow source of truth

`LanguageCapabilities` (`crates/lang_api/src/capabilities.rs`) is
where adapters declare per-language behaviour the engine consults:

- **`module_export_aliases`** — receiver names the language treats as
  module-export aliases (`exports.X` for JS/TS).
- **`module_default_export_names`** — adapter-emitted declaration names
  representing callable default exports.
- **`module_path_syntax`** — rooted qualified-name prefixes recognized by
  that language. Shared resolution never carries a union of source tokens.
- **`universal_type_names`** — type spellings that intentionally provide no
  receiver/overload narrowing in that language.
- **`constructor_method_names`** — narrow constructor-name list.
  Empty means the language has no method-name constructor form; there is no
  cross-language fallback.
- **`super_receiver_tokens`** / **`implicit_receiver_tokens`** — same
  shape: exact per-adapter declarations. Empty means no such source syntax.
- **`callable_reference_syntax`** — exact callable-value prefixes, arity
  notation, optional symbol wrapper, and trailing invocation punctuation.
  Shared callgraph/IDG code applies only the active adapter's declaration.
- **`field_places_complete`** — every source-level field/property
  projection is emitted as an IDG `Place`. Sink-oriented analysis may then
  run sparse AST-demand forwarding for that adapter. Leave this false until
  call-shaped properties, patterns, and implicit projections all have
  conformance coverage; complete export graphs never use this optimization.

Synthesized declarations remain adapter-owned compiler IR. A computed
property getter must derive `receiver_state_sources` from its lowered body in
the same way as an ordinary method; for example, `var cmd { data.cmd }`
retains the exact `self.data` receiver dependency. Template adapters follow
the same rule: Ruby ERB/RHTML synthetic modules expose only Tree-sitter-proven
instance-variable inputs from template expressions, never a shared list of
framework variable names.

The empty value is meaningful. Shared compiler backends do not substitute a
cross-language token list, guess from capitalization, or parse source text.

The `Decl`-field population matrix in
[adapter-capabilities.mdx](./adapter-capabilities.mdx) is the
canonical view of which adapters populate which fields.

## Workspace caches that depend on adapter facts

Adapters should be aware that the workspace caches several derived
artifacts per file/decl, keyed on `(FileId, version, content_hash)`
or equivalent:

- **`ClassMemberIndex`** — `(class_sym, method_name) → Vec<FuncId>`
  and `class_sym → constructor FuncIds`. Built from the global
  decl index. Requires adapters to populate `Decl::parent` for
  class methods and `DeclKind::Constructor` for constructors. Constructor
  method forms are adapter-declared in `constructor_method_names`; an empty
  declaration means no method-name constructor form. Shared resolution has no
  cross-language constructor fallback.
- **`EnclosingIndex`** — per-file binary-searchable enclosing-decl
  span array. Requires `Decl::body_span` (or `Decl::span`) to be
  monotonically increasing in file-position order; decl bodies in
  one file must not overlap at the same start.
- **`DeclNameIndex`** — workspace-wide lowercased decl-name table
  for `inspect --query <pat>`. Requires `Decl::name` to be the
  identifier the user would type.
- **`ValueFlowCache::returning_seed_names`** — precomputed per
  function when a compatibility client first requests the value-flow graph;
  normal/full-prewarm indexing does not build every projection. Requires
  adapters to emit `FlowEvent::Return { value_name, value_text, .. }`
  with `value_name` populated whenever the return value is a single
  identifier. Returns of compound expressions
  (`return x + y`) populate `value_text` only; the value-flow graph
  emits the Return node according to the adapter's structured source facts.
  Canonical security/export return flow is answered by the IDG rather than
  this compatibility cache.
- **Per-decl matcher facts cache** (`crates/security/src/matcher/mod.rs`)
  — caches `collect_calls`, `collect_assignment_texts`, decorators,
  alias chains, runtime types, lifecycle transitions per decl.
  Requires `Decl::flow_events` and `Decl::type_aliases` to be stable
  for a given `(FileId, version, content_hash)`.

These caches are correctness-equivalent to the uncached path by
construction. They impose no new obligations on adapters beyond the
existing `Decl` / `FlowEvent` contracts.

## Forbidden patterns

- **No regex against full file contents.** The tree-sitter tree is the
  source of truth; if a fact is not in the tree, the adapter walks back
  to the source bytes for the relevant span. Whole-file regex defeats
  per-file caching.
- **No depending on file extensions inside extraction logic.** Workspace
  ingest already filtered to this adapter's files; the adapter is owned
  by exactly one language.
- **No emitting both qualified and bare `Call` events at the same
  span.** Browse layer dedup expects exactly one; emitting both forces
  browse to choose, which encodes adapter conventions where they don't
  belong.
- **No populating any `InterTaintConfig` transfer table from an adapter.**
  Adapters report facts through `Decl`
  and `FlowEvent`; the security layer is the only crate that translates
  rule matches into engine-config facts.
- **No relying on the engine to strip language keywords.** The engine
  doesn't pattern-match `new `, `return `, `def `, `__construct`,
  `Self(`, `static(`, or any other syntactic keyword out of raw
  expression text. Adapters classify constructors structurally
  (`CallKind::Constructor`), emit return values via `FlowEvent::Return`,
  and produce `value_text` that already has the keyword removed. Callable
  value prefixes, arity notation, and symbol wrappers are declared through
  `LanguageCapabilities::callable_reference_syntax`; shared crates own no
  cross-language punctuation inventory. Vocabulary-free name-boundary helpers
  are candidate lookup only and never establish symbol identity.

Imported namespace and type qualifiers are call-resolution syntax, not
runtime receiver values. Adapters emit their exact `ImportSpec` and
`CallReceiverFact` records; compiler-object linking marks matching whole-module
bindings as `CallReceiverRole::Namespace`. A parameter or non-import assignment
with the same name is exact shadowing evidence and keeps the receiver role
`Value`. IDG transfer must not create an implicit receiver edge for a
`Namespace` fact.

`ImportSpec` entries come only from grammar import/include/use declarations.
Never fabricate an import from a qualified type use to satisfy a package gate:
that corrupts local nested-type resolution and makes a syntax occurrence look
like external dependency evidence. Fully qualified calls remain provable from
their exact call identity plus rulepack-declared package semantics.

## Testing contract

Each adapter ships fixtures in its `tests/` directory and at minimum:

- A smoke test (parse + `decl_index` per file, asserts non-empty).
- A traced test (`run_traced(fn_name)`) for at least one representative
  function.
- Per-construct fixtures for every `LanguageCapabilities` field the
  adapter claims `Exact` or `Partial` for.

The cross-language regression matrix
(`crates/taint/tests/over_taint_matrix.rs`) adds invariants that must
hold for every supported language; new adapters should appear there.
