# Sanitizer and transform coverage

Fixtures under `test-fixtures/languages/<lang>/sanitizer_test/` and
`sanitizer_credit/` contain parallel raw and treated handlers. Historical
`_safe` / `sanitized` function names are test selectors, not safety claims.
The exact source-to-sink context determines the result.

Sanitizers never remove IDG propagation. Default taint output hides findings
with credited `sanitized` status; `--show-sanitized` exposes those paths without
changing analysis. A context-free transform remains visible and unsanitized.

## What the tests require

- `crates/cli/tests/sanitizer_fixtures.rs` checks that all 20 language fixtures
  retain a raw finding. C, C++, and Elixir fixtures additionally assert
  on-path sanitizer evidence and its rule/location fields. Erlang, Rust, and
  Swift URL-encoded shell fixtures assert non-crediting transform evidence.
- `crates/security/tests/sanitizer_credit_audit.rs` checks all 20 languages
  against their explicit expected context. Missing fixtures fail the audit.
- `crates/cli/tests/security_rule_context_regressions.rs` adds independently
  API-shaped unsafe and safe controls, checks exhaustive canonical JSON, and
  verifies that terminal output labels transforms consistently with JSON.

The credit audit's treated legs have these expectations:

| Languages | Expected treated-leg result |
|---|---|
| C, C++, Dart, Elixir, Erlang, Go, Kotlin, Lua, Objective-C, Scala, Swift | Any emitted treated finding must be `sanitized`; the raw control must remain visible. |
| C#, Java | HTML/Java escaping used in shell context must be `wrong-context`. Separate HTML-output controls must receive XSS credit. |
| JavaScript, Perl, PHP, Python, Ruby, Rust, TypeScript | Shell-quoting examples must remain `unsanitized`, with `taint_transforms_seen` and no sanitizer credit. |

These are fixture contracts, not claims that every library API or every
interpreter/version has been executed. Matching examples alone cannot prove
an API's security semantics; see [Rule Testing](../rule-testing.mdx).

## A wrapper is not automatically a sanitizer

```python
def quoted_command(cmd):
    return os.system(shlex.quote(cmd))
```

This still executes an attacker-selected command. Shell quoting does not
establish a trusted executable or prove placement for the selected interpreter.
The quote belongs in `taint_transforms_seen`, not `sanitizers_seen`.

Similarly, URL encoding does not validate a host or scheme. A redirect such as
`redirect("/next?to=" + value)` can instead be excluded through its exact fixed
local path prefix. Bare `"/" + value` does not establish that property.
An unrelated SQL bind elsewhere in a function does not protect interpolated
SQL text merely by co-occurring with it.

## Running

```shell
cargo test -p bonsai-ninja --test sanitizer_fixtures --test security_rule_context_regressions
cargo test -p bonsai-ninja-security --test sanitizer_credit_audit

bonsai-ninja security test-fixtures/languages/python/sanitizer_test taint-analysis \
  --profile all --inferred-sources --show-sanitized --format json --all \
  --no-color --no-progress | \
  jq '.rows[] | {id: .finding_id, status, sanitizers: (.sanitizers_seen // []), transforms: (.taint_transforms_seen // [])}'
```

Read `status` and the attributed rule/location evidence; neither handler names
nor a nonempty sanitizer array prove credit for the sink's context. The
`security sanitizers` inventory lists matched **credit-bearing** sanitizer
rules, not URL/shell transforms. Use taint analysis to inspect transforms along
actual flows, and `security pack` to inspect the complete rule catalog.
