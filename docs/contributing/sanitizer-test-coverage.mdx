# sanitizer_test — per-language fixtures exercising enabled sanitizers

Each `examples/<lang>/sanitizer_test/` directory contains one or more
handler files with parallel `<name>_raw` / `<name>_safe` pairs. The
raw form reaches the sink directly; the safe form keeps the tainted
value flowing to the sink with the sanitizer wrapping it so the
engine attaches sanitizer evidence to the finding.

The fixtures drive `bonsai-ninja security <ws> taint-analysis` and are the
regression surface for sanitizer behaviour — the engine must:

  1. Produce a finding for every `_raw` chain (no sanitizer in the
     path, taint reaches the sink directly).
  2. Attach the sanitizer as evidence on the `_safe` chain — the
     finding's `sanitizers_seen` array lists the sanitizer rule id
     with its source location.

Every language now has BOTH raw and sanitizer-evidence coverage
(verified by `crates/cli/tests/sanitizer_fixtures.rs`).

## The taint-through-wrapper pattern

The fixtures deliberately route taint THROUGH the sanitizer and
INTO the sink so the engine attaches sanitizer evidence — e.g.

```python
def cmd_safe(cmd):
    return os.system(shlex.quote(cmd))  # shlex.quote wraps, os.system is the sink
```

This mirrors real-world code: the sanitizer doesn't block the sink
call, it cleanses the tainted value before it reaches the sink. The
finding reports the sanitizer as evidence (a reviewer sees the
cleanse and downgrades the finding). "Safe" handlers whose tainted
data never reaches any sink (e.g. argv-form `Process.run` with no
shell, a pure return-string function with no response sink) wouldn't
generate a finding at all — so those handlers get rewritten to keep
the tainted value flowing to the sink.

## Running

```shell
bonsai-ninja security examples/python/sanitizer_test taint-analysis --format json | \
    jq '.rows[] | {id: .finding_id, sanitizers: (.sanitizers_seen | length)}'
```

Findings with `sanitizers > 0` are the `_safe` paths — the engine
threaded taint through the sanitizer and attached it as evidence.
Findings with `sanitizers == 0` are the `_raw` paths.

The paginated `security sanitizers` surface lists every enabled
sanitizer rule's hits independently of flows:

```shell
bonsai-ninja security examples/python/sanitizer_test sanitizers
bonsai-ninja security examples/python/sanitizer_test sanitizers --tag shell-escape
```
