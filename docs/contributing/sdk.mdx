# SDK

`bonsai_sdk` is the ergonomic facade. One crate, one entry point, every
analysis surface exposed.

```toml
[dependencies]
bonsai-ninja-sdk = "0.2"
```

The package is `bonsai-ninja-sdk`; its library crate is imported as
`bonsai_sdk`. The SDK re-exports the types and facades CLI consumers need —
no need to depend on lower crates directly (the one exception is
`bonsai_lang_api`, whose `Decl` / `LanguageRegistry` types appear in a few
signatures and are not re-exported).

---

## Quickstart

```rust
use bonsai_sdk::{Bonsai, NativeExportOptions, TaintAnalysisOptions};

fn main() -> anyhow::Result<()> {
    let project = Bonsai::new()
        .with_rulepack("./security-patterns")?
        .index("./my-app")?;

    let report = project.security().taint_analysis(TaintAnalysisOptions::default())?;
    for finding in report.findings {
        println!("{}: {} → {} ({})",
                 finding.finding_id,
                 finding.source.rule_id,
                 finding.sink.rule_id,
                 finding.status.as_str());
    }

    let summary = project.browse().symbol_summaries(Some("os.system"), false)?;

    let exported = project.export().native_json(NativeExportOptions::default())?;

    Ok(())
}
```

Long-lived `Project` handles refresh from disk before command facades run.
Saved file changes update the live workspace in place; new or deleted
files invalidate the affected cache state and rewrite the dataflow
sidecar when needed. Reduced-open projects from literal, path, or
include/exclude filters keep auto-refresh disabled by default so later
facade calls do not broaden the declared scope.

Git-backed refreshes observe clean committed changes as well as dirty files.
Changes to HEAD, the index, or ignore controls trigger full reconciliation;
submodules and index flags that hide edits (`assume-unchanged` or
`skip-worktree`) disable dirty-list acceleration. A selected workspace ignored
by an enclosing Git repository also requires filesystem reconciliation:
an empty Git status cannot prove that its files are unchanged. This applies to
manifest validation and live refresh, including new, renamed, or deleted files.
Read-only Git checks do not
rewrite index metadata. Manifest validation applies the same hidden-index
guard. The fallback changes scheduling only, not source scope.

`read_file` prefers an exact workspace-relative path and rejects ambiguous
suffixes. Related bodies are selected by their source location as well as
name, so same-named methods do not substitute for each other. Line ranges are
one-based and ascending. Cross-file tree links carry actual call-site locations
and canonical edge IDs.

Navigation retains scan-level incompleteness even when no findings are shown.
Tree directory locators are workspace-relative (`.` for the root). Intentional
severity filtering is counted separately from presentation truncation, and a
finding without a real route ID does not produce a fabricated flow summary.

## API surface

### `Bonsai` — configuration builder

```rust
let bonsai = Bonsai::new()
    .with_registry(Arc::new(LanguageRegistry::all()))
    .with_parse_timeout(Duration::from_secs(30))
    .with_rulepack("/path/to/security-patterns")?;
```

| Method | Effect |
|---|---|
| `Bonsai::new()` | Default configuration with all 20 adapters bundled |
| `.with_registry(registry)` | Custom adapter registry |
| `.with_parse_timeout(d)` | Override per-file parse timeout |
| `.with_rulepack(path)` | Load a rulepack from disk |
| `.with_loaded_rulepack(path, pack)` | Inject a pre-loaded `Rulepack` (saves a re-parse) |
| `.with_minified_sources(bool)` | Admit adapter-classified minified JavaScript/TypeScript (CLI `--minified-js`); excluded by default |
| `.with_persistent_semantic_cache(bool)` | Disable reusable persistent sidecars for a cold run (CLI `--no-cache`) |
| `.index(root)` | Parse/index syntax and construct facts without warming persisted semantic sidecars |
| `.index_with_progress(root, callback)` | Same with `WorkspaceOpenEvent` callbacks |
| `.index_structural(root)` | Explicit spelling for `.index(root)` |
| `.index_structural_with_progress(root, callback)` | Same with `WorkspaceOpenEvent` callbacks |
| `.index_semantic(root)` | Explicitly prebuild immutable compiler objects, resolved callgraph, retrieval factstore, compiler linkage, and streamed workspace IDG |
| `.index_semantic_with_progress(root, callback)` | Same with `WorkspaceOpenEvent` callbacks |
| `.open_query(root)` | Ingest the workspace with `OpenOptions::lazy_query()`; each semantic sidecar is hydrated on first use |
| `.open_query_matching_literal(root, literal)` / `..._with_progress(root, literal, cb)` | Open only files whose text contains a literal (the progress form emits ingest/parse events) |
| `.open_query_matching_any_literal_with_progress(root, literals, cb)` | Same for the union of several literals |
| `.open_query_filtered_paths(root, includes, excludes)` / `..._with_progress(root, includes, excludes, cb)` | Open an explicit include/exclude path scope |
| `.open_query_matching_path(root, path)` / `..._with_progress(root, path, cb)` | Open one supported source file |
| `.open_query_retrieval_candidates_with_progress(root, query, filters, cb)` / `.open_query_retrieval_candidate_union_with_progress(root, queries, filters, cb)` | Open the retrieval-candidate file scope for one or several search queries; `Ok(None)` when no fresh retrieval sidecar answers the query |
| `.retrieval_candidate_file_filters(root, query, filters)` | Validate a warmed retrieval sidecar and return workspace-relative candidate files for canonical search/browse/inspect hydration |
| `.retrieval_hydration_include_filters(root, query, filters)` | Return retrieval candidate include filters safe for `open_query_filtered_paths`, including the no-candidate case |
| `.retrieval_search_candidate_file_filters(root, query, filters)` | Compatibility spelling for search integrations; delegates to `.retrieval_candidate_file_filters(...)` |
| `.retrieval_search_hydration_include_filters(root, query, filters)` | Compatibility spelling for search integrations; delegates to `.retrieval_hydration_include_filters(...)` |
| `.open_with_options(root, opts)` | Explicit sidecar / prewarm control |
| `.open_with_options_and_progress(root, opts, cb)` | Same plus progress callbacks |
| `.cache(root)` | Rootless `WorkspaceCache` handle (stats, clear, legacy in-tree cleanup, manifest, default export cache) |
| `.callgraph_summary_from_cache(root)` | `dump-callgraph` rows straight from a fresh callgraph sidecar without opening the workspace; `Ok(None)` when it is missing or stale |
| `.rebuild_structural_cache(root, warm_export)` | SDK equivalent of `bonsai-ninja cache rebuild`: refresh compiler-object/callgraph/linkage/IDG/retrieval sidecars and optionally the default export cache |
| `.security_pack()` | Direct rulepack access |
| `Bonsai::discover_rulepack_root(ws)` / `Bonsai::default_rulepack_root(ws)` | Resolve the rulepack root the CLI would load (`BONSAI_RULES_DIR` override or the default pack); the `Result` form keeps invalid-override errors |

### `Project` — analysis facade

```rust
let project = bonsai.index("./my-app")?;

let refresh = project.refresh_from_disk()?;
let security_report = project.security().taint_analysis(Default::default())?;
let summaries = project.browse().symbol_summaries(Some("handle_request"), false)?;
let trace = project.trace().from("main")?;
let source_flows = project.security().source_analysis(Default::default())?;
let sink_flows = project.security().sink_analysis(Default::default())?;
let exported = project.export().native_json(Default::default())?;
let edge = project.show().by_id("E:0123abcd", Default::default())?;
```

Security analysis also has phase-aware progress entry points. The callback
receives both progress-bar events and structured `AnalysisProgress::Note`
records for scan scope, source/sink counts, taint-graph cache hit/miss
state, and write-through sidecar finish status. The CLI renders those notes
on stderr; SDK callers can route the same stream into logs or embedding UI.
Taint-graph write-through is enabled by default so a second process can
hydrate exact graphs from config-specific
mode/config-specific `taint_graph.v*.<mode>.<config>.factstore` files in the
external workspace cache; set
`BONSAI_TAINT_GRAPH_PERSIST=0` only for disk-constrained runs.

### Workspace open events

```rust
use bonsai_sdk::WorkspaceOpenEvent;

let project = Bonsai::new()
    .with_rulepack("./patterns")?
    .index_with_progress("./my-app", |event| match event {
        WorkspaceOpenEvent::IngestStarted => println!("Walking filesystem…"),
        WorkspaceOpenEvent::IngestFilesStarted { files } => {
            println!("Reading {files} source files…");
        },
        WorkspaceOpenEvent::IngestFileRead => print!("."),
        WorkspaceOpenEvent::IngestFinished { files } => println!("{} files", files),
        WorkspaceOpenEvent::ParseStarted { files } => println!("Parsing {} files…", files),
        WorkspaceOpenEvent::ParseFileIndexed => print!("."),
        WorkspaceOpenEvent::ParseFinished => println!("done"),
        WorkspaceOpenEvent::DataflowPrewarmStarted { pending } => {
            println!("Prewarming {} dataflow entries…", pending);
        },
        WorkspaceOpenEvent::DataflowEntryBuilt => print!("."),
        WorkspaceOpenEvent::DataflowPrewarmFinished => println!("done"),
        WorkspaceOpenEvent::ValueFlowPrewarmStarted => {
            println!("Prewarming value-flow cache…");
        },
        WorkspaceOpenEvent::ValueFlowPrewarmFinished => println!("done"),
        WorkspaceOpenEvent::FlowIdsPrewarmStarted => {
            println!("Prewarming flow ids…");
        },
        WorkspaceOpenEvent::FlowIdsPrewarmFinished => println!("done"),
        WorkspaceOpenEvent::CacheChecked { cache, status, entries } => {
            println!("{cache}: {status:?} ({entries} entries)");
        },
    })?;
```

The `*_with_progress` reduced-open helpers emit the same ingest/parse
events for their narrowed file set. `IngestFilesStarted` is the exact read
worklist after metadata/path filtering; literal queries count every source
candidate that must be read even when fewer files survive the literal test.
Each successful read emits one `IngestFileRead`. Path-filtered query opens may emit
only ingest events when the selected options deliberately defer
declaration indexing. Reduced-open projects keep that narrowed file set
stable unless a caller explicitly re-enables auto-refresh. Query and
prewarm opens also emit `CacheChecked`
events for reusable sidecars such as the dataflow factstore, older dataflow,
callgraph, value-flow, and flow-ids, so embedding tools can explain warm
and cold opens without CLI-only logic.
`ValueFlowPrewarmStarted` / `ValueFlowPrewarmFinished` are emitted only when
an embedding caller explicitly sets `prewarm_value_flow=true`; canonical
`full_prewarm()` builds the shared IDG and leaves the per-function
`ValueFlowGraph` compatibility projection on demand.

Cold semantic sidecar APIs also expose native progress streams:
`warm_retrieval_sidecar_with_progress` reports exact compiler files before
candidate persistence, `warm_compiler_linkage_sidecar_with_progress` reports
exact compiler files before linkage persistence, and
`warm_idg_sidecar_and_manifest_with_progress` reports exact transfer segments
plus accelerator, persistence, and manifest phase boundaries. Storage-only
phases intentionally carry no synthetic percentage.

Native export's `write_native_json_with_progress` reports exact
`StructuralFiles` and `Files` counts. Compact callgraph, structural-flow, and
taint-graph relations report indeterminate phase boundaries because counting
them first would materialize or traverse the stream twice.

## Analysis surfaces

### Security

```rust
let pack = bonsai.security_pack()?;

let report = project.security().taint_analysis(Default::default())?;
let source_report = project.security().source_analysis(Default::default())?;
let sink_report = project.security().sink_analysis(Default::default())?;
let sources = project.security().sources(Default::default())?;
let sinks = project.security().sinks(Default::default())?;
let sanitizers = project.security().sanitizers(Default::default())?;
let deps = project.security().deps(Default::default())?;

let inventory = pack.inventory(Default::default())?;
let audit = pack.audit(None)?;
let validation = pack.validate(Default::default())?;
```

`deps` is the SDK twin of `security deps`;
`dependency_analysis(DependencyAnalysisOptions)` is the twin of
`security dependency-analysis` and returns each package's bound names, use
sites, and the taint findings that reach it. `taint_analysis`,
`source_analysis`, `sink_analysis`, `sources`, `sinks`, and `sanitizers` all
have `*_with_progress` forms, and the three analyses also have
`*_with_phase_progress` forms.

### Inspect and symbol evidence

```rust
let decls = project.inspect().matching_decls(Some("os.system"), false)?;
let summaries = project.browse().symbol_summaries(Some("os.system"), false)?;
```

`symbol_summaries` returns one bounded compiler packet per matching callable:
declaration/source, signature, imports, direct resolved callers and callees,
and unresolved workspace calls. It never recursively enumerates call paths.

### Trace

Step traces are an SDK-only surface; the CLI has no `trace` command.

```rust
let trace = project.trace().from("main")?;
let route = project.trace().source_to_sink("handle_request", "os.system")?;
let json = project.trace().to_json(&trace)?;
let text = project.trace().to_text(&trace);
let dot = project.trace().to_dot(&trace);
```

### Browse

```rust
let defs = project.browse().defs(Default::default())?;
let calls = project.browse().calls(Default::default())?;
let imports = project.browse().imports(Default::default())?;
let refs = project.browse().refs("symbol", Default::default())?;
let strings = project.browse().strings(Default::default())?;
let operations = project.browse().operations(bonsai_sdk::OperationsFilters {
    kind: Some("write"),
    name: Some("token"),
    ..Default::default()
})?;
let classes = project.browse().classes(Default::default())?;
let summaries = project.browse().symbol_summaries(Some("handle_request"), false)?;
let paths = project.browse().paths(bonsai_sdk::PathFilters {
    from: "handle_request",
    to: "run_admin_command",
    ..Default::default()
})?;
let slice = project.browse().slices(bonsai_sdk::SliceFilters {
    symbol: "result",
    line: 15,
    file: Some("gateway.py"),
    ..Default::default()
});
let tree = project.browse().tree(bonsai_sdk::TreeFilters {
    max_finding_ids_per_file: Some(0),
    max_flow_ids_per_file: Some(0),
    max_cross_file_edges_per_file: Some(0),
    ..Default::default()
})?;
let file = project.browse().read_file(bonsai_sdk::ReadFileFilters {
    path: "auth/verify_token.py",
    max_inlined_bodies: Some(0),
    ..Default::default()
})?;
```

Most functions take a workspace + filter struct and return a `Vec<*Out>` of
stable-shaped browse results. `operations` returns shared
syntax-derived use-site facts from `FlowEvent` trees, so SDK consumers see
the same reads, writes, calls, lifecycle/resource events, and normalized
place-shape facts as the CLI. Plain-text filters on fact commands such as
`defs`, `entrypoints`, `imports`, `vars`, `strings`, `comments`, `args`,
`operations`, `classes`, `calls`, and `refs` rank exact matches before
prefix matches before broader substring matches, so SDK consumers get the
same pre-pagination relevance ordering as the CLI. `PathOutcome`,
`SliceOutcome`, `TreeOut`, and `ReadFileOut` are connected views; they
carry `analysis_complete` plus `analysis_incomplete_reasons`. `paths` starts
from resolver-backed compiler-proven callgraph edges (retaining `Exact` or
`Narrowed` provenance) and augments them with
warmed IDG cross-call edges when the query open hydrated an IDG sidecar;
`PathOutcome.backends`, `idg_available`, and `idg_semantic_edges` expose that
planner decision. `PathOutcome` contains `representation:
"compressed_callgraph"`, exact `nodes` and `edges`, and their counts; it does
not enumerate route combinations. When a target pattern matches an indexed
call site but no callable declaration, `terminal_calls` identifies the exact
call and location while the graph corridor stops at the enclosing callable.
`paths` backs CLI `inspect-graph --from`/`--to`; `slices` is SDK-only (the
CLI `slice` command was removed). `slices` projects the selected callable's
workspace value-flow/IDG graph on demand, reuses a compatible cached entry when present, merges adapter-emitted syntax-flow detail, and reports `backends` so
SDK callers can distinguish `value-flow` evidence from `flow-events`.
Parameter boundaries, unavailable semantic graphs, ambiguity, or caps are
incomplete instead of guessed.

### Diagnostics

```rust
let diagnostics = project.diagnostics_report();
```

`diagnostics_report()` is the SDK twin of `bonsai-ninja diagnostics`.
It returns parser/adapter diagnostics, workspace languages, and the
capability declarations for adapters that own workspace files. The complete
registry is published by the generated capability matrix rather than repeated
in every project response. The older
`project.diagnostics()` accessor remains the bare diagnostic vector for
callers that only need warnings/errors.

### Show

```rust
let edge = project.show().by_id("E:0123abcd", Default::default())?;
let flow = project.show().by_id("F:0123456789abcdef", Default::default())?;
let group = project.show().by_id("G:0123456789abcdef", Default::default())?;
let ast = project.show().by_id("N:0123abcd", Default::default())?;
let resolved = project.show().by_id(
    "R:0123abcd",
    bonsai_sdk::ShowOptions {
        query: Some("execute"),
        ..Default::default()
    },
)?;
let taint = project.show().by_id(
    "T:0123abcd",
    bonsai_sdk::ShowOptions {
        taint_source: Some("update_user"),
        taint_seeds: &["token", "action"],
        ..Default::default()
    },
)?;
let finding = project.show().by_id("S:0123456789abcdef", Default::default())?;
```

`show()` is the structured SDK counterpart to CLI stable-id drilldowns.
It supports `E:` call-edge ids, `F:` inspect graph-flow ids or security
taint-path flow ids, `G:` inspect graph-flow group ids or security
taint-path group ids, `N:` AST-node
ids, `R:` resolver-candidate ids, structured `T:` dump-taint propagation
ids, and `S:` security finding ids. Structural `F:` and `G:` are
reopened from the same bounded syntax/resolver-derived inspect evidence used by
CLI `show F:` and `show G:`; when an `F:` id is not an inspect flow,
`show()` falls back to security taint-analysis flow lookup, and when a
`G:` id is not an inspect group it falls back to security taint-analysis
group lookup. Security `F:`, `G:`, and `S:` ids require the project to
have a loaded rulepack. Resolver
ids require the original query through
`ShowOptions::query`, matching CLI `show R:... --query`.
Structured `T:` propagation ids require `ShowOptions::taint_source`
because dump-taint propagation ids are source-seeded. Pass
`taint_seeds` and `taint_sink` when the original dump-taint query used those
filters.

### Dump (debugging / IR introspection)

```rust
let hir = project.dump().hir("handle_request");
let cfg = project.dump().cfg("handle_request");
let callgraph = project.dump().callgraph();
let ast = project.dump().ast(Default::default());
let resolve = project.dump().resolve("handle_request", Default::default());
let edges = project.dump().edges(Default::default());
let taint = project.dump().taint(bonsai_sdk::TaintFilters {
    source: "handle_request",
    ..Default::default()
});
```

`edges` returns the same `EdgeRecord` rows as `dump-edges --format json`,
including stable `E:` ids, resolver stage, evidence, and confidence.

`TaintReport` carries `analysis_complete` and
`analysis_incomplete_reasons` alongside the propagation records so SDK
callers do not have to infer completeness from rendered row counts.

### Export

```rust
let json = project.export().native_json(Default::default())?;
let networkx = project.export().networkx_json()?;
let graphml = project.export().graphml()?;
let cypher = project.export().cypher()?;
```

Native JSON schema v14 emits workspace-relative code locations, typed
loop-control targets, one top-level absolute `workspace_root`, and the code
itself: `files[].source` is the full file text that every span indexes into,
`decls[]` carry `start` / `end` byte spans, `callgraph[]` edges and taint
propagation records carry `call_text`, and `taint_graph.functions[]` carry
`end_line`. `write_native_json(options, &mut writer)` streams the same
document without materializing it in memory. SDK
consumers should join locations to that root only at
the filesystem boundary; storing or comparing location identities by absolute
host path is unsupported. Explicit export-cache rebuilds validate the schema
version before reuse. The complete machine-readable contract is
[`schemas/bonsai-native-export-v14.schema.json`](../../schemas/bonsai-native-export-v14.schema.json).

## Cache management

```rust
let cache = bonsai.cache("./my-app");
let stats = cache.stats()?;
cache.clear_dataflow_only()?;
cache.clear_all()?;
if cache.legacy_in_tree_dir().is_some() {
    // Some((parent, reclaimed_bytes)); rules and unknown files stay in place.
    let removed = cache.clear_legacy_in_tree()?;
}

let stats = bonsai.rebuild_structural_cache("./my-app", false)?;

let project = bonsai.open_query("./my-app")?;
let stats = project.cache().rebuild_structural()?;
let stats = project.cache().rebuild_structural_with_export(true)?;
```

`rebuild_structural_cache` and `Project::cache().rebuild_structural*`
match CLI `cache rebuild`: they refresh the reusable compiler-object,
callgraph, linkage, IDG, and retrieval sidecars and warm the default export
cache only when requested.
They do not run the full dataflow prewarm; use
`open_with_options(root, OpenOptions::full_prewarm())` when reusable
dataflow, flow-id, callgraph, and IDG sidecars should be built up front. The
per-entry compatibility value-flow projection remains on demand because
eagerly closing the whole IDG once per callable is quadratic-scale work. SDK
full-prewarm opens also refresh compiler-object/callgraph/linkage/IDG/retrieval coverage
and publish the external workspace-cache `manifest.json`, so subsequent cache stats can validate
every produced sidecar instead of treating them as orphaned files.
Security `taint_analysis*`, `source_analysis*`, and `sink_analysis*` facades refresh the same
manifest after their exact source-seeded taint graph write-through finishes,
so the current external-cache `taint_graph.v*.<mode>.<config>.factstore` shows as
validated reusable state on the next `cache.stats()` call. Each analysis
configuration uses a distinct config-qualified file and does not overwrite
another mode's warm facts.
Projects opened through filtered/literal/path-scoped query APIs are exact for
that scoped command, but they are not complete workspace indexes; their
security analyses keep taint graph reuse in memory and intentionally skip the
shared taint graph sidecar and manifest refresh.
Path-scoped opens retain the selected source's stable full-workspace `FileId`
when a compiler-object generation names that path. The selected payload still
must match adapter, path, content hash, and SHA-256 digest; a miss recompiles
that file through its Tree-sitter adapter without admitting stale facts.
`cache.stats()?.validation` reports manifest freshness, semantic/dataflow/
taint/export readiness, per-sidecar freshness, and stale reasons. The
validation path checks binary sidecar payloads as well as manifest
fingerprints; raw `*_exists` fields only mean an artifact is present on disk.
`CacheStats.legacy_in_tree_dir` / `legacy_in_tree_bytes` report recognized
legacy analysis files in the inactive `<root>/.bonsai` directory, excluding
current rules and unknown project state. `WorkspaceCache::clear_legacy_in_tree()`
removes only those files and removes the parent only when empty; CLI
`cache clear --legacy` uses the same API. It never follows directory links or
touches the active external cache.
`clear_all()` validates the native workspace binding and refuses workspace
roots, ancestors, directory links, or unrecognized top-level entries before
removing anything. `clear_dataflow_only()` also validates ownership.
The shared orphan sweep prefers the native binding and accepts a complete
legacy manifest only when no binding exists. It deletes only confirmed missing
workspaces; unreadable, corrupt, live, and unattributed entries remain intact.
`bonsai_workspace::workspace_cache_root_binding()` exposes the same read-only,
native-path identity decoder without creating or repairing artifacts.
Root-only `WorkspaceCache::write_manifest()` publishes the locked native
binding before its manifest; no source-backed `Project` is required.
`bonsai_workspace::register_workspace_cache_root()` supplies the same binding
publisher for direct sidecar writers. Stats and binding inspection remain
read-only; cleanup never fabricates ownership to authorize deletion.
Default export-cache reads capture payload and metadata from the same locked
generation, then validate and stream that immutable snapshot. Concurrent
publication returns a cache miss without blocking; an interrupted replacement
cannot leave valid metadata attached to unrelated report bytes.
Retrieval uses the candidate-only evidence contract described in
[Architecture](architecture.mdx#query-browse-trace). CLI and SDK query paths
can validate warmed
retrieval sidecars from source/dependency/schema fingerprints before selecting
candidate files for search and literal-filtered browse hydration; inspect uses
that path only as a pre-open large-workspace scope and does not treat retrieval
as a post-open truth filter. Cache stats applies the same retrieval pipeline
check, so a candidate index copied from another workspace path is stale until
rebuilt. Rendered facts still come from canonical workspace APIs.

## Direct workspace access

For lower-level operations, `project.workspace()` returns a `&Workspace`:

```rust
let ws = project.workspace();
let global = ws.compiler_linkage_index();
let cfg = ws.db().cfg(func_id);
let resolved = ws.cached_resolved_call_graph(); // singleton Arc; share across queries
```

Prefer the compiler linkage/header indexes for workspace-wide symbol work.
Do not call `AnalyzerDb::global_index()` while an IDG query service is open:
that reconstructs complete bodies beside the graph. IDG consumers should
reuse `IdgQueryService::global_linkage_index()`.

The workspace exposes accessors for the precomputed caches that
power the "index once, query many times" model. Each one is
`parking_lot::RwLock`-backed and safe to share across rayon worker
threads:

```rust
let dataflow = ws.dataflow();             // per-FuncId KindedTokens + EntryTaintGraph
let value_flow = ws.value_flow();         // lazy per-FuncId compatibility ValueFlowGraph
let flow_ids = ws.flow_ids();             // per-FuncId browse-row F-IDs
let inter_caches = ws.inter_taint_caches(); // engine resolver memo + alias maps
let resolved = ws.cached_resolved_call_graph(); // Arc<ResolvedCallGraph>
let taint_idx = ws.taint_index();         // (source_func, seed_key) → EntryTaintGraph
let class_idx = ws.class_members();       // (class_sym, method) → FuncId
let enclosing = ws.enclosing_index();     // per-file binary-searchable enclosing-decl
let decl_names = ws.decl_name_index();    // lowercased decl-name table for inspect query
```

`Project::semantic_context()` returns the same normalized workspace
`context` object that `bonsai-ninja index <workspace> --format json` prints: module roots,
dependency/generated/excluded roots, toolchain manifests, configured
source hints, source-transformation evidence, and summary counts.

`OpenOptions` (the SDK re-export of `bonsai_workspace::WorkspaceOpenOptions`)
controls which of these get prewarmed:

```rust
use bonsai_sdk::OpenOptions;

OpenOptions::default()      // same as query_only()
OpenOptions::query_only()   // load fresh sidecars, compute requested facts on demand
OpenOptions::lazy_query()   // ingest only; hydrate each semantic sidecar on first use (open_query default)
OpenOptions::parse_only()   // cold parse/index; no sidecar effects (index / diagnostics)
OpenOptions::full_prewarm() // dataflow/flow-id plus canonical callgraph/IDG and manifest
```

The high-level `bonsai-ninja index` and SDK `Bonsai::index(root)` paths use
`OpenOptions::parse_only()` so an index pass stays focused on syntax
and construct facts. Use `bonsai-ninja index <workspace> --semantic` or
`Bonsai::index_semantic(root)` when a workflow deliberately wants structural
semantic sidecars, including retrieval, built up front. Use
`open_with_options(root, OpenOptions::full_prewarm())` only for the
heavier all-entry dataflow/flow-id prewarm. Legacy per-entry value-flow graphs
are projected from the canonical IDG only when a compatibility client asks.
The semantic index path
and SDK full-prewarm path write the external-cache `manifest.json` after the reusable
sidecars are produced; `Project::cache().read_manifest()` returns the same
cache coverage and fingerprint metadata surfaced by CLI
`cache stats --format json`.
`Project::cache().stats()` additionally validates that metadata against the
current workspace before marking sidecars reusable.

The manifest (`CacheManifest`, `schema_version` 8) records
`workspace_source_files[]` as `CacheManifestSourceFile { hash, stamp,
text_digest }`: `hash` is the FNV-1a content hash semantic sidecars are keyed
by, `stamp` the filesystem change identity, and `text_digest` the hex SHA-256
of the source text, present only when the on-disk bytes are the text verbatim
(valid UTF-8). On Unix, a warm query open whose stamps still match interns
each file by that digest and reads its text on first use instead of during
ingest; a manifest with a different schema version, workspace root, or
minified-source profile falls back to the full read.

`Workspace::ingest_dir` clears or invalidates every cache when a
file edit lands, so subsequent queries observe current state.

## Stability

The SDK API is the public contract. Field names in `Finding`, `RuleMatch`,
`TraceResult`, `DefOut`, `CallOut`, etc. remain compatible within a published
release line. Before 1.0, breaking changes require a minor-version bump and a
migration note; after 1.0 they require a major-version bump.

The CLI is a thin renderer over this SDK; both surfaces evolve together.

### Migrating from 0.2 to 0.3

Update all `bonsai-ninja-*` dependencies together to `0.3.1`.

- `browse.strings()` and `browse.comments()` now return
  `LiteralFilterError`: match `Regex` for invalid expressions and
  `UnknownContentLength` when a positive minimum cannot be proven. General
  error propagation with `?` into a boxed/aggregate error still works.
- `StringLiteral`, `Comment`, `StringOut`, and `CommentOut` expose
  `content_len: Option<usize>`. It counts Unicode scalar values in the lexical
  source body, excluding delimiters/prefixes and preserving whitespace,
  escapes, and interpolation. `Some(0)` means empty; `None` means unproven.
  Custom grammar handlers can supply the new `string_content_len` and
  `comment_content_len` hooks; shared analysis never guesses delimiters.
- Exhaustive matches must handle `AstOutcome::FunctionAmbiguous` and
  `ResolveOutcome::FileContextAmbiguous`. Show the supplied candidates and
  request an exact selector; do not choose the first one silently.
- `AstNode.children_omitted` records depth-limited presentation. A complete
  parse can still have omitted display subtrees; consumers should preserve
  that distinction.

CLI scripts should also note that repeatable global `--contains` values
accumulate across command levels. For `strings` and `comments`, these filter
complete row string fields; their `--regex` switch is case-sensitive unless
the expression uses `(?i)`. `export` and operational `cache` commands reject
these view filters. Native export schema 14 and the exact analysis scope are
unchanged. Compiler-object ABI 206 invalidates older derived sidecars normally;
no manual cache deletion is required.

PHP nowdoc inventory rows now retain the complete literal text and span,
including opening/closing tags, and include empty nowdocs. Their `content_len`
and browse category describe the parser-owned body; callers should not trim
the rendered text to reconstruct a semantic value.

`VarOut.source_names` contains the sorted, unique RHS identifiers and call names
from all compiler projections of one exact assignment. `source_name` remains
the comma-separated display form. A `--source` selector keeps the complete
matching write, not only its matching RHS fragment; two writes on one line
remain distinct by byte column. These are syntax facts, not taint propagation
claims about a callee's return value.

### 0.2 migration

`WorkspaceCache::migrate_legacy_compiler_object_sidecar()` remains callable but
returns `Ok(None)`. The historical v11 layout has an incompatible frontend ABI;
use normal `index` / `index_semantic` to rebuild it from adapter-lowered source.

Version 0.2 removes recursive materialization of concrete call-path
combinations from navigation and export:

- The SDK `paths` API (`inspect-graph --from/--to` on the CLI) now returns the
  exact compiler-resolved source-to-target corridor as
  `nodes` plus `edges`, including branches and cycles without path explosion.
- Browse `--flows` is replaced by `--summaries`; reopen an emitted `F:` id with
  `show` for one callable's declaration, body, direct resolved neighbors,
  imports, and unresolved call evidence.
- The SDK no longer exposes recursive inspect-chain helpers or
  `ResolvedChain`. Use `bonsai_browse::paths` for the compressed corridor and
  `bonsai_browse::symbol_summaries` for bounded symbol evidence.
- Native export continues to represent the complete call relation as
  `compressed_callgraph`; no accuracy-affecting path-materialization switch is
  required.
