# Taint engine specification

The bonsai taint engine is a semantic data-flow analyzer that tracks
untrusted data through:

- intra-procedural CFG dataflow within a single function,
- inter-procedural call propagation across functions, and
- cross-file resolution via imports / exports / aliases,
- IDG value-flow edges for production security scans.

This doc covers the engine's contract, the ten concepts it implements, and
the read/write rules that consumers should understand. It's the engineering
reference. For the hands-on rule-authoring view, see [Pattern Guide](../pattern-guide.mdx).

## Contract

The reusable summary engine is exposed as a pure function:

```rust
interprocedural_taint(
    entry_func: FuncId,
    entry_sources: TokenSet,
    config: &InterTaintConfig,
    db: &AnalyzerDb,
) -> InterTaintResult
```

Given a non-empty `entry_sources`, it traces every reachable propagation.
Given an empty `entry_sources`, it produces zero records; the engine never
invents taint. Diagnostic and compatibility consumers can drive it through
`interprocedural_taint_to_completion_with_caches` (in
`crates/taint/src/inter/mod.rs`), which shares an `InterTaintCaches` across
calls and runs to fixpoint within `config.budget`.

Production `security taint-analysis`, `security source-analysis`, and
`dump-taint` use the IDG-backed graph builders in
`crates/taint/src/reachable.rs`. Those builders resolve source seeds to IDG
nodes, apply configured transfer summaries, compute a precision-bounded
closure, and then cut/report only the relevant semantic target or lineage
corridor. This is the deployed source-to-sink path; direct raw-AST taint and
whole-workspace per-source/per-sink traversal are not production evidence
paths.

Rulepack-free inspect taint rows use `Workspace::syntax_flow_graph` from
`crates/workspace/src/flow_query.rs`. That workspace facade is the only
command-facing switch between a warmed IDG target cut and the canonical
cached `EntryTaintGraph`; `inspect` does not build IDG on its hot path.
Both backends use the same adapter-lowered `FlowEvent`s, resolver-backed
call edges, precision ceiling, and taint crate propagation semantics.

Default entry seeds are centralized in `reachable.rs`:

- `default_entry_taint_seed` is used by fact-oriented and diagnostic
  consumers such as `dump-taint`.
- `default_entry_graph_seed` is used when materializing cached syntax-flow
  graphs so downstream filters can query a wider but still syntax-derived
  graph.

Do not duplicate the params/assignment-target/bare-call-argument seed logic
in command crates. Add new event container handling in the shared helper so
inspect, cached dataflow, and dump-taint stay aligned.

The workspace exposes the canonical `InterTaintCaches` singleton via
`Workspace::inter_taint_caches()`. Production and diagnostic drivers borrow
that one instance so resolver answers per `(caller_func, call_span)`, file
alias maps, function summaries, and local bindings accumulate across runs in a
single CLI process. `Workspace::ingest_dir` calls `InterTaintCaches::clear()`
when a file edit lands.

Only the security layer populates `config.source_bearing_functions` —
the set of helpers whose matched source has been proven to reach a return.
A function that reads untrusted data and returns only a status doesn't
qualify. Other consumers drive the engine with their own seeds and an
empty set.

## Ten concepts

Each concept is pinned by a test in
`crates/taint/tests/ten_concept_alignment.rs`.

### 1. Source model

Caller-supplied seeds. `TokenSet` is `AHashSet<String>`. Identifiers can be
bare (`req`) or qualified (`obj.field`). Qualified identifiers track
per-field taint.

```rust
let seed: TokenSet = ["req".into()].into_iter().collect();
let result = interprocedural_taint(entry, &seed, &config, &db);
```

### 2. Sink model

The engine reports unresolved external calls in
`InterTaintResult.tainted_calls`. The security layer decides what's
actually a sink — the engine never filters by name. `TaintedCall.kind`
identifies the record shape. `kind: Call` carries syntactic call-argument
indices. `kind: Write` carries a synthetic operand for the assignment RHS
so the security matcher can enforce `arg_tainted: { index: 0 }` on write
rules. `kind: Return` is return-expression evidence and has no call
argument slots.

### 3. Sanitizer model

`InterTaintConfig.sanitizers: TokenSet` is accepted but doesn't change
propagation semantics. Sanitizer attribution is a security-layer concern;
the engine preserves the semantic taint path and leaves sanitizer status to
the security layer.

### 4. Call graph

Function A → function B edges, resolved via
`bonsai_resolve::resolve_callable_with_context`. Every edge carries a
`Precision` and an `EdgeKind` (Direct / Virtual / Indirect / Unknown).
Callable values pass through `bonsai_common::callable_reference_variants`
so the various forms (`&fn/1`, `fun fn/1`, `\&fn`, string callables, Ruby
method symbols, qualified tails) collapse to the same bare callable.

Adapters lower callback invocation syntax to real `Call` events before
this step. Perl `$cb->($value)` becomes a call named `$cb` with `$value`
as arg 0, so a prior `run_cb(\&executor, t)` binding can dispatch to
`executor(t)` without text fallbacks.

Receiver-callback shorthands (`cb.call`, `cb.run`, `cb.apply`) only
dispatch through local callable bindings when the binding resolves to a
function or method value. Constructed objects with same-named methods go
through receiver-type dispatch instead. Don't add results of
constructor-shaped calls (`repo = Repository.wrap(raw)`) to the callable
binding map.

Receiver-type facts are produced from adapter-emitted type aliases,
constructor syntax, and AST-derived `Decl.parent` ownership. The DB/index
path enriches `FlowEvent::Call::receiver_types` before callgraph, taint,
security, inspect, browse, and export consume the facts. The global pass
extends direct receiver types through indexed base classes so every
consumer sees the same `Child` plus `Base` receiver context. Ambiguous
type names fail closed; the engine must not merge unrelated class
hierarchies by bare name.

When the receiver is `self.<field>` / `this.<field>`, the resolver
also consults the enclosing class's constructor `receiver_field_writes`
and reads the source-parameter type from the constructor's
`type_aliases`. `def __init__(self, runner: CommandRunner): self.runner
= runner` makes every other method's `self.runner.X(...)` call
dispatch through `CommandRunner.X` — without the engine having to
re-walk `__init__`'s body at every receiver call.

### 5. Data-flow graph

Per-function `FlowEvent::Assign` events carry `target`, `source_name`,
`source_call`, `source_call_args`, and `source_names` so taint flows
through compound RHS without re-parsing. `source_names` preserves
qualified RHS reads (`obj.field`, `obj['field']`, `obj->field`) as
value-bearing operands, including grammars that split selectors into
multiple nodes.

Value-preserving call results are explicit rulepack models, not text
fallbacks or engine API tables. When a sanitizer/passthrough rule declares
`taint_semantics.call_result_passthrough_args` or
`call_result_passthrough_receiver`, string/list transforms such as
`upper`, `toUpperCase`, `strings.ToUpper`, `TrimSpace`, and
formatting/join helpers bridge their configured input operands to the
assignment result. Go `append` bridges each appended operand to the
returned slice while the container-mutator rule below separately models
receiver descendant state.

Constructor / object-initializer assignments with named fields are
field-sensitive. `env = Envelope({cmd: raw, kind: K})` seeds `env.cmd` from
`raw` without tainting bare `env` or `env.kind`. Positional constructors
fall back to descendant-container taint only when a type-like call
actually receives tainted data.

Indexed buffer bookkeeping does not overwrite the whole container. Adapter
shapes like `buf[sizeof(buf) - 1] = '\0'` may emit both precise indexed
writes and structural base tokens; the IDG drops the `sizeof` metadata and
same-span base self-write so the terminator assignment cannot erase the
tainted buffer value.

### 6. Module resolver

`bonsai_resolve::alias_map_for_file` builds `{local_name → AliasTarget}`
from `ImportSpec` entries. The engine consults the alias map at every call
site to translate local names to global decls.

### 7. Context sensitivity

Same function, different seeds → distinct results. The engine memoises by
`FunctionSeed { func, seed }` (sorted) so each `(func, seed)` pair has its
own analysis. Recursion is bounded by this memoisation.

### 8. Field sensitivity

`obj.value = tainted` writes `obj.value` into state, not bare `obj`. Reads
of `obj.other` don't match. The carrier-arg case (`process(obj)` with
state `{obj.value}`) still propagates via
`state_qualified_token_matches_text`. A bare tainted lifecycle carrier
(`helper(obj)`) doesn't taint independent fields or locals derived only
from those fields.

### 9. Path sensitivity

Branches don't dilute clean paths. `Branch` handling clones state per arm,
walks both, and unions post-states. Clean reassignment in both branches
clears prior taint at the merge.

The adapter contract requires both arms to be present. The kit's
`branch_repair` recovers the partition for grammars that lump both arms
together. That repair runs before taint analysis, so inspect, trace,
export, and security all see the same branch shape.

**Pattern arms.** Languages where `match`/`switch` parses as a flat
`Branch` with arms concatenated into `then_events` (Scala, Swift, Rust)
get peeled by `split_match_arms_in_branch_events`. Each arm becomes its
own nested `Branch::then_events`.

**Typed catch arms.** `Try` events carry `catch_types` populated by
adapter post-processes. The engine seeds the catch param only when at
least one body throw is type-assignable:

- Empty `catch_types` (catch-all) → conservative seed.
- Catch type is a known absolute root (`Exception`, `Throwable`, `Error`,
  `System.Exception`, `Object`) → conservative seed.
- Otherwise → exact-name match between `Throw::thrown_type` and
  `catch_types`. Compound throws fall back to conservative.
- `RuntimeException` is intentionally NOT a root — it doesn't catch
  checked exceptions.

**Detached futures.** Rust `tokio::spawn` / `std::thread::spawn` bodies
are wrapped in `FlowEvent::Defer` by the adapter. The engine's Defer
handler observes the body's effects (so dangerous spawned sinks still
surface) but doesn't propagate spawn taint into the caller's
post-spawn continuation.

### 10. Summary generation

`FunctionSummary` records positional taint effects:

- `returns_taint_of`: parameter indices whose value taint reaches the
  return.
- `returns_descendant_taint_of`: indices whose explicit descendant taint
  reaches the return.
- `returns_container_taint_of`: indices whose direct value gets embedded
  into a returned container, so the caller's assignment target carries
  descendant taint.
- `returns_field_taint_of`: exact returned-container fields whose values
  come from a parameter. `return {"user": user}` taints `result.user`,
  not `result.*`.
- `returns_element_taint_of`: exact returned tuple/list positions whose
  values come from a parameter. `return {"ok", p}` / `return (clean, p)`
  taints only the second destructured binding in `{a, b} = helper(p)` or
  `(a, b) = helper(p)`.
- `taints_params_from`: parameter-to-parameter side effects (e.g.
  `join(dst, ..., src)` writes `src` into `dst`).

Caller's `apply_return_taint` consults the summary when processing
`var = callee(args)`. Adapters set `Decl.has_implicit_returns` only for
language or body forms where a final expression really returns a value
(Rust/Ruby tail expressions, expression-bodied lambdas/functions). The
summary pass only uses terminal-tail evidence when that adapter fact is
present; ordinary terminal assignments are not treated as returns.

When an adapter emits `Assign.source_call` without `source_call_args` but
also emits the sibling `FlowEvent::Call`, the inter walker borrows the
call's arg list. That's semantic correlation between two adapter facts,
not a text fallback — return-summary checks still use positional
arguments.

Container summaries are intentionally split. Whole-container taint is a
fallback for dynamic aggregate returns. Named-field returns and positional
tuple/list returns are applied only when the caller assignment exposes the
matching field or destructuring index; they must not scalar-taint sibling
fields or sibling bindings.

## Workspace-level result caches

The engine's per-call results are cached at the workspace layer so a
second query of the same shape against the same workspace becomes a
lookup instead of a fresh propagation pass.

- **`DataFlowCache`** (`crates/workspace/src/dataflow.rs`) — per-`FuncId`
  `KindedTokens` + `EntryTaintGraph`. Loaded from a valid persisted
  sidecar when present, computed on demand for exact query scopes, and
  fully rebuilt only by explicit prewarm paths such as
  `index --prewarm-dataflow`; persisted to
  `.bonsai/dataflow.v3.factstore` (legacy `dataflow.v2.bin` is still
  readable for warm reopens). The cache carries each entry's transitive
  dependency file set, so an edit to any callee invalidates only the
  affected entries.
- **`ValueFlowCache`** (`crates/workspace/src/value_flow.rs`) — per-`FuncId`
  seed-free `ValueFlowGraph`. Built for the requested scope and cached
  for reuse. Each entry also ships a
  `returning_seed_names: AHashSet<String>` precomputed at graph-build
  time — the set of param/assign-target names whose forward closure
  reaches a `Return` node in the same function. Security-analysis
  answers "does this seed reach a return?" with a single hash-set
  intersection. Persisted to
  `.bonsai/value_flow.v3.factstore`.
- **`TaintGraphIndex`** (`crates/workspace/src/taint_index.rs`) —
  `(source_func, sorted_seed_key) → Arc<EntryTaintGraph>`. Lifted
  out of the per-invocation map in `build_findings_chain_aware` so
  a second `taint-analysis` against the same workspace + rulepack
  reuses the cached graph. Persisted to
  `.bonsai/taint_graph.v2.factstore` with version + config-fingerprint
  guard; mismatched fingerprints invalidate.
- **`TransitiveCallersIndex`** (`crates/workspace/src/transitive_callers.rs`) —
  depth-bounded transitive caller closures on the resolved call
  graph. The closure is rulepack-independent; security-analysis
  consults it to schedule caller-frontier expansion for
  source-returning helpers without re-running BFS per invocation.
- **`Workspace::cached_resolved_call_graph()`** — singleton
  `Arc<ResolvedCallGraph>` shared across `inspect`, `security`,
  `dump callgraph`, the `DataFlowCache`, and the `FlowIdCache`. The
  data caches receive it via `seed_call_graph(arc)` when a query or
  explicit prewarm path has built it so they don't rebuild identical
  content.

All caches are `parking_lot::RwLock`-backed and safe to share
across rayon worker threads. `Workspace::ingest_dir` clears or
invalidates each one when a file edit lands.

## Resolver semantics and precision

`resolve_callable_with_context` (`crates/resolve/src/lib.rs:124`)
is the single semantic entry point. It applies, in order:

1. `Visibility::Private` filter — keep only same-file decls.
2. `Visibility::Module` / `Visibility::Crate` — module-path /
   top-segment match against the caller's `ModulePath`.
3. Receiver-type narrowing when `ctx.receiver_type` is `Some` —
   `Decl.parent` must be the receiver type or in its base chain.

Unqualified same-directory top-level fallbacks are enabled only for
languages whose adapters model files as a shared package/module namespace
or translation unit link surface (`.c`, `.h`, `.cc`, `.cpp`, `.cxx`,
`.hpp`, `.hh`, `.hxx`, `.kt`, `.kts`, `.swift`, `.pl`, `.pm`). The caller
must provide the workspace file-path lookup in `ResolveContext`; otherwise
the fallback is unavailable. File-scoped module languages such as Python
must import or alias the symbol, so the resolver fails closed instead of
fabricating a cross-file edge.

The engine's `resolve_call_candidates_with_caller_at` builds the
`ResolveContext` from each call site's `(caller_func, call_span)`,
threads it into the resolver, and memoises the answer in
`InterTaintCaches::resolved_calls_by_site`. When the answer is a
single candidate, the edge is `EdgeKind::Direct` /
`Precision::Narrowed`. Multiple candidates are emitted only when adapter
facts semantically explain the set, such as typed virtual dispatch over a
known receiver family or a same-scope overload family. Overload families are
then narrowed by declared argument/parameter type facts when available, so a
known `String` actual does not propagate into an `Int` overload. The remaining
multi-candidate edges are `EdgeKind::Virtual` /
`Precision::Narrowed`. Contextless or unexplained multi-candidate sets are
not public evidence and must be surfaced as incompleteness/debug metadata,
not widened into `Precision::OverApproximate` findings. There is no
"used-tail-fallback widens single candidates to OverApproximate"
exception — `ResolveContext` filtering already narrowed the result.

Receiver-type-unknown calls produce no semantic call target. Debug-only
helpers may explain why a name looked dynamic, but public review/security
flows must wait for receiver-type, alias, module, or model facts before
emitting an edge.

Closure-factory calls are resolved only when the factory's body returns a
single lambda/function literal in the same file. The callgraph binds the
assignment target to that returned callable; ambiguous or multi-return
factories stay unresolved rather than tainting every later indirect call.

## Engine layers

The taint crate is layered:

- **Layer 1 — name reachability** (`reachable.rs`): pure structural
  traversal grouped by `FactKind`. No data flow.
- **Layer 2 — assign chain** (`assignment.rs`): monotonic identifier
  propagation through `Assign` events. Used internally by summary
  construction and as a fast-path scan.
- **Layer 3 — intraprocedural** (`intra.rs`): forward dataflow over the
  CFG with per-block in/out state. Worklist iterates to fixpoint with a
  safety cap (CFG size × 8, min 16). Reports `saturated` on cap.
- **Layer 4 — interprocedural** (`inter/mod.rs`): worklist-driven
  fixpoint over `(func, seed, dyn_bindings)` items. Memoised by
  `FunctionSeed`.

`InterTaintConfig` covers the knobs:

- `sanitizers: TokenSet` — informational only.
- `budget: u32` — `(func, seed)` worklist chunk size (default 512);
  to-completion drivers resume chunks until the semantic worklist
  drains.
- `intra_worklist_cap: Option<u32>` — per-function safety cap.
- `source_bearing_functions: AHashSet<FuncId>` — security-layer source
  helpers.
- `clean_output_overwrites: Vec<CleanOutputOverwrite>` — declarative
  overwrite shapes derived from rulepack `taint_semantics`.
- `source_output_args: Vec<SourceOutputArgs>` — source calls whose
  listed output arguments receive taint, such as `recv`, `SSL_read`,
  and `fgets` buffers. These are derived from source rules, not from a
  built-in API list.
- `call_result_passthroughs: Vec<CallResultPassthrough>` — rulepack
  declarations that selected call arguments or the method receiver flow
  to the call result, such as URL decode/unescape helpers. The engine
  owns the transfer primitive, not a hardcoded API list.
- `output_arg_flows: Vec<OutputArgFlow>` — rulepack declarations that
  selected value arguments flow into an output argument. This covers
  formatter/copy-style APIs without putting library names or argument
  orders in the engine.
- `callback_invocation_methods: AHashSet<String>` — method tails that
  invoke callable receivers.
- `receiver_state_propagations: Vec<ReceiverStatePropagation>` —
  rulepack-declared receiver/method shapes that move argument taint into
  receiver state for later receiver-only sinks. The engine owns no global
  mutator-name list.

`InterTaintResult` returns:

- `per_function: AHashMap<FunctionSeed, IntraTaintResult>` — per-pair
  caches.
- `call_records: Vec<CallPropagation>` — every cross-function flow.
- `tainted_calls: Vec<TaintedCall>` — every call/write/return whose
  operands carry tainted values.
- `precision: Precision` — worst seen along any traversed edge.
- `pairs_analyzed: u32`, `saturated: bool`, `continuation:
  Option<InterTaintContinuation>` — for resumable chunked runs.

## Read-side semantic checks

The engine has two read-side functions with different strictness.

**`arg_text_is_tainted(text, state) -> bool`** — the relaxed check used
at call-arg / sink-arg sites:

1. Empty trimmed text → false.
2. Interpolation match (`$x` / `${x}` against state) — runs before the
   quoted-literal short-circuit so `"... $x ..."` propagates.
3. Whole-string quoted literal → false.
4. Strip value-free operands (`sizeof(x)`, `alignof(T)`, `typeof(x)`,
   `nameof(x)`).
5. Direct match against state.
6. Sigil-stripped match (`$x` ↔ `x`, `@arr` ↔ `arr`).
7. Normalised qualified form (`obj['k']` ↔ `obj.k`).
8. Qualified-text branch: exact qualified seed prefix-or-equal.
9. Unqualified-text branch: bare read of any qualified seed sharing the
   base.
10. Identifier-tokens-outside-strings fallback (quote-aware), with
    qualified-access bases filtered when the same token has no standalone
    value occurrence.

**`rhs_operand_is_tainted(text, state) -> bool`** — the strict check used
at assignment-RHS and call-argument `source_names`. Same as the relaxed
form minus steps 8 and 9 (no bare-name promotion, no token-walk
fallback). This is what keeps `out = data['other']` from inheriting
`data.value`'s taint.

Interpolated string taint is adapter-derived. The parser surfaces real
interpolation expression children as `source_names`; the taint engine
does not parse `$x`, `${x}`, `#{x}`, or f-string syntax out of raw text.

## Branch conditions and constant facts

`FlowEvent::Branch` optionally carries a `condition` text. The engine
recognises a small set of language-neutral patterns (literal booleans,
`flag`, `!flag`, `flag == 0`) so guarded code doesn't generate spurious
flows. The list grows conservatively — a constant fact must be
language-neutral and trivially safe to reason about.

Tainted conditions are not dataflow. A tainted branch guard may choose
which clean/dynamic container is returned, but it does not make every
field in that returned container tainted. Returned containers are tainted
only by explicit data movement into the returned value or one of its
tracked fields or positional elements.

## Append-style mutators and lifecycle calls

Append-style container mutators (`push`, `append`, `add`, `addAll`, queue
enqueue forms) propagate tainted arguments into the receiver's descendant
state (`items.*`), not into the receiver scalar value. This models
array/list contents without treating unrelated lifecycle fields as
tainted.

Carrier passing where a specific field is tainted (`client.argv`,
`env.cmd`) gives the callee matching field state (`param.argv`,
`param.cmd`). The carrier parameter itself isn't marked as a tainted
scalar unless the caller had explicit value taint — so `free(client)`
doesn't taint every field reachable below `client`.

## Drift gates

Engine semantics are pinned by snapshots under `.snapshots/`:

- `COVERAGE_BASELINE.snapshot` — per-language capability matrix.
- `ADAPTER_CAPABILITIES.snapshot` — adapter-claimed coverage.
- `ADAPTER_FLOW_EVENT_COVERAGE.snapshot` — which `FlowEvent` variants
  each adapter emits.

CI rebuilds these and fails on drift unless the corresponding `.md` file
is updated in the same PR. That keeps the docs honest with the code.
