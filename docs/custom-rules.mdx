# Custom Rules

Workspace-local rules live under `<workspace>/.bonsai/rules/` and use the same layout as the shipped pack.

```text
.bonsai/rules/
└── python/
    └── sinks/
        └── cmdi.yml
```

| Layer | Precedence | Use case |
|---|---:|---|
| Embedded bundle or `--rules-dir` pack | Base | Portable shipped default or an explicitly selected editable/custom base. |
| `<workspace>/.bonsai/rules/<lang>/...` | Overlay | Project-specific sources, sinks, sanitizers, and non-finding typing models (local layout drops the `langs/` wrapper). |
| `<workspace>/.bonsai/rules/<kind>s/*.yml` | Overlay | Small flat local packs (rule must declare `language:`). |
| Duplicate `id` in overlay | Replaces base rule | Disable or tighten a shipped rule for a workspace. |

## Disable A Shipped Rule

This example assumes the overlay also defines the enabled
`mycompany.cmdi.safe_exec_wrapper` replacement. The validator rejects a
`subsumed_by` target that is missing, disabled, or part of a cycle. Use
`over-broad`, `requires-constraint`, or `pending-adapter-fact` when there is
no enabled replacement.

```yaml
- id: python.cmdi.os_system
  enabled: false
  disabled_reason:
    code: subsumed
    subsumed_by: mycompany.cmdi.safe_exec_wrapper
  language: python
  tag: command-injection
  match:
    kind: call
    callee:
      attribute: [os, system]
  description: "Disabled locally; project uses a wrapper rule instead."
```

## Run With A Local Pack

```bash
bonsai-ninja security ./src taint-analysis --rules-dir ./security-patterns
```

Omit `--rules-dir` for the immutable pack compiled into the binary. Passing an
invalid explicit directory is an error; the CLI never silently substitutes the
bundle for a requested custom pack.

<Note>
Rule IDs are stable API. Prefer adding a more specific rule ID over changing the meaning of an existing shipped ID.
</Note>

## Add A Factory Return Type

Use a `typing/` rule when a library factory determines the static type of a
later receiver but source syntax alone does not:

```yaml
- id: mycompany.python.typing_client
  enabled: true
  language: python
  returns_type: Client
  match:
    kind: call
    callee:
      attribute: [mycompany, make_client]
  match_examples:
    - name: client factory
      code: |
        import mycompany
        def example():
            client = mycompany.make_client()
            return client
  description: "mycompany.make_client returns a Client receiver."
```

Typing rules provide resolver evidence only and never produce findings.

For a language whose grammar does not distinguish `Type(...)` from an
ordinary function call, use an exact `kind: new` target on the security rule.
The rulepack then supplies constructor identity without a capitalization
guess. Keep result typing explicit and separate:

```yaml
- id: mycompany.kotlin.typing_widget
  enabled: true
  language: kotlin
  imports: [com.mycompany]
  returns_type: Widget
  match:
    kind: new
    callee:
      attribute: [com, mycompany, Widget]
  match_examples:
    - name: imported widget constructor
      code: |
        import com.mycompany.Widget
        fun example() { val widget = Widget() }
  description: "com.mycompany.Widget constructs a Widget receiver."
```

`kind: new` proves constructor identity; `returns_type` is what allows the
assigned local to satisfy later receiver-type rules. Neither behavior depends
on identifier case. Import/package constraints on the typing rule are part of
the type proof and are enforced before the model can affect a receiver. When a
function-shaped call resolves to a workspace value or ordinary function, that
compiler identity shadows an external `kind: new` model; mixed or ambiguous
workspace candidates fail closed. Match examples should include both the
provider-positive case and a same-spelled local-function negative.

The same boundary applies to `taint_receiver_from_args` rules. When a library
receiver type exists only in typing YAML, bonsai-ninja compiles the complete
rule match to exact AST call spans before constructing the IDG. Import and
shadowing constraints therefore remain effective during propagation, while
the shared taint engine receives no API-name inventory. Add a negative example
for an unimported or locally shadowed same-spelled call whenever the model
could otherwise be ambiguous.

## Add External Callback Parameter Types

Use callback typing when source syntax proves the callback relationship but a
library signature supplies parameter types. Keep the framework call and types
in YAML; language adapters record only the parsed call argument and callback
parameter bindings.

For a callback passed at a known call argument:

```yaml
- id: mycompany.java.typing_route_callback
  enabled: true
  language: java
  imports: [com.mycompany.router]
  callback_arg_index: 1
  callback_param_types:
    - [com.mycompany.router.Request, Request]
  match:
    kind: call
    callee: {name: route}
  match_examples:
    - name: route callback
      code: |
        import static com.mycompany.router.Routes.route;
        class App {
          Object routes(Object predicate) {
            return route(predicate, request -> request.toString());
          }
        }
      expect_match_text: [route]
  description: "The route callback receives the framework Request type."
```

For an explicitly typed functional-interface binding, use typing-only
`match.kind: type` and omit `callback_arg_index`:

```yaml
- id: mycompany.java.typing_fetcher_callback
  enabled: true
  language: java
  imports: [com.mycompany.graph]
  callback_param_types:
    - [com.mycompany.graph.Environment, Environment]
  match:
    kind: type
    target: {name: Fetcher}
  match_examples:
    - name: typed fetcher callback
      code: |
        import com.mycompany.graph.Fetcher;
        class App {
          void configure() {
            Fetcher<Object> fetcher = environment -> environment.toString();
          }
        }
      expect_match_text: [Fetcher]
  description: "Fetcher callbacks receive the framework Environment type."
```

`callback_param_types` follows callback parameter order. Each inner list is
the exact qualified/short alias set for one parameter. The loader rejects
these fields outside `typing/`, rejects missing call argument indices, and
rejects `kind: type` without a callback signature.
