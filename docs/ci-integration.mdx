# CI Integration

Use release binaries or a cached Rust build. In CI, pass `--no-color --no-progress` for clean logs and `--format json` or `--format sarif` for artifacts. Run `index` first when you want structural parse/index validation as a separate CI step; scan commands also open the workspace and compute their exact required scope on demand. Use `index --prewarm-dataflow` only for workflows that intentionally warm the legacy full-workspace dataflow sidecar.

## GitHub Release Artifacts

Repository releases are built from `v*.*.*` tags by `.github/workflows/release.yml`. The workflow builds Linux x64, Linux arm64, macOS Intel, macOS Apple Silicon, Windows x64, and Windows arm64 archives, includes `security-patterns/`, `docs/`, `README.md`, `AGENTS.md`, `SKILLS.md`, and checksum files, then publishes them with `softprops/action-gh-release`.

For source-build target checks outside that release artifact matrix, use
`scripts/check-targets.sh`; see
[Platform And Architecture Support](platform-support.mdx) for the parser
bundle constraints that affect non-mainstream CPU architectures.

```bash
curl -L -o bonsai.tar.gz \
  https://github.com/gromhacks/bonsai-ninja/releases/download/v0.1.0/bonsai-ninja-x86_64-unknown-linux-gnu.tar.gz
curl -L -o bonsai.tar.gz.sha256 \
  https://github.com/gromhacks/bonsai-ninja/releases/download/v0.1.0/bonsai-ninja-x86_64-unknown-linux-gnu.tar.gz.sha256
sha256sum -c bonsai.tar.gz.sha256
tar -xzf bonsai.tar.gz
./bonsai-ninja-x86_64-unknown-linux-gnu/bonsai-ninja --version
```

## GitHub Actions

```yaml
name: bonsai-security

on:
  pull_request:
  push:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - run: cargo build --release -p bonsai_cli --locked
      - run: ./target/release/bonsai-ninja index . --no-color --no-progress
      - run: |
          ./target/release/bonsai-ninja security . taint-analysis \
            --rules-dir security-patterns \
            --format sarif \
            --all \
            --no-color \
            --no-progress \
            --output-path bonsai.sarif.json
      - uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: bonsai.sarif.json
```

<Note>
GitHub SARIF upload requires `security-events: write`. For forked pull requests, upload permissions depend on repository settings.
</Note>

## GitLab CI

```yaml
stages: [security]

bonsai_security:
  image: rust:latest
  stage: security
  script:
    - cargo build --release -p bonsai_cli --locked
    - ./target/release/bonsai-ninja index . --no-color --no-progress
    - |
        ./target/release/bonsai-ninja security . taint-analysis \
          --rules-dir security-patterns \
          --format json \
          --all \
          --no-color \
          --no-progress \
          --output-path bonsai-findings.json
  artifacts:
    when: always
    paths:
      - bonsai-findings.json
```

## CircleCI

```yaml
version: 2.1

jobs:
  bonsai-security:
    docker:
      - image: cimg/rust:stable
    steps:
      - checkout
      - run: cargo build --release -p bonsai_cli --locked
      - run: ./target/release/bonsai-ninja index . --no-color --no-progress
      - run: |
          ./target/release/bonsai-ninja security . taint-analysis \
            --rules-dir security-patterns \
            --format json \
            --all \
            --no-color \
            --no-progress \
            --output-path bonsai-findings.json
      - store_artifacts:
          path: bonsai-findings.json

workflows:
  security:
    jobs:
      - bonsai-security
```

## Exit Codes

| Command outcome | Exit code | Notes |
|---|---:|---|
| Successful scan, findings or no findings | 0 | Findings are report data, not a process failure. |
| Invalid flags, bad regex, missing workspace | Non-zero | Treat as CI failure. |
| Rulepack validation failure | Non-zero | Fix schema, examples, or collisions. |

Use a small wrapper if your policy requires failing builds when findings exist.
