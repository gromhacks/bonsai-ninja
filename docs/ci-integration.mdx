# CI Integration

Use a release binary or a cached release build. For automation, pass
`--no-color --no-progress` and write JSON or SARIF through `--output-path`.
Findings are report data: a successful scan exits zero even when findings are
present. Apply repository policy in a separate step.

## Recommended workflow

For one scan, the security command can open the workspace and compute its
requested exact scope directly:

```bash
./target/release/bonsai-ninja security . taint-analysis \
  --profile production \
  --format sarif \
  --all \
  --output-path bonsai.sarif.json \
  --no-color \
  --no-progress
```

Run `index .` first when you also want an explicit syntax/diagnostic gate.
Use `index . --semantic` only when several broad semantic commands in the same
job will reuse its validated compiler-object and graph sidecars.

Persist the operating-system workspace cache between jobs only when the cache
key includes source revision, lockfiles, the bonsai-ninja version, and the
target platform. Sidecars are accelerators, not authority: the binary validates
their source, adapter, ABI, dependency, and policy identities before reuse.

## Completeness and paging

Semantic analysis has no BFS depth, iteration, file, or result cap.
`--all` removes output paging; it does not change accuracy. If a CI job stores
only a page, it must not claim exhaustive review.

For JSON output, require:

- `analysis_complete: true`;
- an empty `analysis_incomplete_reasons` list;
- every source, sink, and path location to exist under the selected workspace;
- deterministic stable IDs across an unchanged snapshot.

Parser or resolver incompleteness is a valid static-analysis result, not a
successful “no findings” verdict.

## GitHub Actions

```yaml
name: bonsai-security

on:
  pull_request:
  push:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - run: cargo build --release --locked -p bonsai_cli
      - name: Run bonsai-ninja
        run: |
          ./target/release/bonsai-ninja security . taint-analysis \
            --profile production \
            --rules-dir security-patterns \
            --format sarif \
            --all \
            --output-path bonsai.sarif.json \
            --no-color \
            --no-progress
      - uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: bonsai.sarif.json
```

GitHub SARIF upload requires `security-events: write`. Forked pull requests
may not receive that permission; retain the SARIF artifact even when upload is
disabled by repository policy.

## GitLab CI

```yaml
stages: [security]

bonsai_security:
  image: rust:latest
  stage: security
  script:
    - cargo build --release --locked -p bonsai_cli
    - |
        ./target/release/bonsai-ninja security . taint-analysis \
          --profile production \
          --rules-dir security-patterns \
          --format json \
          --all \
          --output-path bonsai-findings.json \
          --no-color \
          --no-progress
  artifacts:
    when: always
    paths:
      - bonsai-findings.json
```

## Failing a job on findings

The CLI distinguishes execution failure from policy failure. A scan with
findings exits zero; malformed configuration, invalid flags, unavailable
workspace input, or rulepack validation failures exit non-zero.

Use the JSON or SARIF artifact to enforce policy after confirming the report is
complete. For example, a wrapper can fail only on new unsanitized critical or
high findings while allowing unchanged baseline findings.

## Repository release checks

This repository's tag workflow is `.github/workflows/release.yml`. It verifies
version/tag provenance, runs cross-platform build and test jobs, executes
documentation and rulepack audits, performs self-analysis, checks packaged
output formats, and runs the pinned large-workspace gate before publishing.

The workflow builds archives for:

- Linux x64 and arm64;
- macOS Intel and Apple Silicon;
- Windows x64 and arm64.

Archives include the self-contained binary, readable `security-patterns/`
source for inspection/customization, the versioned native export JSON Schema,
human documentation,
`CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, `AGENTS.md`,
`SKILLS.md`, the installable agent skill, license information, and checksums.
Each tagged archive and checksum manifest receives a signed GitHub/Sigstore
artifact attestation. A
relocated binary-only smoke uses no adjacent rulepack plus an empty user/parser
cache and an empty workspace cache. This proves native parser delivery and the
embedded rulepack fallback without relying on earlier runner state or the
source checkout.

## Large-workspace regression gate

Changes to compiler objects, adapters, resolver, callgraph, IDG, taint,
security planning, query execution, caching, or export must run:

```bash
cargo build --release --locked -p bonsai_cli
BONSAI_ELASTICSEARCH_ROOT=../elasticsearch \
BONSAI_REQUIRE_ELASTICSEARCH_GATE=1 \
BONSAI_MEMORY_BUDGET_MB=3072 \
  cargo test --release --locked -p bonsai_cli \
  --test elasticsearch_large_repo -- --nocapture
```

The gate checks semantic generation and reuse, lightweight navigation,
inspect, rule inventories, and production taint. It evaluates latency only
after each command completes and verifies completeness, so an SLO cannot hide
truncated semantic work.

The 3 GiB value schedules concurrency and cache retention. It is not a result
budget or a promise that operating-system RSS will equal the configured value.
Do not raise SLOs to make a regression pass. Record the source snapshot, file
count, cold/warm state, wall time, memory, swaps, and completeness, then review
the architecture change. Current measurements live only in
[Release Readiness](RELEASE_READINESS.md).

## Native export changes

The regular large-workspace test does not write the multi-gigabyte native
export on every runner. Changes to export serialization, compiled graph
representation, phase release, or export caching also require an artifact-host
check:

```bash
BONSAI_MEMORY_BUDGET_MB=2048 MIMALLOC_PURGE_DELAY=0 \
  ./target/release/bonsai-ninja export ../elasticsearch \
  --format json \
  --output-path /tmp/bonsai-es-export.json \
  --no-color \
  --no-progress

jq --stream 'empty' /tmp/bonsai-es-export.json
shasum -a 256 /tmp/bonsai-es-export.json
```

Verify that native call/path relations remain `compressed_callgraph`, every
truncation counter is zero, and a one-shot export does not publish a hidden
reusable export cache. Record size, wall time, memory, swaps, completeness, and
hash.

## Test-build performance

`[profile.test] debug = 0` is intentional. The workspace links many integration
executables that include all language adapters. Full DWARF substantially
increases link time and artifact size without changing test behavior. For a
local debugger session, opt in explicitly:

```bash
CARGO_PROFILE_TEST_DEBUG=2 cargo test -p <crate> <test-name>
```

Production runtime measurements always use release binaries.

## Exit codes

| Outcome | Exit code |
|---|---:|
| Successful command, with or without findings | 0 |
| Invalid arguments, regex, workspace, or output configuration | Non-zero |
| Rulepack validation failure | Non-zero |
| I/O or analysis execution failure | Non-zero |
