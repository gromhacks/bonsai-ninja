# CI Integration

Use release binaries or a cached Rust build. In CI, pass `--no-color --no-progress` for clean logs and `--format json` or `--format sarif` for artifacts. Run `index` first when you want to validate syntax/construct indexing before later commands; scan commands also open the workspace and compute any missing exact scope on demand. Use `index --semantic` only for workflows that intentionally warm the immutable compiler-object generation plus structural semantic sidecars up front. Unchanged compiler objects are content-addressed and reused across CI cache restores after exact validation. `index --prewarm-dataflow` materializes the compatibility dataflow projection for older SDK/query consumers; it does not select another taint engine.

The compiler frontends and sparse IDG closure use the same semantics in
interactive, CI, SDK, and export modes. Semantic taint analysis has no BFS
depth, iteration, or result cap. `--all` controls artifact pagination; omitting
it can produce a valid first page but must not be treated as review of every
finding.

Large-project speed depends on three pinned compiler ownership rules:
compiler-object import/syntax headers must filter before body decode; every
consumer must share the workspace's canonical resolved callgraph; and
external-memory IDG acceleration must allocate lazily on promotion/spill.
Architecture conformance rejects violations before the timed gate is run.
Flow-ID/export code must reuse the live compiler linkage header and canonical
callgraph instead of calling `global_index()`, and export must serialize/drop
callgraph and exact-body phases before opening the IDG. Native export has no
capped/BFS path-prefix mode: the resolved callgraph is always the exact
linear-space path-language representation.

## Workspace test build performance

`[profile.test] debug = 0` is intentional. The repository has hundreds of
standalone integration-test executables, and each large security/CLI test
links the complete 20-language analysis graph. Embedding full DWARF made a
cold `cargo test --workspace --locked` spend tens of minutes linking and
triggered repeated macOS policy scans without improving test semantics. Do not
remove this profile setting as routine cleanup. For an intentional debugger
session, opt in locally:

```bash
CARGO_PROFILE_TEST_DEBUG=2 cargo test -p <crate> <test-name>
```

CI correctness still uses `cargo test --workspace --locked`; production
runtime and memory measurements always use the release binary.

## Large-workspace performance regression gate

Engine, cache, query, security, and export changes must run the real
Elasticsearch gate after building release:

```bash
cargo build --release --locked -p bonsai_cli
BONSAI_ELASTICSEARCH_ROOT=../elasticsearch \
BONSAI_REQUIRE_ELASTICSEARCH_GATE=1 \
BONSAI_MEMORY_BUDGET_MB=3072 \
  cargo test --release --locked -p bonsai_cli \
  --test elasticsearch_large_repo -- --nocapture
```

The test uses a 3 GiB compiler scheduling budget by default. It first allows a
cold `index --semantic` to finish, then measures a second fresh-process warm
reuse plus navigation, inspect, security inventory, and production taint
commands. Every assertion is evaluated after the command exits and
`analysis_complete` is checked, so an SLO failure cannot interrupt, skip, or
truncate semantic work.

The inspect gate also protects phase residency and target planning: broad
`inspect --taint-flow` must finish syntax discovery and release exact bodies
before opening the IDG, batch-resolve matching AST spans, and reuse a sparse
backward target-demand proof. Reintroducing one unrestricted closure per
lexical hit is both a latency and peak-memory regression.

Entry-rooted closures are scheduled from the measured non-reclaimable
linkage/output reserve plus a bounded sparse frontier per worker. Do not size
this phase from live RSS: the external-memory IDG's clean file-backed pages are
reclaimable, and charging them as committed memory serializes identical work
according to page-cache history. Conversely, do not introduce a worker floor
that ignores the configured budget. Subject to CPU availability, the current
resource-profile tests pin maximum concurrency of ten workers at 3 GiB, two
at 2 GiB, and one at 1 GiB; all configurations run the same entries and fixed
points.

Raw-flow rendering is part of the same gate. Row-size costs are precomputed by
the closure workers and reused by pagination; page planning must not serialize
or rescan every flow. Only the requested raw-taint page is formatted and
cached. Eagerly formatting future pages is unrelated work and is prohibited
for this mode; the complete deterministic page/cursor stream remains
available on demand.

The same gate protects two warm-start complexity bounds. Dense IDG compiler
headers remain fixed-width and buffered rather than being decoded through a
generic row/object codec, and occurrence deduplication remains an exact hash
identity operation rather than a scan of all previously emitted hits. These
are representation and algorithm constraints only; neither permits a semantic
cap, approximate equality, or skipped integrity validation.

Default warm ceilings are 15 seconds for semantic index reuse and 30 seconds
for each query/analysis command. Dedicated slower performance hosts can
calibrate `BONSAI_ES_WARM_INDEX_MAX_SECS`,
`BONSAI_ES_NAVIGATION_MAX_SECS`, `BONSAI_ES_INSPECT_MAX_SECS`,
`BONSAI_ES_SECURITY_INVENTORY_MAX_SECS`, and
`BONSAI_ES_TAINT_MAX_SECS`. Do not raise a repository baseline merely to make
a regression pass: record the host, source-file count, cold/warm cache state,
wall time, physical footprint/RSS, swaps, and completeness, then review the
phase/allocation change.

The final 2026-08-06 ABI-v62 reference pass completed all five tests in
1,760.06 seconds, including the required one-time rebuild from the incompatible
ABI-v61 generation. That explicit empty-cache `index --semantic` bulk prewarm
took 1,541.88 seconds; normal commands do not force it. Immediate fresh-process
reuse took 2.32 seconds, default inspect 10.33 seconds, broad raw-taint inspect
29.58 seconds, fresh-cache production taint 30.22 seconds, and warm production
taint 25.90 seconds. Source, sink, sanitizer, and dependency inventories took
3.85, 22.63, 18.32, and 10.42 seconds respectively. Compiler lowering
remained near 1 GiB RSS, released its bodies before IDG replay, and the IDG
worker remained below the 3 GiB scheduling budget.

A 2026-08-07 final warm-generation repeat passed all five tests in 234.09
seconds without changing those limits: immediate semantic reuse took 2.48
seconds, default inspect 10.02 seconds, broad raw-taint inspect 29.53 seconds,
fresh-cache production taint 34.28 seconds, and warm production taint 27.74
seconds. The broad inspect result retained all 12,233 entry closures and
198,025 unique pageable paths; compiler-owned declaration targets and direct
target ownership now avoid redundant header/relevance lookups without changing
the IDG fixed point.

The integration test deliberately does not write the multi-gigabyte native
Elasticsearch artifact on every CI runner. Changes to native export, compiler
summary closure, phase release, JSON streaming, or export caching must also run
an artifact host gate:

```bash
BONSAI_MEMORY_BUDGET_MB=2048 MIMALLOC_PURGE_DELAY=0 \
  ./target/release/bonsai-ninja export ../elasticsearch \
  --format json \
  --output-path /tmp/bonsai-es-export.json \
  --no-color --no-progress
jq --stream 'empty' /tmp/bonsai-es-export.json
```

Record bytes, wall time, physical footprint/RSS, dirty resident memory when
available, swaps, and SHA-256. Confirm `flow_chains_mode`,
`taint_graph.chains_mode`, and `taint_graph.flow_id_labels_mode` are all
`compressed_callgraph`, every truncation counter is zero, and a one-shot cache
miss did not create an `export.default.*` artifact in the workspace cache. Do not replace this gate with a
timeout or reintroduce a materialized path-prefix option.

## GitHub Release Artifacts

Repository releases are built from `v*.*.*` tags by `.github/workflows/release.yml`. The workflow builds Linux x64, Linux arm64, macOS Intel, macOS Apple Silicon, Windows x64, and Windows arm64 archives, includes `security-patterns/`, `docs/`, `README.md`, `AGENTS.md`, `SKILLS.md`, and checksum files, then publishes them with `softprops/action-gh-release`.
The installable `.agents/skills/bonsai-ninja/SKILL.md` package is included as
well, so extracting a release preserves both human documentation and the
agent-discoverable workflow.

For source-build target checks outside that release artifact matrix, use
`scripts/check-targets.sh`; see
[Platform And Architecture Support](platform-support.mdx) for the parser
bundle constraints that affect non-mainstream CPU architectures.

```bash
curl -L -o bonsai.tar.gz \
  https://github.com/gromhacks/bonsai-ninja/releases/download/v0.1.0/bonsai-ninja-x86_64-unknown-linux-gnu.tar.gz
curl -L -o bonsai.tar.gz.sha256 \
  https://github.com/gromhacks/bonsai-ninja/releases/download/v0.1.0/bonsai-ninja-x86_64-unknown-linux-gnu.tar.gz.sha256
sha256sum -c bonsai.tar.gz.sha256
tar -xzf bonsai.tar.gz
./bonsai-ninja-x86_64-unknown-linux-gnu/bonsai-ninja --version
```

## GitHub Actions

```yaml
name: bonsai-security

on:
  pull_request:
  push:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - run: cargo build --release -p bonsai_cli --locked
      - run: ./target/release/bonsai-ninja index . --no-color --no-progress
      - run: |
          ./target/release/bonsai-ninja security . taint-analysis \
            --rules-dir security-patterns \
            --format sarif \
            --all \
            --no-color \
            --no-progress \
            --output-path bonsai.sarif.json
      - uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: bonsai.sarif.json
```

<Note>
GitHub SARIF upload requires `security-events: write`. For forked pull requests, upload permissions depend on repository settings.
</Note>

## GitLab CI

```yaml
stages: [security]

bonsai_security:
  image: rust:latest
  stage: security
  script:
    - cargo build --release -p bonsai_cli --locked
    - ./target/release/bonsai-ninja index . --no-color --no-progress
    - |
        ./target/release/bonsai-ninja security . taint-analysis \
          --rules-dir security-patterns \
          --format json \
          --all \
          --no-color \
          --no-progress \
          --output-path bonsai-findings.json
  artifacts:
    when: always
    paths:
      - bonsai-findings.json
```

## CircleCI

```yaml
version: 2.1

jobs:
  bonsai-security:
    docker:
      - image: cimg/rust:stable
    steps:
      - checkout
      - run: cargo build --release -p bonsai_cli --locked
      - run: ./target/release/bonsai-ninja index . --no-color --no-progress
      - run: |
          ./target/release/bonsai-ninja security . taint-analysis \
            --rules-dir security-patterns \
            --format json \
            --all \
            --no-color \
            --no-progress \
            --output-path bonsai-findings.json
      - store_artifacts:
          path: bonsai-findings.json

workflows:
  security:
    jobs:
      - bonsai-security
```

## Exit Codes

| Command outcome | Exit code | Notes |
|---|---:|---|
| Successful scan, findings or no findings | 0 | Findings are report data, not a process failure. |
| Invalid flags, bad regex, missing workspace | Non-zero | Treat as CI failure. |
| Rulepack validation failure | Non-zero | Fix schema, examples, or collisions. |

Use a small wrapper if your policy requires failing builds when findings exist.
