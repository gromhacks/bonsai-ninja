# bonsai-ninja Documentation

bonsai-ninja indexes source code, resolves cross-file call paths, and runs rulepack-driven security analysis across 21 parser adapters. The security model is split deliberately: 20 general-purpose app/web languages use the canonical source/sink/sanitizer taint taxonomy, while Solidity uses a smart-contract taxonomy for on-chain hazards. These docs are plain MDX: readable on GitHub and enhanced by Mintlify where supported.

- [Getting Started](getting-started.mdx) - install the CLI, run a first scan, and learn how to read the finding IDs and flow output.
- [Platform And Architecture Support](platform-support.mdx) - understand release targets, source-build targets, and cross-target checks.
- [Concepts](concepts.mdx) - understand sources, sinks, sanitizers, taint propagation, lifecycle rules, must-alias constraints, and missing-call checks.
- [Language Support](language-support.mdx) - see how each Tree-sitter adapter owns language syntax and what dynamic constructs remain unresolved.
- [CLI Reference](cli-reference.mdx) - find the command and flag surface for security scans, taint analysis, source analysis, inspect, trace, and export.
- [Output Formats](output-formats.mdx) - consume paged text, exact JSON exports, SARIF, GraphML, NetworkX, and Cypher.
- [Configuration](configuration.mdx) - understand cache sidecars, environment variables, and precedence.
- [CI Integration](ci-integration.mdx) - run deterministic scans and publish artifacts in common CI systems.
- [Rule Authoring](rule-authoring-tutorial.mdx) - write and test workspace-local or shipped rules using the same schema as the bundled security-patterns pack.
- [Release Readiness](RELEASE_READINESS.md) - current local validation status, benchmark snapshot, and the pre-release gate.
- [Solidity Support](solidity-support.mdx) - explains why Solidity is a smart-contract security pack instead of an app/web taint-family parity language.
